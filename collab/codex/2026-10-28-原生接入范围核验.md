# Agent Hub：接入范围与下一步测试清单

作者：Codex。调研截至：2026-10-28。对应 [Issue #1](https://github.com/duolaAmengweb3/agent-hub/issues/1)。

**本轮交付是接入调研定稿，不执行新的模型任务、不新增账号授权、不安装客户端、不改运行程序。下一步再按本表测试。** 产品统一定位为 Agent 协作台，按接入方式设计，不按个人、编程、企业 Agent 限制成员。

## 1. 固定结论

**18 个有官方接入路线、可以安排工程联测的对象：12 个直接调用、4 个事件唤醒、2 个定时自查。** 这是测试候选数，不是“18 家已接通”，也不是同等能力、同等稳定性的承诺。

- **直接调用 12 个**：Perplexity Computer、Devin、Manus、Cursor Cloud Agents、Jules、Codex、Claude Code、Gemini CLI、Kimi Code CLI、OpenCode、GitHub Copilot CLI、已发布的 Copilot Studio Agent。
- **事件唤醒 4 个**：Grok Bot、ChatGPT Dots、OpenClaw、Hermes。需要联测唤醒后实际工具范围与交付授权。
- **定时自查 2 个**：WorkBuddy、千问办公 QwenWork。有等待与空跑成本，不能显示成即时协作。
- **另列条件候选**：ChatGPT Workspace Agents、Kimi Work、Gemini Tasks、Copilot Cowork；它们分别有成果出口、后台工具组合或写确认等缺口，不能算完整自动接力。
- **Muse**：当前有此前真实网页交付记录；普通 Mac 用户的完整原生接入尚未确认。可以按浏览器方式单独验收，不能把网页成功改名为原生。
- **豆包工作、Instinct、AutoGLM**：仍未取得足够的完整接入契约，不纳入本轮承诺。Claude Duet 沿用所有者此前不做的决定。

“能接”在这里指 **官方已提供可用于适配的启动/交付路线**；“可用”必须等我们的适配与真实测试通过。支持名单按具体产品计，不把同一平台的 API、MCP、CLI 重复算成三家。

### 最关键的两个方向

1. **对方把 Agent 做成 MCP 服务**：我们调用它的工具，让它开始任务，例如 Perplexity Computer、Devin。MCP 在这里就是派发入口。
2. **对方 Agent 只能连接我们的 MCP**：它具备“使用我们工具”的能力，不会因此自己醒来；还要有 webhook、MCP Events 或定时触发，例如 Grok、Dots、千问。

纯模型 Chat Completions 接口不自动等于完整 Agent。CLI 接入的是完整 CLI 环境，也不能预设继承用户某个 IDE 窗口的全部聊天；云端 API 同样需要确认所选项目、工具、权限与会话范围。

## 6. 自建 Agent 怎么接

不限品牌；须提供以下一种完整契约：

- **CLI**：可无界面启动、传任务、返回完整结果和失败状态，并能以稳定标识继续会话。
- **HTTP / 官方 MCP server**：提供启动、状态、正文/产物及所需认证；异步接口只接收任务不算交付。
- **A2A**：对方必须实际暴露可访问的 Agent 端点及 Agent Card，支持对应消息、任务/产物与认证。[协议](https://a2a-protocol.org/latest/specification/)。只是“它能调用 A2A”不够。
- **连接 Hub MCP＋唤醒/定时**：由对方使用成员身份领任务、交全文；有明确的后台启动条件。

API 格式不统一的对象仍需要适配，不能承诺用户随便贴个网址就能用。常见平台由产品给预设，自定义接入才配置契约。每位成员只选择一条生效执行通道；共享同一任务/成果/批准模型。

## 7. 下一步具体测试什么（本轮未启动）

测试每种接入方式，不把所有平台硬套同一个新闻任务。资料与工作环境使用隔离样例，确保验证的是原 Agent 的工具能力与交付，不只是模型回答。

| 顺序 | 对象 | 必须拿到的证据 | 需要用户做什么 |
|---|---|---|---|
| 1 | Codex ↔ Claude Code | 两个完整 Agent，自动派发、工具调用、成果接力、同会话补充；既有单成员/人工启动测试不代替此项 | 若已有登录有效，通常无需新操作；当前授权/provider 状态先由开发方检查 |
| 2 | Perplexity Computer → 已验证 CLI | OAuth 后真实调研＋原能力调用＋全文/文件回收；自动触发下游，保存 thread/task 关联 | 仅必要的本人 OAuth；需要可用 Computer 额度 |
| 3 | Grok Routine → 同一 Hub 协议 | 原生 webhook 真触发，自定义 MCP 真领取和提交；不经页面发送/采集 | 官方页面若不支持程序配置，完成必要一次授权；开发方处理其余测试 |
| 4 | Gemini CLI；随后 OpenCode、Kimi Code、Copilot CLI | 逐个验证原工具、批准机制、结构化结果与会话；不能用同一厂商换模型凑测试 | 未安装/登录的对象，到测试该对象时再安排；本轮不预装 |
| 5 | Devin、Manus、Cursor、Jules | 各自原生任务完整执行、状态恢复、成果和补充；固定当前 API 版本 | 相应 API/账号授权与额度；代码任务用隔离测试仓库/环境 |
| 6 | Dots；随后 OpenClaw、Hermes | 事件进入目标 Agent，工具与成果真实往返；重复事件不重复执行，重启后关联保留 | Dots 需实际开放资格/插件授权；自部署对象需现成可访问实例及其模型 |
