# 接入可行性台账：到底能接几家

- 作者：Claude
- 日期：2026-10-28
- 起因：所有者担心"最后只能支持几家，甚至只有 Grok 一家，产品就没有价值"，要求先把这一点调研、测试清楚，固定结论。
- 范围：只算**不靠浏览器操作网页**的接入方式（原生通道）。浏览器通道单列。
- 依据等级：**实测** = 本次在本机真实跑通；**官方** = 读过官方文档原文；**你确认** = 所有者在自己账号里确认过；**待测** = 有依据但关键一环没验证。

---

## 1. 结论

**不会只剩 Grok 一家。不靠浏览器、有官方依据的原生通道，目前至少有 12 家；其中 1 家（Claude Code）本次已实测跑通完整接力。**

但要分清两类：

| 类别 | 原生通道情况 | 对产品的意义 |
|---|---|---|
| **大厂个人 Agent**（Grok、Dots、Gemini、Muse、Perplexity……） | 只有 **Perplexity** 能被工作台直接调用；**Grok、Dots** 能被叫醒后自己来领任务（各有一环待测）；**Gemini** 能接但每次交结果要人点确认；**Muse 没有原生通道** | 如果产品**只做**个人 Agent，能稳定接入的确实只有 3～4 家，偏少 |
| **有接口或命令行的 Agent**（Claude Code、Codex、Gemini CLI、Manus、Devin、Jules、Cursor、Copilot Studio、OpenClaw、Hermes……） | 全部能被**直接调用**，不需要叫醒，也不需要浏览器 | 数量多、通道稳；"任何 Agent 都能加入"在这一类上是成立的 |

所以：**按所有者已经定下的方向——"任何 AI Agent 都能接入"——产品有足够多可接的对象，值得做下去；如果退回到"只接大厂个人 Agent"，价值确实会被卡住。** 最有价值的组合是两类混编：个人 Agent 握着各自的生态（X、Gmail、Instagram……），接口类 Agent 负责稳定地完成重活。

## 2. 实测：两个真实 Agent 经 MCP 完成接力

在本机启动现有工作台的云端服务（本地 workerd + D1，代码基线 `c618342`），建两个成员和一个两步任务，分别启动两个**互相独立的 Claude Code**（2.1.308，无界面模式 `claude -p`），每个只连自己的 MCP 凭证，只给通用指令"用 hub 工具查看并完成分给你的工作"，**不告诉它任务内容和编号**。

| 步骤 | 成员 | 结果 | 用时 | 花费 |
|---|---|---|---|---|
| 1 整理事实 | Claude Code A | 自己调用 `list_my_work → claim → submit`，交了 3 条要点 | 17 秒 | 约 $0.13 |
| （交接） | 工作台 | 第 1 步完成后，第 2 步自动变为"可以做了"，指派给 B | — | — |
| 2 写成推文草稿 | Claude Code B | 自己读到 A 的成果，改写成 3 条推文草稿并提交 | 16 秒 | 约 $0.06 |

- 服务端核对：任务状态"已完成"，两步成果正文都已存档，内容前后衔接（B 的 3 条草稿逐条对应 A 的 3 条要点）。
- **证明了：** 现有 MCP 工具和接力机制在真实 Agent 上是通的；"命令行 Agent"可以原生接入。
- **没证明：** ① 两个成员都是 Claude Code，不是跨厂商；② 两个实例是我依次手动启动的，"自动启动下一位"需要 Codex 方案里的命令行执行器，现在代码里还没有；③ 账号容器借用了 `gemini` 平台编号（平台清单里没有 Claude Code），实际连进来的是 Claude Code。

## 3. 逐家台账

### 3.1 能被工作台直接调用（最稳：工作台主动派活、主动取结果）

| Agent | 怎么接 | 依据 | 备注 |
|---|---|---|---|
| **Claude Code** | 命令行 `claude -p` + MCP | **实测**（本次） | 用用户自己的订阅或 API 额度 |
| **Codex** | 命令行 `codex exec` + MCP | Codex 本地核对过命令帮助 | 同上 |
| **Gemini CLI** | 命令行 `gemini -p` + MCP | 公开 CLI 用法 | 待实测 |
| **Perplexity Computer** | 工作台作为 MCP 客户端，调用官方 Computer MCP 服务器：`call_perplexity_computer` 发起或继续任务、`read_thread` 查进度、`answer_question` / `confirm_action_*` 处理提问和批准、`cancel_task` 取消、可上传下载文件 | **官方**（[Computer MCP Server](https://docs.perplexity.ai/docs/getting-started/integrations/computer-mcp-server)） | 用 Perplexity 账号 OAuth 授权；消耗账号额度；单次调用最长等 2 分钟，之后用 `read_thread` 取结果 |
| **Manus** | 官方 API（v2）建任务 + webhook 接收完成通知 | **官方**（[Manus API](https://open.manus.ai/docs)） | API Key |
| **Devin** | 官方 API 建会话、轮询状态，可指定结构化输出 | **官方**（[Devin API](https://docs.devin.ai/api-reference/v1/sessions/create-a-new-devin-session)） | 主要是编程任务 |
| **Google Jules** | 官方 API 建会话 | **官方**（[Jules API](https://developers.google.com/jules/api/reference/rest/v1alpha/sessions/create)） | 还是 alpha 版；需要连 GitHub 仓库；编程任务 |
| **Cursor Cloud Agents** | 官方 REST API | **官方**（[Cloud Agents API](https://cursor.com/docs/cloud-agent/api/endpoints)） | 编程任务 |
| **Microsoft Copilot Studio 里的 Agent** | 官方 A2A，或 HTTP 触发 | **官方**（[A2A 连接](https://learn.microsoft.com/en-us/microsoft-copilot-studio/add-agent-agent-to-agent)） | 企业场景 |
| **OpenAI Workspace Agents** | 官方触发接口 | **官方**（见 M0 文档 S6、S7） | 仅 Business / Enterprise；接口当前不返回正文，需 Agent 用 MCP 交结果 |
| **OpenClaw、Hermes** | 自己部署，命令行 / 定时任务 + MCP | **官方**（[OpenClaw 定时](https://docs.openclaw.ai/cli/cron)、[Hermes 钩子](https://hermes-agent.nousresearch.com/docs/user-guide/features/hooks)） | 需要自己部署 |

### 3.2 能被叫醒，再自己通过 MCP 领任务、交结果

| Agent | 怎么叫醒 | 怎么交结果 | 依据 | 待测的关键一环 |
|---|---|---|---|---|
| **Grok Bot** | webhook 触发 Routine | 自定义 MCP | **官方**：能按 URL 加自定义 MCP（任何账号）；webhook 能触发 Routine | **Routine 运行时能否调用自定义 MCP，官方没写** → Codex 方案的 N1 先验证 |
| **ChatGPT Dots** | 工作台用 Slack 机器人在频道里 @ 它 | 自定义 MCP | **官方**：Slack 里私信或频道 @ 都能找它（[Message your dot](https://learn.chatgpt.com/docs/dots/channels)）；**你确认**能加自定义 MCP | 被 @ 后它能否自己调用自定义 MCP 完成并提交；没有 API |
| **Gemini Tasks** | 给你的 Gmail 发一封触发邮件 | 自定义 MCP | **官方** | **每次交结果都要你手动确认**（Google 规定）；仅美国、英文；需 AI Pro / Ultra |

### 3.3 只能靠它自己定时来查（慢，且电脑要开着）

## 4. 下一步要测的（需要所有者的账号）

按"对结论影响大"排序；每项都由开发方执行，只在需要本人登录或授权时找所有者。

| 顺序 | 测什么 | 为什么重要 | 需要所有者提供 |
|---|---|---|---|
| 1 | **Grok N1**：webhook 唤醒 Routine → Routine 调用自定义 MCP 领任务、交结果 | 个人 Agent 里最关键的一家；Codex 已排为最先验证 | 在 Grok Bot 里加 MCP、建 Routine |
| 2 | **Perplexity Computer MCP**：工作台调用 `call_perplexity_computer` 完成一个调研任务并取回结果 | 官方最完整的个人 Agent 原生通道，很可能是最稳的一家 | Perplexity 账号 OAuth 授权 |
| 3 | **Dots + Slack**：Slack 里 @ 它 → 它用 MCP 领取并提交 | 决定 ChatGPT 这一家能不能原生接入 | 一个 Slack 工作区，把 Dot 加进频道 |
| 4 | **跨厂商接力**：Perplexity 或 Grok 找资料 → Codex / Claude Code 写草稿，连续 3 次 | 第一次真正的跨厂商协作 | 同上 |
| 5 | Manus 或 Gemini CLI 接入 | 扩大"直接调用"一类的实测数量 | API Key 或命令行登录 |

## 5. 对产品方向的建议

1. **定位维持"任何 AI Agent 都能加入"**，不要退回"只接个人 Agent"。
2. **第一批主打的组合**：Perplexity（调研，原生）+ Grok（X 实时内容，N1 通过后）+ Claude Code / Codex（写作和执行，原生），再加 Dots（Slack 叫醒）。这几家覆盖"找资料 → 核实 → 写稿"的完整链路，而且都有原生通道。
3. **Muse 保留网页通道，明确标注**，不作为主打。
4. 建议在 Codex 的执行顺序里，把 **Perplexity Computer MCP 接入**加到 N1 旁边一起验证：它是工作台主动调用、不依赖叫醒，比 Grok 更可能先跑通跨厂商接力。
