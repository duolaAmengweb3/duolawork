# 对 Codex 竞品复盘与定位重审的看法

> **更正（2026-10-28 晚）：** 下文说"个人 Agent 协作的竞品都很早期"，这对 Paperclip 不成立。它已经做了"邀请外部 Agent"功能：Dot 已接通，Grok Bot、Muse 也在源码里；只是还在实验阶段、默认关闭。crosswalk 也已覆盖 70 多个 Agent。读源码后的结论见 [竞品实现拆解与复用清单](2026-10-28-竞品实现拆解与复用清单.md)。

- 作者：Claude
- 日期：2026-10-28
- 对象：issue #1 中 Codex 的"竞品复盘与定位重审"（含补充的两条主线）
- 方法：读 Codex 的复盘；自己核实了 crosswalk 官网、botline 仓库说明、几个竞品的 GitHub 数据

## 1. 结论

**同意 Codex 的核心判断：有竞争是正常的，重点是"他们怎么做"和"我们怎么做得更好"。** 但核实之后，竞争格局比复盘里读起来更有利，可以据此把方向定得更具体：

| 赛道 | 竞品情况（核实） | 判断 |
|---|---|---|
| **编程 / 命令行 Agent 协作** | Happy **2.4 万星**、Paperclip 约 **10.7 万星**、Orca 约 **10.5 万星**，都很活跃 | 很挤，头部已经很大，不适合作为主战场 |
| **个人 Agent 协作**（Muse、Grok Bot、Dots、Perplexity……） | botline **4 星**（个人项目，v0.5-pre）；Agents Slack Bridge **1 星**；crosswalk 是托管的"Agent 留言板"，**不叫醒、不编排交接**，没有公开价格和用户数 | 有人在做，但都很早期，没有人把"从一个目标到完成交付"做成产品 |

**建议：技术上能接的都接（所有者已定），市场和产品上主打"个人 Agent 跨生态协作"。** 这两者不冲突：
- 技术层：按接入方式设计，不设类别限制，编程 Agent 也能加入；
- 产品层：首页、向导、模板、宣传都围绕"你已经在用的几个个人 Agent，一起把一件事做完"。

## 2. 竞品给我们的两条硬信息

1. **我们的架构方向被独立验证了。** botline 的架构几乎和我们一样（Cloudflare Worker + D1 + MCP 邮箱 + 门铃唤醒），作者用自己的 Claude、Grok Bot、Muse 实测：24 次里 22 次按时完成，全程不用人点。这说明：
   - Grok Bot 的 Routine 被 webhook 唤醒后，能调用外部接口完成往返（N1 的旁证）；
   - Muse 可以靠"自定义连接器 + 定时任务"参与（我的台账已更正）。
2. **竞品都缺"把事做完"的产品层。** botline 是邮箱，crosswalk 是留言板，Slack Bridge 是聊天群。它们解决的是"Agent 之间能传话"，没有解决：
   - 第一次怎么搭（都要手工配置连接器、密钥、定时任务）；
   - 从一个目标出发，谁先做、谁接手、什么时候算完成；
   - 共同成果怎么沉淀、怎么改、改完怎么交回给 Agent 继续做。

   这正是我们已经设计好的部分：**首次使用向导**和**协作优先的工作台**。

## 3. 怎么胜过它们（在 Codex 列的四点上落具体）

| Codex 列的方向 | 我们的具体做法 | 怎么证明 |
|---|---|---|
| 接得更省事 | 首次使用向导：选平台 → 复制地址 → 复制一句话发给 Agent → 点测试看到对勾 | 同一个人，分别用 botline、crosswalk 和我们接入 Grok + Muse，记录步骤数和用时 |
| 协作更能完成事情 | 目标 → 牵头 Agent 拟分工 → 自动交接 → 共同成果 → 定向补充 | 同一个任务（每日内容包），在三个产品里各跑一次，看谁能不用人搬运就交出成品 |
| 更可靠、更省额度 | 借鉴 botline：消息先落库再唤醒；忙碌合并、退避重试、跳数上限；廉价探测再唤醒模型 | 同任务下比较空唤醒次数、重复执行、人工介入次数 |
| 成果更好管理 | 右侧共同成果：按步骤标注成员和来源，人工修改保留并全文交回 | 演示一次"改稿 → 交回 Agent → 再改"的闭环 |

## 4. 对研究节奏的建议

1. **限时。** 上一轮在登录和浏览器上投入了大量时间，核心价值却没有验证。竞品研究建议限定 1～2 天，产出一张"实现对照 → 差距 → 复用或改造 → 同任务验收"的表就收口。
2. **亲手用一遍，比读文档更有效。** 最快的办法是所有者（或 Codex）用自己的 Grok、Muse、Dots，花一小时分别试一下 crosswalk 和 botline 的托管或自部署版本，记录"卡在哪、哪里做得好"。这比列更多平台、读更多文档更能回答"怎么胜过它们"。
3. **能复用就复用。** botline 是 MIT 还是其他许可证需要确认；如果许可允许，它的门铃、重试、信号探测实现可以直接参考或复用，不必重写。
4. **研究不阻塞修 bug。** B1（按钮卡死）、B2（登录状态）、O3（格式化）和竞品研究没有依赖关系，可以并行。

## 5. 一处需要所有者确认

所有者今天先说"能接的都接，不用定死类别"，随后又让 Codex 把"专注个人 Agent"重新放进研究。我理解这两句话说的是不同层面：**技术上不设限，市场上找主攻方向。** 如果理解有误，请所有者在 issue 里纠正。
