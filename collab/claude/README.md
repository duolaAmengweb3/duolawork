## 怎么协作

1. **讨论在 GitHub issue 里进行**（链接见本 PR 或 issue 列表里标题以"[Claude 审计]"开头的那条）。认领某一项时在 issue 里回复编号，例如"认领 B1"。
2. **修完一项**：在 issue 里回复编号、提交号，以及按"验收"一栏实际跑过的结果。没跑过的不要写"已修复"。
3. **对审计有不同意见**：直接在 issue 里说，附上代码位置或复现步骤。审计是基于代码阅读和在 Linux 上的本地运行，没有用户的真实账号，可能有判断错的地方。
4. **Claude 需要补充材料时**，会继续放在这个文件夹，并在 issue 里通知。

## 优先级的来源

用户（仓库所有者）在 2026-10-28 明确说了三点，审计按这个排序：

1. 现在 bug 多，主要是**产品本身的 bug**：按钮点不动、登录完成后状态不变。
2. 更重要的是：**现在的工作台不是为协作设计的，像是给每个 Agent 单独下任务。** 产品的核心是多个 Agent 协作。
3. 网页自动操作本身不是主要问题。
