| 高 | **切人时漏掉迟到的结论。** A 尚未回答时切到 B 并发言。待 B 回答后让 A 完成，再问 B。A 的结论在对话记录中，B 两次收到的输入都没有它。A 的气泡在派发时已分配较小的序号，完成时只更新气泡内容，B 的已读游标已经越过它。[预分配消息序号](../../src/server/threads.ts#L403) · [增量筛选](../../src/server/handoff.ts#L176) | A 的气泡留在原位。按完成事件或内容修订给 B 补交迟到的结果，后续发言只补交一次。 |

**工具轨迹另有一项数据保护问题。** Codex 将命令文本前 80 个字符作为轨迹摘要；现有脱敏函数只识别几种固定前缀。带普通密码参数、带签名的地址等内容存在随轨迹落库并传给下一位成员的路径。这是代码审阅发现，此次没有检查真实用户的轨迹，也没有认定已发生泄露。建议先按工具类型只保留展示任务所需字段，用虚构标记验收数据库、界面事件和下一位成员的输入。[命令摘要](../../src/server/drivers/codex-driver.ts#L483) · [脱敏规则](../../src/server/drivers/types.ts#L99) · [交接中的工具轨迹](../../src/server/handoff.ts#L207)

## T3 Code 原实现与本次交付

直接核对本机 T3 Code Beta 0.1.11 的打包服务端。其运行包包含上游 `packages/provider-core/src/server/handoffBudget.ts`，默认 Token 上限为 16,000，另设 64,000 字节上限；历史选择器跟踪原始 item ID，在生成转移时区分完整上下文与增量上下文。DuolaWork 的交接主路径由本仓的 `HandoffEngine` 实现，按每 Token 三字节估算、按消息序号截取，再拼入本地任务与文稿。**当前交付借鉴了 T3 Code 的做法，仍未直接接入它的选择器和恢复逻辑。** [DuolaWork 的实现](../../src/server/handoff.ts#L4)
