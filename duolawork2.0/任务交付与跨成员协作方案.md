# 任务交付与跨成员协作

用户在原对话给出目标，工作台在同一处说明谁在处理、哪些结果已经取得，以及是否需要用户介入。普通聊天继续直接回复。单次任务和每一期定时任务分别记录交付。

## 如何判断交付

| 用户期望 | 工作台核对的事实 | 用户看到的结果 |
| --- | --- | --- |
| 文字答复 | 本步提交了有效正文，正文随任务交付 | 答复已交付 |
| 文件或协作文档 | 本步写入记录、所属对话、目标名称和约定目录与现存资料一致；文件摘要或文档版本一致 | 资料已保存，点击打开对应成果 |
| 外部系统状态发生变化 | 通过受管凭证向目标资源发起只读 GET，返回成功且约定的业务字段与预期值相符 | 外部结果已核实 |
| 执行后断线、目标尚未更新 | 保留原步骤，按间隔重查同一资源；只有查询被重试 | 正在核对外部结果 |
| 外部平台缺少可用的读回接口，或多次核对都未确认 | 保留未核实状态；可以再次查询，或由实际核实过结果的人确认 | 外部结果待确认；人工确认单独标明 |

派单成员按步骤声明成果。复合目标可以先交文稿、再交文件、最后更新外部记录，各步独立验收。自有工具的执行成员可以在知道资源标识后补充读回条件。已声明的目标不能被执行成员调弱。旧任务若仅有答复记录，界面按现有交付记录展示，不补造外部回执。

## 如何让人看懂协作

单次任务卡从第一次出现起保留原位置；定时任务每期开一条独立记录。委派关系、当前实际执行人、派单人接手或跟进的状态随服务器记录更新。点击成果打开具体资料，点击标题查看步骤和历史。任务需要用户补充时就在原卡回答。多个执行人并行时显示实际参与成员，切换当前聊天对象不改变原任务归属。

## 验收方法

从聊天框派单，检查文字、文件和外部操作三种交付。故意提交缺少文件的完成声明、相同请求、丢失的回执、延迟可见的外部状态和不能自动读取的结果。刷新页面、暂停再继续、重启服务后检查卡片位置、资源归属、核对来源及外部写入次数。外部写入使用隔离目标，正式业务账号上的发布和群发不作为验收动作。

## 模型与推理强度

输入框旁的模型入口按当前对话和成员保存。选择项来自该成员所在执行节点。Codex 读取原生模型目录；Claude 读取 CLI 初始化响应；ACP 成员读取会话模型及该模型的思考级别。平台没有暴露强度时只展示可操作的选项，固定 Bot 沿用接入端设置。保存后从下一次分发开始使用，已经运行的步骤继续使用原参数。分别验收参数到达原生协议、刷新、成员切换、节点断线及不支持的组合。
