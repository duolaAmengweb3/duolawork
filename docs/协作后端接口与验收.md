## 2. 前端怎样接

正式桌面新版本合入本分支后，前端调用同源 `/api/v2/*`。本地服务转发到云端 `/v2/*`，管理凭证只存在本地后端，不发送给 renderer、不放 URL。

- 账号及成员继续用 `/api/state` 内的稳定 ID，不新建假身份映射。
- 项目、消息、稿件、反馈、规则以服务端为准。localStorage 只可用于未提交输入。
- 写操作有稳定 `requestId`。超时重试保持原编号、原内容；内容变化必须新编号。
- 编辑带 `revision`；409 时读取新版本，让用户选择，不自动覆盖。
- 每个按钮独立 loading；普通请求 15–30 秒超时；不能用全局 busy 锁所有项目。
- `/api/v2/project` 返回最近 100 条消息和 `activityCursor`。随后约每 2 秒请求 activity；有 `hasMore` 时先翻完，不能跳到末尾丢消息。
- 消息 HTML、稿件 HTML 都是不可信内容；展示时由 UI 做白名单清洗。下载默认 attachment/octet-stream，不能当脚本打开。
- 领取/进度/交付来自后端事件；不要播放假 Agent 思考、不要将通知 HTTP 200 写成任务完成。

### 读取接口

| 云端路径（本地前加 `/api`） | 返回 |
|---|---|
| `GET /v2/catalog` | 唯一首发配方及四个平台接入类型 |
| `GET /v2/connections` | 脱敏接入状态；不返回平台密钥 |
| `GET /v2/setup?memberId=...` | 该平台接入说明、MCP/OpenAPI 地址；凭证另走既有安全流程 |
| `GET /v2/records?kind=project&after=...` | `items,nextCursor`，每页最多 100；隐藏验证项目不展示 |
| `GET /v2/project?id=...` | 项目、运行、最近消息、文稿索引、知识、反馈、日程 |
| `GET /v2/run?id=...` | 运行、排序步骤、脱敏尝试、通知与原 Computer 任务/问题 |
| `GET /v2/activity?projectId=...&cursor=...` | 增量事件、游标、hasMore、refreshAfterMs |
| `GET /v2/document?id=...` | 原稿 `original`、工作稿 `working`、revision |
| `GET /v2/records?kind=document_version&parentId=...` | 指定文稿全部版本（翻页） |
| `GET /v2/metrics?projectId=...` | adopted、discarded、pending、evaluated、采用率、样本标记、运行按时率、返工；成本未知 |
| `GET /v2/files/{id}` | 经过授权的真实文件字节 |

可分页类型：project/run/step/message/document/document_version/knowledge/knowledge_version/edit_event/feedback/feedback_event/schedule/file。用 projectId 限定范围，parentId 查版本或历史。run 详情中的 leaseHash、OAuth/Routine 密钥均剔除。

### 用户命令

全部 `POST /v2/commands`，正文为 `{type,requestId,...字段}`，返回 `{result}`。

| type | 主要字段 |
|---|---|
| `project.create` | recipeId=`daily-x-content`, recipeVersion=1, name, topic, slots={discover,verify,write}，值为成员 ID；可选 approvals=[槽位]、deadlineMinutes（1–1440，默认 null） |
| `project.update` | projectId,revision；可改 name/topic/slots/approvals/deadlineMinutes；运行中的分工快照不变 |
| `project.control` | projectId,control=`pause/resume` |
| `run.start` | projectId；成员缺授权/验证时 409，不生成假运行 |
| `run.control` | runId,control=`pause/resume/cancel`；取消 Hub 不等于原平台已停止 |
| `message.send` | projectId,body；可选 memberId 表示 @；运行中追加排队，不取消原领取 |
| `step.approve` | stepId；只用于 needs_approval |
| `step.retry` | stepId,reason；原平台状态不明时须 confirmRemoteStopped=true |
| `resource.release` | resourceKey,attemptId,confirmRemoteStopped=true；失效旧领取，不能释放仍正常执行的尝试 |
| `document.edit` | documentId,revision,body；可选 format=text/markdown/html |
| `document.revise` | documentId,revision,instruction；可选 memberId；只修改指定稿，完整人工稿随任务传递 |
| `feedback.set` | documentId,value=`adopted/discarded/pending`；复制/导出不调用此命令 |
| `knowledge.write` | projectId（或 global）,title,body；可选 category=material/rule,fileIds,versionIds,approved；编辑还带 knowledgeId,revision |
| `knowledge.review` | knowledgeId,revision,status=`approved/rejected/revoked` |
| `schedule.set` | projectId,revision（已有时必填）,enabled,timeZone（如 Asia/Shanghai）,hour,minute；首次不默认开启 |
| `connection.probe` | memberId；生成原生工具回传挑战；不是模拟成功开关 |

`knowledge_version` 与 `feedback_event` 保留历史。归档稿件不自动变成规则。附件上传后，显式写入项目 material 的 fileIds 才会随批准资料进入运行；不会偷偷把所有文件传给所有平台。

### 文件与配置

- `POST /v2/files`：Content-Type `application/octet-stream`；`X-Hub-File` 为 URL 编码 JSON，字段 requestId/projectId/name/mime。成员上传改用 attemptId/lease，不能伪造 owner。
- 上限 8 MiB，空文件拒绝。响应 id/name/size/sha256。成果只能引用本次尝试上传成功的文件。
- 默认 `FILE_STORAGE=d1`，512 KiB 不可变分块；已开通的 D1 即可运行。这个账户 R2 API 返回 10042（未开通），没有因此申请新付费服务。
- 支持显式配置 R2：绑定 FILES 并设 FILE_STORAGE=r2。文件记录保留 storage 类型，既有 D1 文件继续可读；缺少绑定时明确报错，不静默换存储。
- D1 单库容量取决于账户套餐，附件占用也计入；8 MiB 是单文件应用上限，不代表无限总容量。大规模附件部署应使用 R2。参考：[D1 限额](https://developers.cloudflare.com/d1/platform/limits/)。

`POST /v2/connections`：requestId/memberId/platform/capabilities（research/writing/files）。Grok 另需官方 Routine url/token；Muse 可设 pollSeconds（最低 60、默认 300）。切换通道会清除该通道的旧验证状态，不更改原账号或浏览器资料。账号仍执行时不允许切换。

## 3. 原生 Agent 接入

同一成员只生效一种原生传输；不在失败时自动退回浏览器、普通聊天或廉价模型。

| 平台 | 已实现的传输 | 真实账号必须补齐的条件 |
|---|---|---|
| Grok Bot | 原 MCP 工具 + 官方 Routine webhook；200 仅受理；429/5xx 退避，网络结果不明不重发 | 原 Bot 授权成员工具、专用 Routine、其 webhook URL/key；实际唤醒一次回传 |
| Muse | OpenAPI/REST connector + `/v2/signal` 轻量检查；有待办再叫模型 | 在原 Muse 建 connector 与 hook/定时；实际周期取决于账号支持，不能承诺秒级 |
| Dots | MCP Events：discovery/list/subscribe/unsubscribe、签名验证、续期与双签轮换、稳定事件 ID | 原 Dot 添加插件并真实订阅 work.ready；官方回调完成挑战 |
| Perplexity Computer | 官方 OAuth + MCP Tasks；保存 task/thread ID；轮询同一任务；问题回传；真实附件上传与回收 | 用户完成官方 OAuth；原套餐允许 Computer MCP；验证原任务实际结果 |

成员工具：`list_work,claim_work,report_progress,submit_work,read_document,read_file,propose_knowledge,upload_file`。

- MCP：`/v2/mcp`。REST：`POST /v2/tools/{name}`。工具 schema：`GET /v2/openapi.json`。
- 只用成员 Bearer，不用 ADMIN_KEY 假扮 Agent。管理凭证不能调用成员工具。
- 领取返回 attemptId/lease、知识快照、前序 documentIds、完整待修改稿。前序正文通过 read_document 读取；附件 read_file 按 64 KiB 返回 base64 和 nextOffset，或使用授权 REST 下载。
- 进度 report_progress 延长原领取 15 分钟；超时保留占用和结果，标待核对。状态不明不自动再次付额度启动。
- submit_work 每条带 title/body/sources/fileIds；shortfall 明确说明缺口。通过格式门槛不等于事实已独立核验。
- Computer 由唯一适配器执行领取，不再让原 Computer 重复 claim。`tasks/update` 使用官方 inputResponses 原问题键；确认成功仅表示答复被受理，不是任务完成。没有公开 HTTP 接口能随意停止原 Computer 时，Hub 不伪装停止。
- `POST /v2/oauth/start {memberId}` 返回官方授权 URL；callback 校验一次性 state/PKCE。`POST /v2/computer/respond {requestId,attemptId,inputResponses}` 只允许 owner；模型不能代用户批准。

资料依据：[Grok Routine](https://docs.x.ai/grok-bot/skills-routines-and-automations)、[Muse 已有实现](https://github.com/sabotage-dev/botline/blob/main/docs/recipes/muse.md)、[Dots Events](https://developers.openai.com/plugins/build/mcp-events)、[Computer MCP](https://docs.perplexity.ai/docs/getting-started/integrations/computer-mcp-server)。这些是接口依据，不能替代当前用户账号的真实验证。

## 4. 开发、发布和验收

```sh
npm test
npm run typecheck
npm run verify:collaboration
npm run verify:session
node scripts/deploy-collaboration.mjs acceptance
node scripts/deploy-collaboration.mjs production
```

部署脚本只读现有私有配置，校验目标账户和 D1，应用新增表，不重置 ADMIN_KEY、不写本地登录配置。验收云服务使用独立 Worker/工作区及测试身份，完成后删除自己产生的临时数据和 Worker；不向原平台发任务。production 前后比对原账户/成员是否保留。

ADMIN_KEY 同时用于派生平台凭证加密密钥。**不可直接轮换它**：需要先解密迁移原生连接/OAuth 数据再换新密钥，否则会明确报 credential_locked，不会覆盖数据。

本次没有执行 `deliver:local`，因为 UI 由另一位开发者负责，本分支不替换正式桌面界面。新 UI 合并后仍须执行正式打包、生效核对及完整用户路径验收。当前后端可联调，与“用户已经能从新界面使用完整产品”分开表述。
