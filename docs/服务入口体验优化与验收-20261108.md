# 服务入口体验优化：连接器、Vault 与技能

2026-11-08。本轮处理页面反复等待、服务目录隐藏和服务 Logo 裂图；不改变原 Agent 登录或凭证使用权限。实现已完成，最终安装与上线记录见末节。

## 问题与设计

- 旧版页面切换会卸载组件并清空列表，每次重新走跨地域接口。连接器还用 Promise.all 等待连接列表和运行端状态，任一慢请求都阻塞主内容。生产客户端重复导航实测约 0.8–2.3 秒；原始记录见 evidence/services-ux-20261108/before.json。
- 新版采用一份当前工作区的内存元数据缓存：请求合并、30 秒新鲜期、过期后保留原列表并后台更新、刷新失败保留已知内容，401/403 清空无权缓存。写操作立即更新已确认的公开元数据并使相关筛选失效；版本/工作区变化阻止旧响应覆盖新状态。先显示首屏，随后预热三个小列表；鼠标或键盘进入导航时提前取数。
- 缓存仅允许连接列表、运行端列表、Vault 列表和技能目录。凭证值、查看结果、备份包、OAuth 地址、技能正文均不在这个缓存中，不写 localStorage。各项实际操作仍由服务端检查当前权限与版本。
- 工作区更换清除旧缓存。跨端服务变更只通过既有更新流发出资源种类与 ID，由当前用户重新读取；普通成员不能收到全局 Vault 等资源 ID。运行端心跳只影响运行端状态，不重新加载整个目录。
- 连接器主页直接分「已连接」和「未连接」，带搜索/分类，点击服务卡片直接进入对应表单。已连接的同一服务可以有多个账号，保留添加另一个账号的入口；停用和待重新登录状态明确显示。自定义与导入配置直接可见。
- Logo 原文件误放在项目根 public/services，Vite 的根目录是 ui，导致客户端未带上图片，缺失图片却被当作 SPA 页面返回。新版使用静态 import 打包官网原始 Logo，包含飞书；记录各文件来源和哈希。自定义服务使用通用插头，不伪造品牌。

## 验收

1. 慢网络下冷启动目录先显示；运行端请求不阻塞服务目录。
2. 两部分目录、多个同服务账号、搜索分类、直接连接、自定义和导入均可操作。
3. 三个页面切回已读列表不清空；新鲜期内不重复请求；过期/断网更新保留内容。
4. 旧响应不能覆盖写操作后的新结果，切换工作区不串缓存；凭证值/备份不缓存。
5. 官网 Logo 全部可解码、无外网图片依赖，实际安装包同样验证，窄屏不溢出。
6. 原有真实 stdio 调用、权限撤销和 Vault 生命周期回归通过。
7. 登录资料保护门槛、实际安装启用与独立审阅分别留证；控制延迟样本不冒充全网持续延迟保证。
