# Claude 回执失败与会话阻塞修复

日期：2026-11-08。补充原诊断文档，不覆盖原始现场证据。当前为实现与验收候选，发布结果另记。

## 故障链与处理

1. 工具入口使用现有 JSON Schema 校验必填字段和类型，数据库查询也拒绝空记录编号。缺参返回明确 400，不再以 SQLite 500 掩盖错误。
2. 所有 Agent 共用相同入口。仅兼容已观察到的 stepId/turnId、docId/documentId 旧写法；两者冲突拒绝。文档、成员、聊天及原生会话权限照常检查。
3. 回执失败保留原通知、租约和 lastAckError，不自动重试业务或标记完成。纠正后仍可按真实身份正常回执。
4. Claude 使用官方插件 Stop、StopFailure、SessionEnd 事件报告本轮已结束。只传事件、原会话、通知、租约；不读取原生对话文件，不保存或转发最终回答。
5. 原生已结束但无成功回执：转为待核对并释放精确占用，旧工作不自动重做，同一会话中的新消息可继续。独立会话不受影响。已成功回传不能被晚到的事件改回异常。
6. 结束事件先在连接器自己的目录持久保存，断网和凭证刷新失败只重试观察，不重放文档修改或发送。过期租约、其他成员/会话事件不能释放新执行。
7. 真正的后台执行仍保留占用。常驻 Monitor 是消息监听器，不算未完成的推理任务，否则监听器自身会造成永久阻塞。

## 原生及产品边界

- 原 Claude 登录、模型、项目、工作会话和订阅保留。只更新 DuolaWork 自己的连接器与插件，使用官方 /reload-plugins 热加载。
- 结束事件不是业务完成证明。待核对与已完成分开，不能替 Claude 补写静默或伪造最终消息。
- 多个聊天若仍绑定同一个原会话，正常执行仍然串行；独立新会话才能并行。本修复消除假占用，不承诺同一原生会话同时执行多轮。
- 此事件观察适用于新版 Claude Monitor 插件。服务端校验与兼容立即适用于所有 Agent，旧连接器仍需更新后才具有可靠结束观察。
- 官方 Stop 不覆盖用户中断；进程丢失及断线继续使用现有运行状态核对和超时机制，不凭心跳宣称业务成功。
