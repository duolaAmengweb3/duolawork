# 从"数字员工"产品复用什么

- 日期：2026-10-26
- 目的（你的要求）：一人公司和数字员工产品已经验证过的**需求场景**和**产品设计逻辑**，我们拿来复用，把产品能力做好。
- 拆了谁：Sintra（12 个 AI 员工）、Marblism（7 个，自称 4 万多家企业在用）、Lindy（AI 队友）、Paperclip（开源 Agent 公司，约 10.7 万星）。数据多为官网自述。

---

## 一、它们的核心思路，和我们的区别

**它们：** 自己造一批"AI 员工"，每个员工是一个岗位（社媒经理、文案、客服……），卖一个订阅。

**我们：** 不自己造。**岗位照样设，但每个岗位交给握着那个生态的大厂 Agent 来干。** 用户想的是"我要一个社媒经理"，不是"我要配置 Muse 的 MCP"。

---

## 二、需求场景：一人公司要招哪些"岗位"

把 Sintra 和 Marblism 的岗位合在一起（两家都有的说明需求更确定），再对应到我们能用的大厂 Agent：

| 岗位 | 做什么 | Sintra | Marblism | 交给谁（谁握着这个生态） |
|---|---|---|---|---|
| **社媒经理** | 追热点、写帖子、排期发布、看哪条效果好 | 有 | 有 | X → Grok；Instagram、Threads、Facebook → Muse |
| **行政助理** | 管邮件和日程、约会议、每日简报 | 有 | 有 | Gmail、日历 → Gemini；QQ 邮箱 → WorkBuddy |
| **获客 / 销售** | 找潜在客户、写开发信、跟进到回复 | 有 | 有 | X 上的需求信号 → Grok；查公司资料、记进 CRM → Dots；跟进邮件 → Gemini |
| **SEO / 内容** | 写博客、做搜索可见度 | 有 | 有 | 检索 → Perplexity；写稿 → Gemini 或 Dots |
| **客服** | 用品牌语气回复咨询、处理评论和私信 | 有 | 前台（接电话） | Facebook 评论、Instagram、WhatsApp → Muse；企业微信 → WorkBuddy |
| **文案** | 广告、网页、邮件文案 | 有 | — | Gemini（写进 Google 文档）或 Dots |
| **数据分析** | 把数据变成结论和预测 | 有 | — | Dots、Perplexity |
| **电商运营** | 上新、订单、库存 | 有 | — | Dots（连 Shopify 等应用） |
| 建站、法务、招聘、个人成长 | — | 部分有 | 部分有 | 第一版不做 |

**一人公司最常要的前四个：社媒经理、行政助理、获客、内容。** 两家都有，国内新华网关于"数字员工帮一人公司"的报道里，提到的也是宣发、推广、财务。

## 三、产品设计逻辑：哪些拿来用

| # | 设计 | 谁在用 | 为什么有效 | 我们怎么用 | 优先级 |
|---|---|---|---|---|---|
| 1 | **按岗位组织，每个岗位有名字** | Sintra、Marblism | 用户按"我缺什么人"来想，不按"技术怎么配" | 新增"团队"：先招岗位（社媒经理、行政助理……），每个岗位指定由哪个 Agent 来干；任务按岗位派 | **P0** |
| 2 | **公司档案（共享大脑）** | Sintra 的 Brain AI（"整个团队共用一份记忆"）；Lindy 把记忆存成可编辑的文件 | 背景只讲一次，所有员工都知道 | "共享资料"升级成**公司档案**：你的业务、产品、客户、品牌语气、目标、禁区。向导第一步就填；所有 Agent 领任务时自动带上 | **P0** |
| 3 | **上手四步：讲生意 → 连工具 → 定规则和审批级别 → 让它们干活** | Sintra | 每一步都简单，不需要会写提示词 | 首次使用向导改成：① 讲你的生意（填公司档案）② 选场景和岗位 ③ 连上 Agent ④ 定审批规则 ⑤ 试跑 | **P0** |
| 4 | **定目标，它们自己负责；只在需要批准时来找你** | Marblism（"Set the goal. They own it."） | 用户不想天天派活 | 岗位可以设**例行工作**（每天、每周固定做的事）；平时不打扰，只在确认中心找你 | **P0** |
| 5 | **每日简报** | Lindy（每天 8 点）、Sintra 的行政助理 | 一个地方看到"团队昨天干了什么、今天要你做什么" | 每天早上一份团队简报：各岗位完成了什么、哪些等你确认、哪个 Agent 掉线了 | P1 |
| 6 | **做一次，存成技能，以后复用** | Lindy | 越用越省事 | 跑通的流程一键存成模板；每个岗位附带"实测过的原话" | P1 |
| 7 | **预算上限** | Paperclip | 不怕额度被意外用光 | 每个成员的叫醒次数上限，80% 提醒（PRD 已加） | P1 |
| 8 | **看效果，多做有效的** | Marblism 的社媒经理会追踪哪条帖子表现好 | 结果能量化，用户愿意留下 | 社媒经理岗位记录每条草稿后来的数据（需要你手动填或者接 X 数据） | P2 |
| 9 | **一个账号管多门生意** | Marblism、Paperclip | 一人公司常常同时做几件事 | 多个工作区，各自的档案和团队 | P2 |

## 四、要避开的坑（来自 Sintra 的差评）

| 坑 | 用户原话 / 现象 | 我们的情况 |
|---|---|---|
| 额度少、规则不透明 | 每月 250 个额度，多付钱额度也不增加 | 我们不卖额度，用的是用户自己的 Agent 订阅；我们只统计叫醒次数，规则写清楚 |
| 退款难 | 要发邮件才算申请退款，在页面上取消不算 | 将来收费时，取消和退款要在页面上一步完成 |
| 客服全是 AI | 找不到真人 | 早期你亲自支持第一批用户 |
| 能接的工具有限 | "integration with software is very limited" | 这正是我们的优势：大厂 Agent 本身连着几千个应用 |
| 结果会编造 | 不核实不敢用 | 模板里固定加"核实"这一步（比如 Dots 逐条查官网）；关键步骤要你确认 |

---

## 五、产品结构因此调整成三层

```
公司档案（大家都知道的背景）
    ↓
团队（岗位：社媒经理、行政助理、获客、内容……每个岗位由某个大厂 Agent 来干）
    ↓
工作（两种）
  · 例行工作：某个岗位每天 / 每周自己做的事
  · 接力任务：跨岗位、跨 Agent 的多步任务（原来的设计）
```

原来的"成员（Agent 连接）"变成团队下面的技术层：用户先招岗位，再看到"这个岗位由哪个 Agent 来干、它连上没有"。
