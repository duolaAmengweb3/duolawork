# 原生多会话与提速交付验收

日期：2026-11-07。范围：Claude 新建原对话、跨会话并行、单会话传递开销、连接器升级与不降级验收。负责人过度通知全员属于单独待审方案，没有混入本次行为改动。

## 用户现在怎样使用

账号连接一次；在每个聊天的成员对话入口，可以选择已有对话、新建对话或配对当前对话。Claude 的“新建对话”现在已经具备真实 VPS 创建能力，点击“创建并使用”后由原环境完成启动与绑定，不需要用户复制带参数的启动命令。

- 选不同的原生对话，可以并行处理不同群的事情。
- 多个群选择同一个原生对话，会共用它的执行队列，保留其连续上下文。
- 新对话默认有保存在 Agent 自己环境中的独立项目文件夹；也可以选择该环境已有项目。原项目不会搬到 Hub 本机。
- 本轮保留了用户原有群的绑定。原先共用 Claude“新电脑迁移”的群仍沿用该上下文；需要独立工作的群可以在入口新建。
- “独立对话”不等于四家都必须常驻一个操作系统进程，也不等于项目文件隔离。共用项目的修改仍需 Git / 分支 / worktree 协调。

| 运行方式 | 本次执行边界 | 已验证范围 |
| --- | --- | --- |
| Codex 原生会话 | 原生 thread 分开；官方宿主可复用进程 | 真实两段原对话并行，保留加入前记忆及各自项目文件 |

协议层已覆盖 1、2、3、4、5、10、17 个会话及重启、重复请求、同会话别名等情况。这个矩阵不代表在真实模型上同时压测了 17 个会话，也不承诺无限并发：模型账号配额、原平台限制和机器资源仍然存在。

## Claude 原生创建怎样落地

采用官方原生后台会话和原生会话列表，复用已经运行的 Claude 可执行程序及明确指定的 model / effort / agent 参数；不创建模型 API 替代品，不读取或复制提供方登录凭证，不改原生全局权限与模型设置。

创建先成为一个持久请求；同一请求只有一位接收器持有，启动前写独占日志。官方 `--bg` 自行分配真正的 UUID，不能假设它会使用调用者指定的 session ID。连接器根据原生命令返回、名称、工作目录与创建时间确定实际结果；新会话自己的监控上线后，服务器才保存绑定。失败、断线或不确定超时不会盲目再开一段，也不会覆盖用户刚选的其他对话。

首次新文件夹的信任问题已真实复现并修复：只有用户要求新建、由 DuolaWork 刚创建且为空的专属文件夹，才通过正常原生终端确认这个精确路径的信任提示。等待输入就绪和原生选中状态，不能把方向键与回车一次写进去。Linux 使用系统终端程序；Mac 使用 Python 标准库 PTY，因为 BSD `script` 不接受管道 stdin。任意其他项目若尚未受原生环境信任，仍报告明确的原生确认需求，不篡改信任数据库。Mac PTY 在隔离终端夹具验证，真实 Claude 创建验收在用户已授权的 VPS 完成。

原生实现依据：[Claude 官方 Agent view](https://code.claude.com/docs/en/agent-view)、[Claude 权限文档](https://code.claude.com/docs/en/permissions)。文档说明能力，下面的本机 / VPS 回传才是本次验收证据。

## 提速改了哪些实际路径

1. **按实际原生会话排队。** 不把同一账号下所有群锁在一个队列，也不固定只准两段会话执行。同一原生会话的别名依旧串行，避免上下文互相覆盖。
2. **领取直达。** 通知已经携带具体消息和群；Claude、Codex 工具入口、Gemini / Antigravity ACP MCP、动态工具及 DeepSeek 都使用同一领取约定。原环境传入真实 session，服务器原子校验群、成员、会话绑定和领取状态。移除了普通聊天领取前重复的列表查询。正式验证工作等兼容路径仍保留必要的查询。
3. **补齐后台形态。** 真实 Gemini 续聊发现后台 ACP MCP 仍走旧查询链，本次已补齐；不是仅修改“原窗口收到一段唤醒文字”的形态。保留原 stop-hook 所需工作标记，避免提速破坏原生完成回执。
4. **共享上下文并行读取。** 群记录、记忆、会议和授权等独立读取并行；不省略原来的权限校验。
5. **确认过的旧 Agent 消息用可恢复引用。** 检查点绑定成员、群和实际原生会话，只有实际回复 / 明确静默回执后才推进。首次或新会话收到完整消息窗口；用户原话、用户更正、触发消息、新消息、修改后的证据仍原文提供。只省略本会话之前确认收到且未变化的旧 Agent 消息，并保留可取回原文的编号、版本及读取入口。没有让另一模型压缩或改写原始结论。
6. **备用收件入口同样限定会话。** MCP、动态工具、终端 helper 和 DeepSeek 的 receive_messages 也补入实际会话与群范围，避免绕过相同的隔离和上下文约定。

原始资料、历史消息、约定和工具能力都保留。原生模型压缩自己的记忆后，如果缺少依据，连接器要求读原文；也提供完整上下文刷新。不能把“之前送到过”冒充“模型现在一定记得”。
