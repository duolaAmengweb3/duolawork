# 通用消息链路提速与可靠性

本轮范围对应项目群 #467 和 Todo「通用消息链路提速与可靠性」。2026-11-07 的候选实现；本文件下方按验证层更新，源码通过不能替代装机、远端或 DeepSeek 验收。

## 问题与改动

过去，用户发送后还要等下一轮定时刷新；刷新先读工作区再读整个群资料。原生连接器再按自己的时钟轮询，多个等待叠加。一次请求快并不能消除这些等待。

现在，消息和状态提交到同一个数据库事务时，同时写一条不含正文的变更记录。已连接的客户端立即被唤醒，原生连接器得到自己有权接收的真实消息。网络断开后按游标补通知；游标过期则重新读取权威收件箱。通知只是唤醒信号，不能代替消息保存、领取或执行。

传输使用可恢复的 HTTP 长轮询：每次最多挂起 8 秒，有变更立即返回；同进程提交直接唤醒，跨进程或通知丢失最长按 1 秒数据库检查补偿。没有引入新的消息服务器或要求用户开放入站端口。无变化时不调用模型。普通 API 与挂起通知使用独立并发配额，慢连接不占满消息写入通道。

客户端按群分别缓存、合并刷新。聊天消息和收发状态单独读取，资料面板独立刷新；较早返回的旧快照不能覆盖新消息。回车发送先持久保存本机发件箱并显示，服务器回执后立即合并，重试沿用原请求编号。后台更新不拉回用户正在看的历史位置。

## 原生 Agent 与会话边界

- Codex、Gemini CLI、Antigravity CLI 共用 CodingManager 的收件、回执、会话调度基础；不同原生会话可以独立处理，同一会话保持顺序。
- Antigravity 桌面版通过官方 Sidecar；DeepSeek Harness 通过原 Host 插件；Claude 通过其原生会话监听器。提供方适配器负责最后一段交付，共享变更通知和回执约定。
- 同一账号、同一接收进程只维护一条共享通知连接；多个会话不会逐个重复查询相同收件箱。一次查询进行中又有变化，必须补一次查询，不能把新通知丢到下一轮定时器。
- Grok / Dot 的官方回调接入仍沿用官方方式；共享服务端和 UI 的改进适用，但不伪称能控制官方平台内部排队或模型速度。
- 已绑定的项目、原会话、模型、原生工具、账号、上下文和原执行权限保持。没有两会话产品上限；资源、提供方限制与同会话串行仍真实存在。

## 回执含义

| 字段/显示 | 由什么事实产生 | 不代表什么 |
| --- | --- | --- |
| 消息已保存 | 服务端事务提交 | Agent 已接收 |
| connectorReceivedAt / 消息已接收 | 连接器将实际消息写入私有文件并同步到磁盘，再回报服务端 | 模型已开始 |
| nativeAcceptedAt / 原对话已收到 | 原生接收接口接纳通知 | 原生排队已结束 |
| nativeStartedAt / 已开始处理 | 原生协议明确报告本轮开始 | 已有有用答案 |
| claimedAt | Agent 实际调用领取工具 | 网络收件的开始时间 |
| firstPublicOutputAt | 原生协议出现对用户可见的本轮输出 | 输出已解决问题；隐藏推理不会采集 |
| completedAt | 原 Agent 正式回到 Hub | 所有产品验收自动通过 |

所有这些服务端时间使用同一时钟；接收时间包括回执返回服务端的链路，不能拿两个机器的墙钟直接相减。缺少原生事件的适配器保留空值，不推算、不补造。未知 token 用量也保持未知。

回执同时校验成员、群、原会话、恢复轮次及源消息版本。回执丢失可以幂等补传；旧会话的迟到回执不会改变新会话状态。领取和外部副作用的去重仍以原有权威记录为准。原生发送结果不确定时保留待核对，不盲目重做。

## 主任务与协作通知

通知带明确说明：处理这一条、回群后继续原会话中尚未完成且用户仍授权的主任务；用户停止、暂停或改变任务时服从用户。没有自行领取 follow-up 或循环监听。此规则不能被当作所有模型行为的数学保证；必须在原生实测中验证。群回复成功不能被汇报为开发/部署任务完成。

## 验收标准

1. 输入至可见消息 p95 ≤100ms；100 次实际回车，保留全部样本，覆盖迟到 ACK、切群、草稿与滚动保留。
2. 在线空闲运行端，服务端保存至连接器落盘后回执目标 p95 ≤1 秒。协议基准至少 100 次，不调用模型；真实公网需独立报告 RTT 与样本，不能挪用回环结果。
3. 1/3/5/10 等多会话独立，单会话有序；忙会话不会阻塞其他会话；重复和断线不重复执行。
4. 保存后通知失败、回执丢失、重启、乱序、会话更换及权限撤销均有明确恢复或拒绝路径。
5. 原生模型、工具、会话、项目与完整要求保真；已有 MCP 工具兼容；无模型空轮询。
6. 源码、协议测试、真实模型、部署和 DeepSeek 独立验收分别记录。

## 兼容矩阵与退路（首轮审计补充）

下表描述本次候选连接器的实现；“支持”不等于该用户机器上的旧进程已经加载新版。运行版本证据单独记录。

| 接入形态 | changes / inbox | 落盘接收回执 | 通知不可用的原有轮询间隔 | 本轮真实原生证据 |
| --- | --- | --- | --- | --- |
| Codex 原工作对话 / 托管 CLI | 支持，公共 CodingMemberClient | 支持 | 5 秒 + 请求耗时 | 同账号两段原生对话重叠，慢 A 等 30 秒，B 先完成；项目识别词及文件不串 |
| Gemini CLI | 支持，共用调度基础 | 支持 | 5 秒 + 请求耗时 | 协议测试通过；本轮没有单独的官方 Gemini CLI 账号实测，不能把 Antigravity CLI 算成它 |
| Antigravity CLI 后台工作对话 | 支持，公共 CodingManager | 支持 | 5 秒 + 请求耗时 | VPS Gemini2VPS 两段已有专用对话，慢 A / 快 B 实测；收件与模型耗时分列 |
| Antigravity 桌面 / CLI 原生监听 | 支持，公共 Sidecar | 支持 | 3 秒 + 请求耗时 | 协议与既有原生历史证据；本轮装机原生回传另列，未完成前不标本轮通过 |
| DeepSeek Harness 桌面 / 服务端 | 支持，公共 DshConnector | 支持 | 3 秒 + 请求耗时 | 真实桌面独立审计；接收器加载版本单列 |
| Claude 官方 Monitor / Channel | 支持，公共 ClaudeChannel | 支持 | 2 秒 + 请求耗时 | 原后台会话、工具仍在原 VPS；磁盘更新与进程重载单列 |
| Grok Bot / Dot 官方自动回调 | 原有官方链路，不声称第三方平台消费 changes | 无法证明第三方内部落盘则保持未知 | 官方平台控制 | 共享服务端与 UI 改进适用；不虚构官方内部接收/排队时延 |
| 旧服务端不提供 inbox | 404 回退原 list_work | 无 delivery 信封时不补造回执 | 各运行形态上表间隔 | 有意兼容；不能显示“新版落盘已收” |
| 旧连接器连接新服务端 | 保持其原请求协议 | 缺失阶段保持空值 | 旧版本自己的实际频率 | 必须逐运行端更新后才取得新的收益 |

2 秒缓存只保存刚刚收到的同成员权威 inbox 推送，用来让同一进程多个会话共享一次读取。普通 HTTP inbox 查询只合并进行中的请求，不缓存结果。未订阅时不存在这个缓存。正常通知会替换它；停止、通知错误、401/403/409 和写工具立即清除。若网络静默丢包尚未报错，旧快照最多可用 2 秒，之后 fallback 会直读；不能承诺断网期间 1 秒。通知 request 本身有超时，重连为 1/2/4/8/16/30 秒退避；轮询独立继续，不跟着退避停止。UI 通知不可用仍按原 6 秒兜底，不退化为 15 秒。

## 故障注入、信任边界与原生保真

- `tests/dsh-connector.test.mjs`：真实文件系统 ENOTDIR 写入失败时，不发 received、不运行原生 prompt；恢复路径后重新持久化，再 received/accepted。
- `tests/receiver-crash.test.mjs`：测试子进程真实 fsync 后、ACK 前 SIGKILL；磁盘保留完整消息、ACK/原生启动数为零；重启后先重落盘再 ACK；第二次重启无重复原生执行。只终止隔离测试进程。
- `tests/change-feed.test.mjs`：事务回滚不发通知，保存成功后通知丢失可从日志/权威 inbox 恢复，过期游标 reset、撤权、取消、分页重放。
- `tests/native-delivery.test.mjs`：丢失 ACK 幂等重试；相同 requestId 在会话、恢复代次、源消息版本变化或撤销连接后也必须重新授权，不能用缓存成功绕过。
- `tests/native-delivery-client.test.mjs`：进行中读取合并；通知错误立即清缓存并显式切到 fallback。
- `tests/message-snapshots.test.mjs`：旧快照、延迟资料投影不能覆盖新消息和处理状态。
- 服务端不能远程证明用户磁盘或恶意自制连接器。收到回执表示“已认证运行端报告先落盘”；官方连接器以写入顺序与故障测试保障。源消息、授权、绑定和执行完成仍由服务端独立校验；不能宣传成远程磁盘证明。
- Codex 真机样本 `codex-native.json`：peak=2，慢 A 等 30 秒时 B 提前 41.4 秒完成；两个原项目 scope.txt 原文未变，加入前上下文识别词正确回传。
- Gemini 原 CLI 样本 `gemini-native.json`：peak=2、B 先完成；原生会话 UUID/绑定不变、未指定替代模型或改登录。旧测试绑定显示 /home/claude/workspace，而原生历史会话实际 cwd 为运行端 workspace；实测回传的是原生原 cwd，不把显示路径等同于代码运行路径。
- Gemini 首次采样脚本错用 sourceMessageId（真实字段为 messageId），未正确等待 A 活跃，因此没有发 B。该首次消息已正常完成；修正采样器后重新执行完整双会话测试，首次单样本保留但不冒充并发通过，也不混入 100 次协议分位数。
