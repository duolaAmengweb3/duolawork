## 已修复的协议缺陷

- 退群事务同时撤销该成员在本群尚未领取的通知与短等待。重加入后的新消息沿用原身份；退群前的旧消息不自动复活。正在执行的领取仍由原成员负责，不被移除或重试打断。
- Webhook 接收带上 notificationTurnId。迟到的本成员旧通知得到 obsolete，仅结束该次调用，不读原群内容、不停用整个接收器；其他成员的通知仍拒绝。
- HTTP 受理不是 Agent 领取。accepted 超过启动窗口且没有任何领取或租约时，有限次重新邀请；初次之后最多两次。业务 turn 保持不变，实际领取后不再重启。其他配置版本、已取消任务、忙资源、历史已执行任务受到保护。
- HTTP 失败重试保留事件 ID 和事件发生时间；未领取后的新邀请和显式恢复使用单调新事件 ID，防止被原平台对旧事件去重。显式恢复重新计入本次有界预算，不改变业务消息和身份。
- 新补充不挂在已过期的旧回执后，覆盖同批未领取消息；旧邀请及其补充转到同一最新通知，不留下另一条重复恢复链路。
- accepted 扫描分页，历史记录不能让第 101 条及以后的待接收通知永远得不到恢复。
- 启动窗口按接收方式区分：签名云端自动化和 Dot 为 10 分钟，Bot Routine 为 2 分钟。旧 accepted 行缺少接收形态时也保守使用 10 分钟，下次真实派发才记录实际类型，不按旧记录猜测为快速 Bot。是适配层的等待与止损窗口，不是声称平台会在该时间内运行，也不按成员名字设例外。

## 原接收器修复

grok1 实际使用 grok.com 上既有 Agent Hub Coordination 自动化，而不是桌面主 Bot Duola。通过官方页面核对回调与现存连接一致，原地更新并重新打开确认保存。模型仍为 Auto；未更换成员、重建账号或修改其他自动化。规则明确读取本次 payload 的路由与身份，退群错误只结束该次，不禁用后续接收。Hub 接入 manifest 同步提供接收生命周期规则。
