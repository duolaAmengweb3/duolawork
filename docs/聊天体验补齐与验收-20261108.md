# 聊天体验补齐与验收 · 2026-11-08

本轮从实际聊天操作补齐四类缺陷，沿用既有群聊、负责人、原生会话与投递规则。不是重新设计协作机制，也不是对所有产品体验的全面无缺陷承诺。

## 改动与复现

| 缺陷 | 修复后的行为 |
| --- | --- |
| 回复到一半切换群聊，只保留文字，丢失回复对象 | 回复对象与文字、提及和引用一样按聊天保存；完全退出桌面客户端后仍可继续原回复 |
| 失败消息点“修改”，正文被塞进当前输入框，丢失原收件人、引用和回复关系 | 在失败消息原位置编辑并重新发送，保留原有上下文，不覆盖正在写的新草稿；修改后的请求使用新幂等键，未修改的网络重试继续用原键 |
| 加载更早历史后立即切群，迟到的历史响应插入新群 | 历史读取绑定发起时的聊天和页面访问轮次，迟到响应不改当前聊天；加载期间显示进度并防止重复点击 |
| 点击较早的回复预览无反应，因为原文不在当前 50 条消息中 | 按需获取原文并定位，提供“回到原阅读位置”；定位过程中切群也不会串内容 |

待发送消息同时显示 @全员、回复及会议信息，避免提交前后呈现跳变。尚未保存成功的消息不能作为新的回复、Todo、记忆或资料引用来源，避免使用临时消息 ID 产生无效操作。

失败消息只有在确定被拒绝时才能修改；结果未确认的消息仍只允许使用原请求重试。新正文与原发送上下文一起原子写入本地发送队列，再实际发送；本地写入失败不删除旧失败记录。

## 验收

- 原版真实界面复现了四个用户可见缺陷，保留 [修复前记录](evidence/chat-recovery-20261108/before.json)。第五项是定位过程中切群的补充回归；原版因尚不能定位，未进入异步定位流程，不能将其算成独立的原版复现。
- [浏览器实测](evidence/chat-recovery-20261108/browser.json)：5/5，通过真实本地 HTTP 后端，历史读取注入 1.2 秒延迟；不是静态截图或模拟 React 状态。
- [实际安装包实测](evidence/chat-recovery-20261108/installed.json)：5/5，包含完整退出 Electron 进程、重开、继续原回复。使用隔离数据，不改用户聊天与原生 Agent 登录。
- 588/588 自动测试、类型检查、浏览器登录资料保留门槛及安装包生命周期检查通过。
- [速度回归](evidence/chat-recovery-20261108/latency-browser.json)：100 次 Enter 到消息绘制 p95 12.8ms，最大 33.7ms；10 次未读聊天进入，最大 20.6ms；另覆盖 20 次切群草稿与阅读位置。命令回执注入 120ms 延迟、未读读取注入 1.2 秒延迟。数字只表示本机 UI 响应，不代表 Agent 模型出答案速度。
