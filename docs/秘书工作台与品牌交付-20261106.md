# 秘书工作台、会议状态与官方品牌

日期：2026-11-06。本次是既有 M1–M11 实施后的收尾，不替换自由沟通、账号接入与每群工作对话的产品模型。

## 用户会看到什么

- 左侧「秘书」直接打开右侧工作台，保留原群、草稿和阅读位置。可展开、收起，Alt+S 可切换；设置藏在齿轮里。第一次由用户指定秘书，以后可以更换。
- 工作台内直接交代事情，呈现具体委托、进展、答案及来源。未发出的内容保留；请求结果丢失后重试沿用原编号，避免重复建群或重复执行。更换秘书后不把尚未发送的旧委托静默转给新秘书。
- 八个入口分别是日报、项目概览、团队动态、三句话看懂、盯一件事、找上次的决定、整理资料、安排协作。需要 Agent 推理的入口准备可编辑的自然语言要求，用户确认发送；概览与动态直接展示已有记录。
- 「待我处理」列出真实等待回答的问题。项目概览根据群内 Todo 统计，明确不是项目完成率；团队动态只展示 Hub 能观测到的领取与进展，不猜原 IDE 是否空闲。
- 可选每日指定时间生成日报，按用户时区，同一天不重复派发；重启后保留。秘书变更后，原秘书的定时安排停用，用户可重新开启。原 Agent 的模型处理耗时另计，没有“两秒完成跨项目分析”的保证。
- 持续关注绑定实际 Todo 或会议，结束后交给秘书读取结果并回报。用户可以停止关注。不凭一句“我会盯着”显示已经设置，也不反复唤醒 Agent 空转。
- Coding 秘书沿用既有账号和工作对话选择器；尚未选择时给出一个明确入口。没有为用户偷偷选择项目、接管其他原会话或改变原生模型。

## 会议

群聊顶部保留一条轻量会议状态，清楚显示筹备、进行、收尾、结束以及进入记录的入口。开始和停止可以直接点击。聊天过程完整保留。

负责人可以理解自然口语的确认；使用开始工具时需引用最新用户原话和消息编号，保存确认来源。不能拿成员意见、旧要求或提交计划之前的输入冒充用户确认。仍有不确定时由负责人简短确认，用户不需要背固定口令。人类直接点击开始仍核对当前计划版本。

## Logo 与动态

素材来自用户提供的 `32号-Agent-Hub/DuolaWork-Logo-Kit`，保持官方图形、颜色和比例。

- 桌面 App / Dock：官方 ICNS。
- 主侧栏：循环摇铃动画。
- 秘书入口、工作台、空状态：摇铃或伸手动画。
- 欢迎页、载入状态：循环伸手动画。
- 浏览器页签与快捷图标：官方 favicon / apple-touch 图标。

保持 SVG 自带的减少动态支持，不添加闪烁或影响消息阅读的动效。第三方 Agent 仍使用各自品牌头像。

## 实现与边界

全局秘书沿用已存在的 `manage_workspace` 授权、实际成员身份与原生执行环境。新增委托/关注/日报记录负责持久化；具体理解、沟通与办理仍由秘书 Agent 完成。不是固定步骤的流程机器人，也没有另建一个模型 API 助手。

`overview` 读取真实跨群记录；`request_update` 写明实际状态和结果；`watch` 关注一个真实对象。用户输入在原秘书单聊里正常投递，工作台从真实消息回执呈现结果。已回复与事情已完成分开显示。更换秘书即撤销旧成员的全局管理能力。
