## 判断

整体方向合理：共享连接器让获授权成员取用同一来源，技能让可复用方法按需参与工作，执行仍留在各 Agent 原环境。应沿用这条路线。但第 5 版仍把若干产品概念混在一起，直接照开发会造成「已经安装却用不了」「强制所有成员套同一种方法」「每用一次都要审计」的问题。

## 建议保留的核心

- 原 Agent 已有工具、登录、技能继续由原环境管理；Hub 增加团队共享能力，不接管 IDE/VPS。
- 用标准 `SKILL.md` 和配套资源，不另造私有技能格式；按需读取，不把整个库正文塞进每次消息。
- 显示账号、真实范围、能做什么、读取结果和来源；导入、可读取、成员报告与独立验证分开。
- 撤销阻止后续新访问；已读内容不能远程从模型中抹去。失败可以展示带日期的旧资料，但必须明确是旧资料，不冒充本次读取成功。
- 先把现有 GitHub 只读完整做好，再按实际资料需求增加连接器；飞书是候选，不因会议推荐自动取得开发及账号授权。

## 需要修改的产品定义

| 当前说法 | 问题 | 建议 |
|---|---|---|
| 导入文件叫「已安装」 | Hub 存了文件不等于 Codex、Claude、Gemini 均原生安装 | 默认叫「已添加 / 可供使用」；只有适配器验证过某原环境安装才显示该环境已安装 |
| 技能是本群模板，写一次全员遵循 | 技能也可能是查资料、分析或调用工具的方法；同一群会干很多种事 | 技能可分配给群/成员，但由 Agent 根据当前任务按需选用。用户明确要求的格式/约定才是必须遵守的约定 |
| 一键把群共识变技能 | 把反对意见、临时提案、一次性事实整理成永久规则会失真 | 支持「把这个做法保存下来」；负责人结合实际成功案例起草，保留来源、适用条件、反例和版本。不因多人点头自动提升为强制规范；已授权的方法整理可以由 Agent 完成，不逐条找人审批 |
| 安装→读取→使用→已验证四态 | 这是不同成员、不同运行、不同版本的记录，不是一条全局单向流程 | 技能卡只展示可用范围和依赖；详细使用记录按任务/成员/版本展开。核验关联某次产物，不能一人用成功就全员永久变绿 |
| 有 scripts 就每次必须跑 | 一个包内脚本可能只服务部分用法；没有 scripts 也可能调用外部工具 | 按本次步骤需要执行什么、依赖什么来判断；hasScripts 只作为内容提示。应执行却没执行要说明，缺记录只代表尚未核验 |
| 每次应用都要在群里报技能版本并独立验收 | 会把简单任务变成汇报和审批负担 | 后台记录到对应任务；按实际任务验收要求核验结果。不额外强制开会、发消息或增加人类确认 |
| 所有读不到都显示去授权 | 网络、限流、路径错误不是重新授权能解决 | 按可知原因给操作：稍后重试、检查资源、补权限或更新授权；无法区分则明确不可见或不存在 |

## 简单的用户流程

**连接器**：进入「连接器」→选服务→授权→看清账号、资源和使用范围→群里直接让成员读取。已有授权足够就继续，不反复确认。它承载获授权的外部工具能力，不永远限定只能读资料；首期只读是交付范围，后续写能力需明确动作和权限。

**技能**：用户导入现成技能，或说「以后这个事情按刚才的方法做」。成员在授权范围里保存方法与适用条件；复杂/有争议的规则先作为提案而不是用户决定。界面只需显示「做什么、谁可用、缺什么、最近用在哪里」。不要求用户了解方法类/脚本类、加载器或内部证据等级。

**与任务关联**：一个任务可以用多个技能。任务保存使用的版本与产物；技能更新不改写旧产物对应的版本。后续新增 Todo 默认继承任务明确选定的适用方法，但仍核对兼容条件；不把技能硬绑定到全群每一次闲聊。

**与记忆关联**：记忆保留背景、事实和决策，技能保留可重复操作的方法。二者可以互相引用来源，不重复存一份互相冲突的强制规则。群经历保留这个方法为何形成、哪里失败过。

## 实施边界和已有缺口

当前代码已有：GitHub 账号和仓库级读取、群/成员范围检查、撤销后新请求检查、调用后再次校验授权版本；标准技能文件、版本回退、可用范围、按需读取和成员自报使用。

仍需开发：实际资源读取时间与可区分的读取失败记录；技能读取/运行/独立核验记录与查询；任务关联；从群经历提炼方法的可靠流程；原环境能力/依赖检查。当前仅从公开 GitHub 原文 URL 导入一个 SKILL.md，不等于导入完整含引用和脚本的技能包。完整包须有固定版本及依赖资源，不应宣称任意公开链接均可直接运行。

权限范围保留现有开放策略的语义，但 UI 必须明确写「全工作区/全部成员」及新成员是否纳入；若用户改成指定群和成员就按实际选择检查。不在这次评审中悄悄改旧授权。现有 150KB 是本产品限额，不是 Agent Skills 标准统一上限。

推荐开发顺序：①现有连接器与技能真实状态/来源/使用记录；②技能关联任务、按需使用和缺依赖反馈；③受控方法沉淀；④选定的第二连接器与必要的写操作。前三项已纳入本次实施，归于“连接器与技能完善”任务；第二连接器及写操作仍须按实际资料需求选定，不把会议结束当作功能上线。

## 依据与限制

- [Agent Skills 格式规范](https://agentskills.io/specification)：技能目录可包含说明、scripts、references、assets；compatibility 表达环境需求。支持复用标准包，而不是固定群模板。
- [Agent Skills 官方接入指南](https://agentskills.io/client-implementation/adding-skills-support)：先提供目录摘要，匹配当前任务再加载正文和引用资源；云端可用 API/registry，文件读取只是其中一种入口。支持 Hub 的按需分发路线，不证明每家原生安装均已完成。
- [MCP 授权规范（2025-06-18 版本）](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization)：工具接口与授权范围是不同层；这里引用其边界，不把 MCP 本身说成账号和依赖自动配置方案，也不将该历史版本冒称最新。

前述实现事实来自本次源码检查；产品取舍是本次建议，未运行新的商业账号或脚本联测。原会独立意见已经提出多项正确边界，复核是在原方案上修正，不重新造一套产品。
