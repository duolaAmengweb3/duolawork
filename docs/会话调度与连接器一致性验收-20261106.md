# 会话调度与连接器一致性验收

本轮针对的问题：不能只让某一次三会话演示成功；换成两段、四段、五段，或换成另一家 Agent，仍应遵循同一套协作规则。

## 用户应看到的行为

1. 一个账号可以在不同项目、不同原生对话里同时工作。Hub 不设“两段”或“三段”的产品上限。
2. 两个群如果选择的是同一段原生对话，就按顺序处理。选择不同对话，彼此不排同一个队。
3. 一段对话连接慢、正在换绑或执行失败，影响的是那段对话；其他独立对话继续。
4. 消息已回群、原生任务已结束、接收器已经更新，是三件事，必须分别有实际回执。
5. 更新、掉线重连和重开软件保留原账号、项目、对话与消息身份；不通过另开空白对话伪装恢复，不自动重复执行结果不明的旧任务。

这不是无限并发承诺。机器资源和原厂账号限流仍然存在，发生时应显示真实原因；Hub 不额外用账号级队列把独立工作串起来。

## 公共规则与各家适配的分工

公共服务记录“哪个群属于哪段原生对话”，按这个身份领取消息，拒绝过期绑定与重复领取。不同会话可以同时领取；同一会话的多个群不能同时写入同一原生上下文。

各家接收器负责把这份工作交到正确的原生对话，以及核对平台实际的执行状态。它们必须满足同一组规则，但平台接口不同，不能认为一份 Gemini 测试可以证明 Claude 或 DeepSeek 已可用。

| 适配形态 | 本轮核查/修改 | 验收层级 |
|---|---|---|
| Codex 原生对话 | 公共 CodingManager 按原生会话调度；保留官方 thread 与 turn 身份 | 多数量调度、实际服务端领取及原生协议测试；独立真实 Codex 测试另记结果 |
| Gemini CLI | 使用相同调度规则，保留 ACP session 身份 | 多数量调度及服务端协议测试；本轮没有真实 Gemini CLI 模型验收 |
| Antigravity CLI | 公共调度 + 原生 Stop 回执；前台返回不等于后台完成 | 真实 VPS 三会话后台命令、回群、结束回执、自更新；连续消息补验另记结果 |
| Antigravity 桌面/IDE | 公共调度及已有原会话桥接 | 隔离协议回归；本轮不把 CLI 证据当作 IDE 实测 |
| Claude 原生 Monitor/MCP | 每个原生会话独立通知与领取，忙碌只影响自己的会话 | 多数量真实 Hub 协议 + Monitor/MCP 适配器测试；未操作用户 Claude 登录或真实原会话 |
| DeepSeek Harness | 修复插件中账号级阻塞；按原生会话分别轮询，慢会话不拖住其他会话；持久化写入排队，避免并行记录互相覆盖 | 多数量插件测试、真实服务端协议；官方 Harness 原生隔离验收另记结果，不能冒充桌面实测 |

Antigravity CLI 的 `fullyIdle` 来自原厂 [Stop Hook 文档](https://antigravity.google/docs/hooks/)，表示后台任务也已结束。只在精确会话、精确本轮工作下接受回执；旧一轮回执不能释放新工作。正常关闭等待在途工作，重启恢复也不能仅凭“已回群”释放仍活着的原生任务。

## 自动化验收覆盖

数量取 **1、2、3、4、5、10、17**。这个集合用于覆盖边界和多数量行为，不是产品允许数量列表。

- 公共调度：Codex、Gemini CLI、Antigravity CLI、Antigravity 共 28 个组合；每段会话有两个群别名，重叠轮询不重复启动，乱序完成后新消息继续。
- 服务端领取：Codex、Gemini、Antigravity、Claude、DeepSeek 共 35 个组合；独立会话同时领取、别名互斥、原绑定忙时不能变更、换绑后的旧会话领取被拒绝。
- Claude：7 种数量；每段原生对话独立唤醒，已领取工作不被重复打断，其他忙碌对话不影响已完成对话接下一条，重启保留领取身份。
- DeepSeek：7 种数量；同账号各对话同时入原生队列，重启不重复入队，别名消息继续；另测某段轮询挂起时其他对话连续接收。
- 原生生命周期：后台完成晚于前台返回、回群晚于后台任务、旧回执、原进程关闭、接收器停止、恢复时原进程仍存活。
- 更新生效：远端以实际版本心跳为准；DeepSeek 桌面以运行中的插件版本为准，写好新插件文件不算原软件已加载。

DeepSeek 的新增测试先在原实现中复现：2、3、4、5、10、17 段全部只派发了一段。修复后全部通过。保留这个修复前失败记录，避免以后又把账号当成执行队列。

对应测试：`coding-session-concurrency.test.mjs`、`execution-bindings.test.mjs`、`native-continuation.test.mjs`、`dsh-connector.test.mjs`、`dsh-desktop.test.mjs`。现有单会话、权限、绑定、消息与重启回归一起运行。

## 真实运行记录

Gemini2VPS 原有五项群/单聊绑定不变。本轮仅使用三段专用验收对话。每段真实执行 25 秒命令，实际三路重叠约 18.83 秒，各自回到对应群，再收到同轮 `fullyIdle=true`；原生会话释放为 idle。原授权、自更新前后的会话身份均保留。

之前的早退、后台权限、重启循环等失败及人工维护恢复，保存在 `evidence/gemini-parallel-live-20261106.json` 的历史记录中。人工维护恢复不算 Agent 自更新成功，命令执行了但没有回群也不算验收完成。

当前完整交付版本、连续消息与其他原生测试结果，以 `evidence/global-audit-release-20261106.json` 和后续补记为准。此文档不声明所有原厂客户端、所有版本、无限并发或未测试的用户环境都已通过。
