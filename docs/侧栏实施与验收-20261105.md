# DuolaWork 侧栏实施与验收 · 2026-11-05

本轮来自用户对资料区、记忆管理和 Todo 进度跟踪的要求。保留自由聊天、用户选负责人、显式 @ 和 @全员，以及原 Agent 的账号、项目和会话。

## 用户实际怎么用

- **资料**：文件、共享文档、链接进入同一资料区，按文件夹和子文件夹整理，可分类查找。支持创建、重命名、移动文件夹，移动文档/文件/链接；仅删除空文件夹。新建文档、链接和上传附件进入当前目录，刷新后保留浏览位置。文件夹位置与资料 ID、内容版本独立，整理目录不会改变已发送的引用。上传到侧栏只保存，发送到聊天是明确动作；在聊天上传仍保留附件消息。资料可以引用到输入框，发送时保留对象类型、ID、范围、版本，Agent 能按版本读取。
- **Todo**：从消息留下待办，或在侧栏直接新建；名称之外的字段可稍后补充。指定成员会真实通知，只有成员实际接手才显示接手记录。支持待办、进行中、受阻、完成、取消；保留进展、受阻原因、截止日期、结果、来源消息和变更历史。用户在界面标完成要写明具体结果，不把“已完成”当系统独立验证。
- **记忆**：本群共享背景、要求、决定和经验。用户直接保存即生效；成员提出的内容标为待核实，确认后采用。编辑保留历史版本，停用后不进入后续 Agent 上下文。历史便签保留身份，缺少原始依据明确标注。支持标题/正文关键词查找、来源与引用。
- **会议**：点击开会只需描述想讨论什么，已有群负责人无需重选。需求直接进入群聊，负责人在群里继续澄清；侧栏查看安排并确认开始。过程与原群消息关联，会议记录可留下 Todo，Todo 可关联已有会议，双向回看。
- 群成员仍在顶部头像和群设置管理。查看或搜索侧栏不唤醒成员，普通聊天不强制建 Todo、文档或会议。

## 工程与兼容

沿用现有 SQLite、对象授权、通知、MCP 和文件存储。没有新建登录/配对系统。新增 read_space_object、search_memory、read_memory、revise_memory、read_todo、manage_folder、move_material；扩展既有 remember、board_task 和 post_message refs。

资料目录使用 channel_folder 和 material_placement 记录，不搬动实际文件字节。沿用现有 VPS 对象文件区；本轮没有迁移存储、接入 GitHub 或更换后端。

Todo/记忆以版本避免并发覆盖；来源与会议必须在本群；停用/未核实记忆不作为 Agent 的有效共享记忆。任务通知具有正常消息及投递状态，保存指派不等于成员已经接手。原版 board_task 的三种状态、旧记忆批准接口保留兼容。

会前沟通同时保留原会议筹备记录和对应群消息，使用同一条记录 ID 去重；不按时间窗口猜测历史消息属于哪场会议。原独立思考/公开核验和自动收尾行为保持。

## 明确尚未交付的原方案部分

本轮提供的是可管理、可供原 Agent 读取的共享记忆业务层。**没有上线 Mem0/Qdrant 语义索引、后台自动抽取、跨群记忆推广或完整删除/备份清除流程。** 关键词检索标明 retrieval=keyword；界面不声称自动学习、不提供未实现的彻底删除。

原《侧栏协作空间重设计》的 Mem0/Qdrant 选型不被替换，仍是后续记忆引擎方案。120题语义召回、万条容量和跨平台商业Agent效果对比未通过本轮测试，不计入完成项。未配置 embedding，不向新的外部供应商发送协作内容。
