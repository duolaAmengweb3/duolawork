# 群聊管理与阅读体验修复 · 2026-11-08

## 用户看见的变化

- 聊天列表右键：置顶/取消置顶；群聊还可删除。群设置中也提供相同入口。
- 置顶保存到工作区，重开后仍保留。新消息预览仍须等正文缓存就绪，置顶回执不能绕过它。
- 删除前显示准确群名与影响。删除群聊移入「已删除群聊」，可恢复原群、消息和资料；不删除 Agent 的账号、原生项目或工作会话。
- 删除停止该群尚未开始的通知与会议。若该群当前正在执行，明确提示等待完成，不打断原生工作。恢复后不会重放旧通知。
- 浏览历史时保留正在看的消息和偏移。新消息只显示数量提示；用户点击「回到最新」，或自己滚到底部，才恢复跟随。

## 根因与实现边界

原聊天接口按最新 50 条返回。用户正阅读分页前部时，收到新消息会替换最新页，刚读的消息可能先退出 DOM，再异步取回，造成跳动。复现用真实 Agent 身份的 post_message 与隔离 HTTP 服务，故意延迟历史回补；旧版本断言「正在阅读的消息被移出了列表」失败。

修复在用户阅读历史时保留移出最新页的已加载消息；服务器最新页仍覆盖同 id 的旧内容。布局更新按消息 id 与屏内偏移维护位置，容器高度也纳入观察。新消息提示悬浮显示，不占据聊天列表高度。未改变 Agent 路由、协作规则、模型、原生连接器或执行方式。

新消息提示统计阅读期间新到的已保存消息（含本人其他端与 Agent）；不把它等同于全局未读数量。历史保留随阅读和主动加载增长，本次未声称验证超长群聊无限数据的性能。

群删除是可恢复的工作区管理操作，只有人类 owner 可置顶、删除或恢复。删除使用当前版本，拒绝过期请求；被删除群不进入普通列表、未读和秘书概览。已授权原成员仍可按 id 读历史，删除不是撤销历史访问权。旧发言/更新不能自动复活该群。
