## 1. 做出的产品

用户已有的 Grok Bot、Dot 接入后，交代一次目标，成员真实领取、分工、交接、补证、自查，交回可编辑成果。默认一份最终成果，用户明确选择时才并排独立提交。修改、取舍和经用户确认的规则能在下一轮沿用。

- 不新增 Hub 的模型调用。汇总、语义检查、补证、归纳规则由原 Agent 做，程序负责依赖、访问控制、结构校验、版本、调度和计数。
- 不用浏览器点聊天伪装后台协作。第一批按定稿接 Grok 的 MCP + Routine、Dot 的 MCP + Events；具体协议、授权、订阅和回执条件先做技术核对。
- 接口、协议或 SDK 实际不满足时，记录原始证据和影响，回 #16 提出差异。未经所有者确认不换成网页脚本、轮询或另一家 Agent 当成完成。
- Muse 第二批；不顺便加入组织架构、排名、OKR 或其他平台。开发顺序只是依赖安排，交付范围仍是完整 v1。

## 4. 真实账号验收：同一目标的六条主线

使用 Grok + Dot 的真实账号，保留同一目标，另建可追踪的运行记录。正常路径必须由真实成员完成；失败或未达标场景可以人为设置受控条件，但要写明注入条件，不能用模拟回复冒充真实返回。

| 场景 | 必须看到的结果 | 对应证据 |
|---|---|---|
| 正常 | 两位领取并提交 → 汇总 → 自查 → 一份成果；计数逐条可点开 | 双平台任务/提交标识、Hub 步骤事件、最终文档版本、截图/录屏 |
| 来源冲突 | 定向补证一次，有据纠错或未确认；路线取舍出现决策卡 | 原论断、来源、补证任务与返回、决策原位和处理后计数 |
| 成员失败 | 收到 1/2，提供重试缺失成员、用已有结果成稿、终止；部分成稿明确缺口 | 受控失败条件、重试记录、剩余交付和部分标记；重复操作不重复任务 |
| 人工修改冲突 | 交回修改后继续改，候选不覆盖，三方对比后由用户应用 | 原稿/派发基准/当前人工稿/候选版本；提交时间与操作录屏 |
| 不达标 | 一条故意无法满足的标准 → 内部修订一次 → 部分达标且列缺口 | 真实成员自查与修订结果、次数、未达标项；不能只测字段非空 |
| 规则复用 | 人工改稿 → Agent 归纳 → 便签 → 用户确认 → 下一轮带入 | 修改差异、归纳任务、用户确认记录、下一轮规则版本快照；结果符合另需段落或程序校验 |

“成果可用”单独核对：最终稿覆盖用户目标和合格标准；重要论断有去向；不把不同偏好拼成矛盾的大杂烩；事实与未确认内容分开；没有内容证据的“都同意”不算协作价值。做不到的标准应诚实部分达标，不能靠更改标准把验收变绿。

## 5. 四类证据与状态不能混用

验收汇总只放在 #16，一行一个场景，记录方案条款、E 编号、构建/提交、运行/步骤/文档版本、预期、实际、证据链接、状态、复验者。截图和机器记录放现有 evidence 目录，不另开分散的过程文档。

| 证据类 | 能证明 | 不能替代 |
|---|---|---|
| 模拟交互 | 流程、异常控制与 UI 行为 | 真实平台接入 |
| 字段与确定性校验 | 权限、结构、版本、并发、计数和来源归一化规则 | 语义正确、事实独立或文稿可用 |
| 真实往返 | 授权、通知、领取、工具调用、完成与结果回收 | 成果满足目标 |
| 成果可用 | 真实目标、正文、来源和验收标准逐项核对 | 稳定性、隔离和异常恢复 |

统一状态：未验证 → 开发中 → 自测通过/待复验 → 复验通过；未通过记失败与复验步骤。平台条件不满足记明具体阻塞，保留证据。不能把 UI 25 项通过改写成 E0–E12 已完成。

## 6. 最后交付门槛

1. E0–E12 全部可逐项对账；六条真实主线有证据；四类证据分列。
2. 修复必须增加能重现该问题的检查，补测相邻状态（例如选择、撤回、刷新；复查期间继续编辑）。代码和证据使用同一构建，复验失败不删除历史记录。
3. 界面逐条对照定稿第 4 节和本轮审计，不只检查截图无溢出；点击后的结果、错误与恢复也要验证。
4. 按 AGENTS.md 在正式发布时运行 `verify:session` 和 `deliver:local`，核对实际桌面、服务与构建一致。不得为升级清空账号、换资料目录或强制重新登录；有运行任务先交接。
5. Claude 复核实现与证据，所有者确认视觉与操作体验。发现影响范围/定位的差异，先回 #16；不自行降级，也不把待复验称作完成。

不能承诺软件永远没有新问题；可执行的“不偏”保证是：固定条款、逐项对应、真实目标验收、失败留痕和独立复验，任一门槛不满足就不交付成“已完成”。

### 8.2 修复历史与剩余验收

- Grok 首次配置误收了剪贴板普通文本。已从官方复制完整签名密钥、通过掩码输入保存；新增前后端校验，不保留明文证据。
- Cloudflare 实际运行时不支持 `redirect:error`，请求未发出；已改为手动拒绝跳转。签名自动化必须返回202才计受理，普通200不计。
- 授权页 CSP 初次阻止官方回调。修正后补了真实 Chrome 表单、PKCE 和官方 MCP SDK 检查。
- 缺席恢复补齐执行中资源保护、跳过依赖、最终输入的缺失说明和部分标记；已暂停只停止接单，不再把有效凭证当作401失效。
- 安装启用先后发现活动 Chrome 动态写盘、旧进程归属和重复恢复问题。保留原进程与资料，不重新登录；最终以 activation.json 的当前结果为准，旧失败未改写成成功。
- Grok 采用账号级官方 Automations，Dot 采用官方 Work 事件会话。原平台工具仍由它们执行；**旧 Duola Bot 专属记忆/个性继承没有独立验证**。请 Claude 复核这一接入形态与定稿的符合程度，不能写成已完整继承。

剩余验收：Claude 对实现和证据独立复核；所有者确认正式 UI 与操作体验。不会据此声称永不掉线、永不出错或长期稳定性已被一次联测证明。

### 8.4 本轮发现的编辑器问题
