# 需求场景调研：一人公司与"大厂 Agent 组团"

- 日期：2026-10-26
- 你的判断：一是各家 Agent 能力不同；二是年初火过"一人公司"，以前是自己搭几个差不多的 Agent，现在可以把大厂做好的 Agent 接起来用。
- 这份文档回答：需求在哪里、哪些场景最适合、对产品有什么指导。数据来源见文末，标"自报"或"第三方"的只看方向。

---

## 一、需求有没有

### 1. 一人公司是真潮流，而且在国内有政策推动

- 复旦大学姚建华团队《2026 年中国一人公司（OPC）调研报告》：截至 2026 年 5 月，全国有 **426 个 OPC 社区**，覆盖 28 个省级行政区、65 个城市；20 个省份发布了 **106 项** OPC 专项政策。
- 工信部等七部门的行动方案首次明确提出培育"人工智能一人公司"（AIOPC）；上海浦东给新注册的 OPC 最高 30 万元免费算力，东莞滨海湾设立 3 亿元 AI 创业基金。
- 另有白皮书称 2025 年新设一人公司超过 730 万户，同比增长四成以上，但**存活率不到一成**（口径不统一，只看方向）。

### 2. 一人公司最大的痛点：一个人什么都得干

复旦报告列出的困难里，和我们直接相关的两条：
- **"技术没有替代经营能力"**：创业者仍然要同时当设计、销售、运营，有人说自己像"全能员工"，不像"老板"；
- **算力成本在上升**：有创业者说算力可能占总成本的八成以上。

海外数据（Forbes 引用的 Clarify Capital 调查，未见原文）：**63% 的 solo 创业者在用 AI，但只有 8% 能把 AI 用到从战略到日常运营的全流程。** 中间这段差距，就是"工具都有了，但串不起来"。

### 3. "管一支 Agent 团队"已经有人在做，说明需求是真的

| 产品 | 做什么 | 规模 | 和我们的区别 |
|---|---|---|---|
| **Paperclip** | 把多个 Agent 组织成一家"公司"：组织架构、任务单、**每个 Agent 的月度预算**、定时或被 @ 叫醒、审批、操作记录 | GitHub 约 10.7 万星（2026 年 3 月创建，直接查的）；开源、自己部署 | 接的是 Claude Code、Codex、OpenClaw、Hermes 这类**能被直接调用**的 Agent；没提 Dots、Muse 这类大厂个人 Agent；面向懂技术的人 |
| Sintra、Marblism、Lindy 等"AI 员工" | 自己搭好一套 Agent（社媒、邮件、客服、销售），卖给小企业 | 每月约 15～50 美元；没找到收入数据 | **就是你说的"以前的做法"**：用自己做的 Agent，能力不如大厂的，也接不到你自己的账号生态 |

### 4. 各家 Agent 确实不一样，而且最大的区别是"手里握着哪个生态"

评测文章的观点（不是实测数据，只看方向）：
- **Dots**：跨很多应用的综合型工作最强（连 4000 多个应用），但要 Pro 起步；
- **Muse**：日常琐事最好用；能用上你的 Instagram、Facebook、WhatsApp 信息（有隐私争议）；
- **Gemini Tasks**：生活和工作在 Google 里的人最顺手（Gmail、文档、日历）；
- **Grok Bot**：适合重复性工作和交接；能用 X 上的实时数据（来源较弱）。

国内：
- **腾讯 WorkBuddy**：官方连接器有 QQ 邮箱、腾讯乐享等；
- **豆包工作**：和飞书深度打通；
- **千问办公**：整合了企业 IM 能力。

**关键结论：各家的差别，与其说是"谁更聪明"，不如说是"谁手里握着哪个生态的账号和数据"。** X 的实时内容在 Grok 手里，Gmail 和 Google 文档在 Gemini 手里，Instagram、WhatsApp 在 Muse 手里，飞书在豆包手里，企业微信在 WorkBuddy 手里。**一件事只要跨了生态，就天然需要几家接力**，这就是我们的位置。

### 5. 没找到的

- **没找到用户直接抱怨"在几个 Agent 之间来回复制粘贴"的讨论**。找到的只有"多模型聚合"类产品（把同一个问题同时发给 ChatGPT、Claude、Gemini、Grok）。所以"用户觉得来回搬运很痛"目前是推断，要在验证阶段直接问用户。
- 没找到 Paperclip、Sintra 等的收入数据。

## 一点五、为什么是现在：和"自己搭数字员工"比

你的判断：以前做数字员工，要给每个 Agent 单独建设；现在大厂都建好了，背后还替你放了服务器，我们只是给它们换个身份、派活，这是跨代的方案。

**领先的地方（同意）：**

| 维度 | 以前：自己搭数字员工 | 现在：用大厂的个人 Agent |
|---|---|---|
| 能力 | 自己写提示词、接工具，能力取决于你搭得多好 | 大厂用最强的模型、花大量研发做好了，还在持续免费升级 |
| 服务器 | 自己部署、自己付算力 | 大厂给每个 Agent 一台云端电脑，一直在线（Dots、Gemini、Muse 都是这样） |
| 账号和生态 | 要一个个去申请接口授权，很多平台根本不给 | 天生连着自家生态：Gemini 连 Gmail，Muse 连 Instagram，Grok 连 X |
| 维护 | 平台一改接口就要修 | 大厂自己维护 |
| 我们的成本 | 算力是大头（复旦报告：有一人公司算力占成本八成以上） | 我们只做调度，服务器成本很低；算力由用户已经付的订阅承担 |

打个比方：以前是自己招人、自己培训；现在是从几家大公司借调已经培训好的专家，你只负责派活和验收。

**弱的地方（要正视）：**

| 维度 | 问题 | 产品上怎么应对 |
|---|---|---|
| **控制权** | 它们怎么想、怎么做，我们管不了；大厂随时改功能和规则（Spark 改名 Tasks、Gemini 写入要确认、Sora 直接关停） | 每个平台的限制写进配置，变了只改配置；不把核心价值押在某一家身上 |
| **速度和稳定** | 不能直接调用，只能叫醒、等它来领；可能慢、可能不照做 | 时间线记录每一步；超时提醒、重试、改派；只做不着急的任务 |
| ~~用户的花费~~ | **更正（你的反馈）：不是主要障碍。** Dots 包含在 ChatGPT 套餐里，不额外收费；Muse 送了一大批；加模型只是新功能 | 不作为主要顾虑 |
| **不知道怎么搭（最大的问题）** | 打开这些 Agent 不知道该让谁干什么、在哪里设置、怎么说它才照做。证据：龙虾代装被打到二三十元，但"装完帮你搭好怎么用"从 300 元涨到 1000 元（x-daily-drafts 报告） | 产品第一价值改成"帮你把团队搭起来"：首次使用向导、推荐分工、实测过的原话、连接测试（PRD 6.0） |
| **地区限制** | Gemini 自定义应用仅美国、Muse 只在少数国家、Dots 欧盟不可用 | 添加成员时如实提示；国内用户用国内的几家 |
| **护城河** | 我们只是一层"调度"，容易被抄；大厂也可能自己做互通 | 积累跨厂商的共享资料、好用的模板、顺畅的接入体验 |

**结论：** 在"能力、服务器、生态、维护、成本"上确实领先一代；但在"控制权、速度、用户花费"上比自建更弱。所以它最适合**已经在付费用多家 Agent、手上有固定重复活、不着急要结果**的人。这正是我们的第一批用户。

## 二、最适合的场景

判断标准：**跨生态**（必须几家接力，一家做不完）+ **重复发生**（值得设置一次反复用）+ **不着急**（能接受 1～3 小时）+ **一人公司常见**。

| # | 场景 | 谁在用 | 接力链（谁握着哪一段） | 证据强弱 |
|---|---|---|---|---|
| 1 | **每日内容包**（自媒体、个人品牌） | 内容创作型一人公司（复旦报告五类之一）；你自己 | Grok（X 热点）→ Perplexity 或 Dots（核实）→ Gemini（Google 文档写稿）→ Muse（Instagram、Threads 版本）→ 你发布 | **强**：你现在就在用 Grok 每天往 x-daily-drafts 仓库推内容，这是真实在跑的流程 |
| 2 | **线索跟进**（独立顾问、服务型一人公司） | 带着过往经验接单的人（复旦报告的"经验迁移型"） | Grok（X 上谁在问相关问题）→ Dots（查对方公司资料、记进 CRM）→ Gemini（在 Gmail 写跟进邮件草稿、在日历留时间）→ 你确认发出 | 中：Gojiberry 等证明"信号获客"有人付钱（见 Xduola 文档 18） |
| 3 | **周报 / 行业追踪** | 研究型、咨询型 | Perplexity（检索）→ Dots（核实数据）→ Gemini（写成文档）→ 你确认 | 中 |
| 4 | **小店客户消息处理**（传统生意升级） | 用 AI 做选品、客服、营销的小老板 | Muse（Instagram、WhatsApp 私信汇总）→ Dots（查 Shopify 订单）→ 回复草稿 → 你确认 | 弱：没找到具体案例；Muse 能不能稳定读私信未确认 |
| 5 | **国内办公 IM 之间搬运** | 同时服务多个客户、客户分别用飞书、企业微信、钉钉的人 | 豆包工作（飞书）↔ WorkBuddy（企业微信）↔ 千问办公 | 弱：都是电脑客户端，要电脑开着；没找到案例 |

**注意：** 小红书在 2026 年开始严打完全由 AI 托管的营销号。所以发布这一步一律留给人，工作台只出草稿。

## 三、对产品的指导

1. **定位改得更具体：** 从"多个 Agent 的工作台"改成 **"一人公司的 AI 团队：用你已经在付费的大厂 Agent，跨生态接力干活"**。
   - 对比"AI 员工"产品：我们不自己造 Agent，用的是更强、并且连着你自己账号的大厂 Agent；
   - 对比 Paperclip：我们接的是大厂的个人 Agent，不用自己部署，不需要懂技术。
2. **第一批用户：** 内容创作型一人公司（证据最强，你自己就是），其次是服务型（线索跟进）。
3. **模板按"跨生态的接力"来设计，** 不按"Agent 的能力"。每个模板写清楚每一步为什么交给这一家（因为它握着哪个生态）。第一版做场景 1，第二个做场景 2。
4. **从 Paperclip 借鉴三点：**
   - **每个成员的额度上限**（花到上限自动暂停，80% 时提醒）：解决"每次叫醒都消耗额度"的担心；
   - **被 @ 叫醒**：和我们的 Slack 叫醒思路一致；
   - **"你是董事会"**：关键动作要你批准，和我们的确认关卡一致。
5. **国内方向值得留着：** OPC 有政策推动，国内三家（豆包工作、WorkBuddy、千问办公）都能接自定义 MCP。限制是电脑要开着，但一人公司本来就整天坐在电脑前，影响不大。

## 四、验证（加进第 1～2 周）

| 要验证的 | 怎么验证 |
|---|---|
| 用户是不是真觉得"在几个 Agent 之间搬运"很痛 | 在 X 上问你的读者：同时用了几个 Agent、平时怎么让它们配合、最烦什么。目标：20 条以上有效回复 |
| 场景 1 的接力是不是比一家全做好 | 同一天各跑一次，比结果和用时（PRD 10.5 节） |
| 场景 2 有没有人要 | 找 3～5 个做服务型一人公司的读者，问他们怎么跟进线索 |
| 和 Paperclip 比，用户为什么选我们 | 问试用者是否用过 Paperclip、为什么没用或者为什么不够 |
