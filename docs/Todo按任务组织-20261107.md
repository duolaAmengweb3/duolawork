# Todo 按任务组织

用户 2026-11-07 批准：围绕要完成哪件事分任务，具体 Todo 放在任务下面，创建者负责归组，负责人维护整体结构。不是按人、日期或每次会议另建清单。

## 产品行为

- 保留「Todo」入口，默认按任务列出；一行说明任务名称、负责人和实际状态，展开显示具体 Todo、执行者、进度与卡点。
- 只用「任务 → Todo」两层；小事直接作为独立任务，不强制拆分。分组是一种组织方式，不增加新的执行队列或角色审批。
- 新建任务可直接命名；从任务里添加 Todo 自动带所属任务。编辑 Todo 可换所属任务或移为独立任务，原 ID、历史、执行者、接手记录、会议和资料引用保留。
- 搜索可以命中子项，仍显示它所属的任务。按进行中/已结束/全部筛选的是任务本身；完成子项不会自动隐藏仍待交付的任务。展开后保留完整子项，不因任务状态筛选漏项。
- 任务上的「2/3 项 Todo 完成」只表示子项记录；取消单独计数。全部结束但任务尚未关闭显示「待核对交付」，不自动宣称交付。负责人核对实际结果后单独结束任务。
- 关闭带 Todo 的任务要求子项均已结束；完成还需填写交付与验收结果。这只是防误关校验，不冒充独立审计。已结束任务需明确重新打开后才能添加或恢复未完成工作。
- 保留会议关联；一次会议可以推进多个任务，同一任务也可以经历多场会议。会议不代替任务归属。
- 秘书总览按任务计数，子项不重复算完成率；子项卡点能反映到所属任务。

## Agent 使用

1. `read_todo(channelId)` 查看任务，支持查询、状态和分页；`parentTaskId` 列指定任务的 Todo，`taskId` 读详情及归属。
2. `board_task(create)` 创建独立任务；具体 Todo 带 `parentTaskId`。创建者先复用已有任务，负责人整理重复和遗漏。没有明确跟进需要就不建。
3. `board_task(update, taskId, parentTaskId, expectedVersion)` 调整归属；空字符串变独立任务。不依赖标题前缀或语言来猜分组。
4. 原工具缓存兼容入口仍可调用新参数；无需用户重登录。整理归属不通知执行人、不重放旧任务；实际委派继续走已有通知机制。

## 旧数据与边界

旧待办无新字段时仍是独立任务。只在明确知道属于同一件事时搬到父任务，不批量猜测，不把历史完成项变成待办。跨群归组、自引用、多层嵌套和把含 Todo 的任务再塞进另一任务均拒绝。现有权限与幂等保留；创建者可仅整理自己创建的待办，不能据此改写其他执行人的进度。

## 实现与验证

复用 `channel_task`，新增 `parentTaskId`；`parentId` 为所属任务或群，现有范围和父节点索引可直接使用，无破坏性迁移。统计覆盖全部子项，列表分页不改变总数。添加/重开子项与关闭父任务通过同一父记录并发校验，不能留下已完成父任务和未完成子项的冲突组合。

专项后端覆盖：旧记录搬组与历史保持、只两层/跨群隔离、完成与重开约束、权限、旧工具兼容、105 子项跨页计数、并发关闭/添加，以及秘书不重复计数。浏览器真实界面覆盖：任务展开、新建继承归属、按子项搜索、移动、返回、刷新持久化、窄窗口与无页面错误。

交付运行证据在 `evidence/task-groups-release.json`；专项界面证据在 `evidence/task-groups-ui.json`。

## 同版单聊列表间距修复

原选择器 `.channel-list > button > span` 给头像外层和文字同时分配 `flex: 1`，导致头像占去一大块空白，状态点也偏离头像。改为只让 `.channel-copy` 文字栏伸展，头像固定宽度，状态点留在头像右下角，右侧保留未读数。窄屏只隐藏文字，头像继续可见。

实际 Chromium 测量：1440 与 920 像素窗口下头像宽 26px、头像至文字间隔 10px；580 像素窗口保持头像可见。来源：`evidence/sidebar-compact.json`。此为展示修复，不改变收件人、未读统计或 Agent 状态判断。
