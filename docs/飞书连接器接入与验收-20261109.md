# 飞书连接器接入与验收

本次只接入飞书。使用本机已经登录的官方 `lark-cli`，不重新注册应用，不复制访问令牌，不改其他项目的 CLI profile。接入依据是用户提供的 `/Users/duola/Desktop/atel/飞书文档使用说明.md`；实现参考 [官方 CLI](https://github.com/larksuite/cli)。

## 使用方式

在连接器页面点击“飞书”。只有一个已登录用户时直接连接；有多个时选择账号。连接卡片显示“飞书 · 账号名”，默认供全工作区成员和聊天使用，用户可以在管理中排除成员或群。重复连接同一 profile 和身份复用原记录。

群里直接给 Agent 飞书链接和修改要求即可。共享 `connector` 工具提供 `feishu_help`、`feishu_schema`、`feishu_call` 三个入口；它们调用官方业务命令，既可读取，也可按原授权创建、局部修改等，不是三项业务功能。复杂参数先查帮助和接口定义，修改原文前读取，修改后读回。原生平台缓存工具目录时仍使用既有共享 connector 入口，无需重建 Agent。

## 运行和身份边界

- 调用路径：任意获准成员 → DuolaWork VPS → 本机共享工具运行端 → 飞书官方 CLI → 飞书。当前运行端是这台 Mac，关机或断网后远端 Agent 也暂时不能调用；不冒充独立云端连接。
- 每条连接固定 CLI profile、应用和用户 ID，所有业务调用显式使用用户身份。每次调用前后核对身份；退出或换号不会静默借用其他账号。其他项目的 profile 和全局默认 profile 保留。
- 原始登录及续期仍由官方 CLI 管理。DuolaWork 私有描述文件只保存可执行路径和身份绑定，不存 OAuth 令牌；云端启动配置加密保存。
- CLI 登录、配置、凭证管理、插件安装和任意 HTTP 入口不对共享调用开放。共享调用传内联内容或飞书资源地址，不读取运行端本地文件。官方高风险确认不会被自动绕过。
- 缺少某项业务权限只让该次调用失败，保留其他已授权能力。错误保留官方错误类型、缺失权限和说明；原账号登录问题单独标记。超时或不确定的写操作不能盲目重试。
- 长结果在运行端完成事务中分块保存，调用记录和任务记录都不再把整篇大文档塞进单条数据库记录。重复请求只读原回执，不重做写操作；结果读取继续受成员和聊天权限校验。
- 更新验收结束时自动恢复原共享工具运行端，正常重启继续使用原运行端身份；重复恢复不另建运行端或替换其凭证。停止时等待正在处理的工具调用收尾。针对本次实测发现的“客户端更新后工具运行端未恢复”另有真实 HTTP、SQLite 和 stdio 隔离回归：`tests/connector-host-update.mjs`。
