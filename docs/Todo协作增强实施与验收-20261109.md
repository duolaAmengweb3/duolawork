# Todo 协作增强实施与验收

本项实现已批准的产品 v0.4 与技术 v0.2：在原有「任务 → Todo」中加入交付约定、实际成果提交、版本核对和可靠接续。没有新增用户工作台或固定轮次，原有自由聊天、原生账号/模型/工具继续保留。

## 实现

- 新建任务自动获得最小交付约定；原历史任务不补造核对记录。`board_task` 的 configure/submit/check 与旧 done 入口共用一个服务。
- 普通事项可一次 submit+selfCheck；指定核对人只能记核对，不能改写执行者成果。独立核对不能由本人或用户豁免冒充。
- 提交和核对不可原地改写，记录真实成员、工作约定、用户原话版本、原件与上游成果。改标题和进度不使检查失效；实际约定变化重开相关工作。后来编辑历史产物只标明需复核，不自动重做外部操作。
- 同一任务内的 Todo 可设前置依赖；循环、跨任务/跨群、带依赖的错误移动被拒绝。主任务单独核对最终成果，不能因子项结束或会议结束就误结案。
- 核对、任务状态、跟进记录与通知同事务保存。请求和业务指纹去重；退回后再次接受以新 check ID 通知，过期通知不能推进新版。
- 原用户要求及补充直接提供给执行者、核对者。核对者可以拒绝偏离目标的条件；关键纠正以实际产物为依据，不以“已采纳”话术作为落实证明。
- 沿用旧 MCP 已认证兼容信封；不要求重登录或重建会话。普通 submit_work 的聊天回传语义保持。
- Todo 原详情展示要求、当前成果、真实核对人和缺口。列表默认打开当前版，聊天历史引用固定原版；刷新详情保留阅读中的 DOM 和表单。
- 聊天回归发现的输入成员名 @ 未解析问题，一并接入现有同群名称解析；提示与真实收件人一致，引用和代码块内的名字不转通知。

## 验证与独立审计

- 最终全量 672 项通过；审计后补了重新接受通知、历史数据、独立任务跟进人及 JSON 字段换序重传的回归。
- 新增核心测试覆盖错误身份、过期条件、未知结果、并发修订、原件变化、依赖接续、旧目录信封、执行决定来源及旧数据兼容。
- 浏览器验收通过原话直达、同详情调整核对人、真实成员提交、用户实际核对、历史读取、脚本不执行与窄窗口布局。
- 原有聊天浏览器验收按当前消息进度和持久发件箱更新，14 项通过。乐观显示与服务端回执分别验证。
- DeepSeek 在原生环境独立复跑新增 12 项及连带 28 项。指出发布前需提交 SHA，以及重新接受时后项通知去重边界。后者已修复并新增回归；不将他的代码审计冒充上线或 UI 亲测。
