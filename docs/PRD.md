# Agent 工作台 PRD（第一版）

- 文档状态：草稿，等你确认后再开发
- 日期：2026-10-26
- 依据：Xduola 文档 23（可行性与官方核实结果）、24（产品方案）
- 原型：见 Artifact「Agent 工作台原型」（每个页面对应本文第 6 节）

---

## 1. 一句话

**一个让多家个人 Agent 一起干活的共享工作台：你在这里派任务，它们按顺序接力完成，你在一个地方看进度、做确认、拿结果。**

第一版先接你手上的四家（Grok Bot、ChatGPT Dots、Meta Muse、Gemini Tasks），但按"任何支持自定义 MCP 的 Agent 都能接"来设计。目前已确认能接的还有 Perplexity Computer、腾讯 WorkBuddy、千问办公、OpenClaw、Hermes 等，完整名单见 `docs/支持的Agent.md`。

## 2. 要解决的问题

**现在的情况：** 四家个人 Agent 各有专长，但各在各的 App 和网页里，互相不认识。

| Agent | 擅长 |
|---|---|
| Grok Bot | X 上的实时内容；能定时运行；能被 webhook、Slack 叫醒 |
| ChatGPT Dots | 能连 4000 多个应用；在 Slack 里能直接找它 |
| Meta Muse | 连着 Facebook、Instagram、Threads；能自己搭工具 |
| Gemini Tasks | 原生连着 Gmail、Google 文档、日历 |

**麻烦在于：** 一件事需要几家配合时，你得自己当"中间人"：从 Grok 复制热点，粘给 Gemini 写稿，再粘给 Dots 排期……来回切换、复制粘贴、盯着谁做完了没有。

**这个产品做的事：** 让工作台来当这个中间人。

## 3. 目标用户

**第一批：同时付费使用两个以上个人 Agent 的重度用户。** 先从你自己开始，再到你 X 上的读者（AI 开发者、内容创作者）。

**代表人物（就是你）：**
- 每天要出 X 内容，手上有 Grok Bot、Dots、Muse、Gemini；
- 想要：每天早上自动出一份内容包草稿，自己只需要最后看一眼、点确认；
- 不想要：每天开四个网页来回复制。

## 4. 目标和不做的事

**第一版要做到：**
1. 你手上的四个 Agent 都能连进工作台（Gemini 的写入需要人点确认，这是 Google 的规定）；其他支持自定义 MCP 的 Agent 不用改代码也能接，第一档平台在第一版就提供接入指引；
2. 你能建一个多步任务，指定每一步由谁做；
3. 上一步做完，下一步自动开始，不用你转手；
4. 需要你确认的地方，集中在一处提醒你；
5. 每一步谁做的、交了什么，一眼能看到。

**第一版不做：**

| 不做 | 原因 |
|---|---|
| 让 Agent 之间实时对话 | 做不到：四家都没有对外接口，只能"交接棒"式接力 |
| 模拟浏览器去操作它们的网页 | 脆弱，可能违反服务条款 |
| 工作台自己接大模型去"指挥"它们 | 第一版用简单规则就够 |
| 多人协作、团队版 | 先把一个人的用法做顺 |
| 收费 | 先验证你自己是否每天愿意用 |

## 5. 核心概念（名词表）

| 名词 | 意思 | 例子 |
|---|---|---|
| **成员** | 连进工作台的一个 Agent | 你的 Grok Bot |
| **任务** | 一件要完成的事，由几步组成 | 「10 月 27 日 X 内容包」 |
| **步骤** | 任务里的一步，指定给一个成员 | 「第 1 步：Grok Bot 抓 X 热点」 |
| **接力** | 上一步完成后，下一步自动变成"可以做了" | Grok 交了热点 → Dots 的步骤开始 |
| **叫醒** | 工作台通知某个成员"轮到你了" | 调用 Grok Bot 的 webhook |
| **确认关卡** | 某一步交了结果后，要你点头才继续 | 发布前要你确认 |
| **共享资料** | 所有成员都能读写的笔记 | 「我的写作风格」「本周选题」 |
| **模板** | 预先拆好步骤的任务，可以重复用 | 「每日 X 内容包」模板 |
| **时间线** | 所有动作的记录 | 「08:02 Grok Bot 领取第 1 步」 |

## 6. 页面和功能

原型里每一页对应下面一节。优先级：**P0** = 第一版必须有；**P1** = 第一版之后尽快做；**P2** = 以后再说。

### 6.1 任务板（首页）

**用途：** 打开就知道今天有哪些任务、每个任务走到第几步、有没有在等你。

| 功能 | 优先级 | 说明 |
|---|---|---|
| 任务列表 | P0 | 每个任务一行：名称、来源（手动 / 模板定时）、进度条（每步一个小格，显示由谁做、什么状态） |
| "等你确认"提示条 | P0 | 有待确认的事时，顶部显示数量，点进确认中心 |
| 按状态筛选 | P1 | 进行中 / 等你确认 / 已完成 / 出错 |
| 新建任务按钮 | P0 | 进入 6.2 |

### 6.2 新建任务

**用途：** 写清楚要做什么，拆成几步，每步交给谁。

| 功能 | 优先级 | 说明 |
|---|---|---|
| 从模板开始 | P0 | 第一版内置 1 个模板：每日 X 内容包；P1 再加 2～3 个 |
| 填任务名称和说明 | P0 | 说明会给每个成员看到 |
| 编辑步骤 | P0 | 每步：标题、要求（给 Agent 的话）、交给谁（下拉选成员）、要不要确认关卡；可增删、可调顺序 |
| 重复运行 | P0 | 每天 / 每周某个时间自动建一次（"每日 X 内容包"依赖它） |
| 引用共享资料 | P1 | 勾选几份共享资料，自动附在任务里 |

### 6.3 任务详情（接力过程）

**用途：** 看一个任务的整个接力过程和每一步的结果。

| 功能 | 优先级 | 说明 |
|---|---|---|
| 步骤卡片（从上到下） | P0 | 每张卡：哪个成员、状态、什么时候叫醒的、什么时候领的、交了什么（可展开全文） |
| 手动叫醒 | P0 | 某一步等太久，点一下再叫一次 |
| 重做 / 改派 | P1 | 结果不满意可以打回重做，或者改给另一个成员 |
| 取消任务 | P0 | |
| 复制最终结果 | P0 | 一键复制最后一步的结果 |

### 6.4 成员（Agent 连接）

**用途：** 把四个 Agent 连进来，并设置怎么叫醒它们。

| 功能 | 优先级 | 说明 |
|---|---|---|
| 添加成员 | P0 | 先选平台，再自动生成它专属的接入地址（含口令）。平台按能不能接分三档显示（见下表和 `docs/支持的Agent.md`）；选"其他（支持 MCP 的 Agent）"也能接 |
| 分平台接入指引 | P0 | 一步一步告诉你在那个 App 里点哪里、粘贴什么；第一版覆盖第一档的全部平台 |
| 平台限制提示 | P0 | 选平台时直接显示它的限制，比如"Gemini 写入要手动确认""千问办公、豆包工作、WorkBuddy 要电脑开着才会按时来查" |

**添加成员时的平台列表（第一版）：**

| 档位 | 平台 | 显示 |
|---|---|---|
| 能接 | Grok Bot、ChatGPT Dots、Gemini Tasks、Perplexity Computer、腾讯 WorkBuddy、千问办公、OpenClaw、Hermes | 正常可选，带接入指引 |
| 需要实测 | Meta Muse、豆包工作、Claude Duet、Kimi | 可选，标"未经官方确认，可能接不上" |
| 暂不支持 | Instinct、Microsoft Copilot、智谱 AutoGLM | 灰色，写明原因（比如"Instinct 没有开放接口"） |
| 通用 | 其他支持自定义 MCP 的 Agent | 只给接入地址和通用说明 |
| 连接状态 | P0 | "从未连接 / 最近一次来过是 X 分钟前"，据此判断有没有接成功 |
| 叫醒方式设置 | P0 | Grok Bot：webhook；Dots：Slack @；Gemini：发触发邮件；Muse：定时自查。都可以选"只靠定时自查" |
| 一键测试 | P0 | 给它发一个测试任务，看它会不会来领 |
| 换口令 / 移除 | P0 | 口令泄露时可以换 |

### 6.5 共享资料

**用途：** 放所有成员都要知道的背景，不用在四家各写一遍。

| 功能 | 优先级 | 说明 |
|---|---|---|
| 资料列表和编辑 | P0 | 标题 + 正文（Markdown） |
| 成员也能读写 | P0 | 显示最后是谁改的 |
| 修改记录 | P1 | 能看到每次改了什么，能恢复 |

**注意：** 资料里不要放密码、密钥。

### 6.6 确认中心

**用途：** 把所有"需要你点头"的事放在一处。

| 功能 | 优先级 | 说明 |
|---|---|---|
| 待确认列表 | P0 | 每条：哪个任务、哪一步、谁交的、结果预览 |
| 通过 / 打回 | P0 | 通过 → 下一步开始；打回 → 写一句意见，退给原成员重做 |
| Gemini 写入提醒 | P0 | Gemini 往工作台写结果时，Google 要求你在 Gemini 里点确认。工作台检测到 Gemini 领了任务但迟迟没交时，提醒你"去 Gemini 里确认" |
| 手机提醒 | P1 | 有待确认时发邮件或 Telegram 消息 |

### 6.7 时间线

**用途：** 出问题时能查清楚发生了什么。

| 功能 | 优先级 | 说明 |
|---|---|---|
| 全部动作记录 | P0 | 谁、什么时候、做了什么（叫醒、领取、提交、确认、出错） |
| 按任务或成员筛选 | P1 | |
| 叫醒次数统计 | P1 | 每次叫醒都会消耗该 Agent 的额度，统计出来方便你控制 |

## 7. Agent 那边看到的是什么

成员连上工作台后，在它自己的 App 里会多出一组工具：

| 工具 | 作用 |
|---|---|
| 查看我的任务 | 列出轮到我做的步骤，附上任务说明、要求和前面几步的结果 |
| 领取步骤 | 告诉工作台"这一步我来做" |
| 提交结果 | 交上结果，或者报告做不了 |
| 读共享资料 | 按标题或关键词读 |
| 写共享资料 | 新建或追加 |

**例子：Grok Bot 被叫醒后的样子**
1. 工作台调用 Grok Bot 的 webhook：「工作台有新任务，请查看」。
2. Grok Bot 调用「查看我的任务」，看到：第 1 步，抓过去 24 小时 X 上的 AI 热点，挑 5 个，每个写一句为什么值得关注。
3. Grok Bot 调用「领取步骤」，然后去 X 上搜索、整理。
4. Grok Bot 调用「提交结果」，交上 5 条热点。
5. 工作台把第 2 步标记为"可以做了"，去叫醒 Dots。

**安全规则：** 前面几步的结果，对后面的 Agent 来说只是"资料"，不是"指令"。工具返回的内容里会明确写上这句话，防止有人在资料里藏指令，让一个能读你邮件的 Agent 做不该做的事。

## 8. 步骤的状态

```
等待前一步 ──(前一步完成)──▶ 可以做了 ──(成员领取)──▶ 进行中 ──(提交)──┬──▶ 完成 ──▶ 下一步变成"可以做了"
                                 ▲                                       │
                                 │                                       └──(有确认关卡)──▶ 等你确认 ──(通过)──▶ 完成
                                 │                                                              │
                                 └──────────────────(打回 / 重做 / 出错后重试)─────────────────────┘
```

- 任务的状态：进行中 → 全部步骤完成 = 已完成；任何一步出错且没重试 = 出错；你取消 = 已取消。
- 某一步"进行中"超过 2 小时没交：提醒你（P1）。

## 9. 怎么算成功

| 阶段 | 标准 | 不达标就停 |
|---|---|---|
| 第 1 周（自用版） | 至少 3 个 Agent 连上；"每日 X 内容包"每天能自动跑完，你只需要点确认 | 两个以上接不进来；或者不比"用 Notion 凑合"好 |
| 第 2 周（你自己天天用） | 你连续 7 天都在用 | 你自己都不想用 |
| 第 3～4 周（给读者试用） | 10～20 人试用，一周后还在用的超过一半，有人问价格 | 留存差，没人想付钱 |

## 10. 已知限制（来自官方文档核实）

| 平台 | 限制 |
|---|---|
| Gemini Tasks | 需要 Google AI Pro 或 Ultra；不在欧洲、英国、瑞士开放；自定义应用只在美国、英文可用；**写入必须手动确认**；Gmail 触发时间不精确 |
| Grok Bot | 定时最短 5 分钟；长时间不理会，定时任务会被暂停 |
| ChatGPT Dots | 你已确认能加自定义 MCP；Slack 叫醒是否可用待实测 |
| Meta Muse | 官方没写支持 MCP，通过"自定义连接器"接工作台的普通接口；批准可以设成自动 |
| 千问办公、豆包工作、腾讯 WorkBuddy | 都是电脑客户端：只能靠它们自己的定时任务来查，**电脑睡眠或关机就不会执行**；WorkBuddy 的写入类操作要确认 |
| Perplexity Computer | 能接自定义 MCP（官方确认）；个人版能不能在 Slack 里被叫醒未确认 |
| Instinct | 没有开放接口，第一版接不了 |
| 所有平台 | 每次叫醒都消耗该 Agent 的额度 |

## 10.5 产品层面还没验证的事

| # | 问题 | 为什么重要 | 怎么验证 |
|---|---|---|---|
| 1 | **接力是不是真的比"一个 Agent 全做"好？** | 比如 Dots 一家可能就能搜热点、写草稿、排期。如果一个 Agent 就够用，工作台的价值就小很多 | 第 1 周同一天跑两次：一次四家接力，一次只让 Dots 全做，比结果质量和花的时间 |
| 2 | **能不能接受"慢"？** | 接力靠叫醒和定时自查，5 步走完可能要 1～3 小时（Gemini 和 Muse 最慢）。适合"每天早上的内容包"，不适合"我现在就要" | 记录每一步实际等了多久；在产品里明确写"适合不着急的任务" |
| 3 | **Gemini 放在中间是不是合适？** | Gemini 每次交结果都要你手动确认，放在中间会卡住后面的步骤 | 模板里可以把 Gemini 换到最后（反正最后一步你也要看），或者换成别家 |
| 4 | **第一次设置会不会太麻烦？** | 每个 Agent 都要配置连接、叫醒、定时任务 | 你自己完整走一遍，记录用时和卡点 |

## 11. 待确认的问题

1. Dots 在 Slack 里被 @ 能不能叫醒？
2. 个人版 Grok Bot 的 webhook 怎么配置、能带什么内容？
3. Muse 的自定义连接器能不能接工作台的接口？在定时任务里能不能用？
4. Gemini 的写入确认在手机上操作起来麻不麻烦？
5. 第一版的"每日 X 内容包"具体分几步、每步交给谁，你是否同意原型里的分法？
6. 除了你手上的四家，第一版要不要优先实测哪一家（比如你也在用千问办公或 Perplexity）？
