## 路线固定

- 用户选 Agent、点击连接；软件处理安装、配置、接收、会话续接与回传。已有登录能复用就复用；平台确实要求本人登录或授权时，在连接流程内完成一次。
- Coding Agent 走官方原生运行接口：Codex App Server；Gemini / Antigravity 走官方 ACP 适配。保留原 Agent 的订阅、模型和工具，不改成模型 API，不操作现有 IDE 窗口充当默认接法。
- Personal Agent 使用已经验证的原生唤醒接口。Grok 的 Routine＋Hub 工具接法继续保留，不因为新增 Coding Agent 重做。
- 自由沟通、单聊、群聊和 Agent 相互 @ 是底层。文档、事项、会议是可选工具，接入不预设岗位、分工或工作流程。

## 官方 DeepSeek 桌面接入（当前默认）

“成员与连接 → 添加成员 → DeepSeek Harness → 继续连接”，选择你正在工作的原生会话，或新建独立助手。沿用官方桌面版现有登录、模型、工具和项目，无需 B.ai Key、命令行或另一份 Web 运行端。本机 macOS 官方 `0.2.1-rc.5` 已完成真实桌面联测；其他版本明确显示未验证，不暗中降级。原有 B.ai / Web 成员保持原连接，不自动迁移。

具体证据、重开与解除连接验收见 [03 的官方桌面章节](03-实现状态与验收记录.md#官方桌面版接入补齐)。下文此前 Web + B.ai 的交付记录保留，不能用来替代官方桌面证据。

## 维护规则

1. 做新平台先查本目录和既有研究，直接复用已确认内容；仅补查版本变化、缺失参数或实测暴露的问题。
2. 方案仍在这里改，记录“原结论、实际新证据、影响范围”，不另建相互冲突的方案。
3. 没通过的测试明确写失败原因、原始证据和下一项修复，不把授权、HTTP 200 或 CLI 输出当成完整可用。
4. 不因失败偷偷切到另一个通道、更换模型、重建账号或清除登录。
5. 验收记录更新后，再更新旧的《支持的Agent.md》摘要；历史调研不覆盖当前路线。
