## 连接、成员、工作会话（11月4日更新）

1. **连接运行端**：复用原账号、订阅、模型与工具，不要求先选择项目或会话，也不因此执行模型任务。
2. **添加工作成员**：同一个 Codex 账号连接可以添加多位成员，例如“Codex · 网站”和“Codex · App”。身份与授权分别保存，可以同时加入同一个群；不共享一个全局凭证文件。
3. **在聊天里选工作会话**：单聊或群聊的输入框上方显示各 Coding 成员的会话入口。每个聊天自行选择已有会话或新建；只有用户明确选了同一个原生会话，才共用其上下文。
4. **保留旧绑定**：更新时把已有聊天映射到原来的精确会话，不改账号、登录、历史和项目。后来新建的聊天不自动继承旧的全局会话。

| 接入 | 在聊天选会话 | Hub 内新建 | 同账号多工作成员 |
|---|---|---|---|
| Codex | 已连接的本机原生运行端中已打开的会话，以及本成员的 Hub 工作会话 | 支持官方 App Server 原生会话，可指定本地项目目录 | 支持，独立身份并发；同一个原生会话不同时绑定两位成员 |
| Antigravity 官方桌面 2.28.0 | 支持选准确原会话 | 当前不提供；先在官方桌面新建后选择 | 支持；各工作成员选择不同原会话 |
| Gemini 原 ACP 后台连接 | 保留，可选本成员已有后台会话 | 支持独立原生会话；不会继承桌面上下文 | 每位原成员保持自己的后台环境 |
| DeepSeek Harness 官方桌面 0.2.1-rc.5 | 支持 | 支持在同一官方 Host 新建，可指定本地项目 | 支持 |
| Grok Bot / Dot | 保留原 Bot / Agent 固定身份，不加虚假的会话选择 | 在原平台创建另一位 Bot / Agent 后单独接入 | 支持多位原生 Bot / Agent，不是把一个 Bot 伪装成多份 |
| Claude Code · VPS | 官方 MCP Channels 远端连接器；由用户在 VPS 加载 | 已接入原会话可选；新建在 VPS 完成 | 协议链路测试通过，真实订阅待用户配合；[操作步骤](Claude-远端连接器与操作步骤.md) |
| 其他候选 | 未纳入本轮新增会话入口 | 不展示未验证能力 | 保留研究状态 |

“运行端已连接”仅表示原生接收环境可用；首次绑定工作会话后仍会做真实往返验证。接入和具体会话验证不混称。原生 App 关闭、原平台过期或权限要求不冒充成功。

## 路线固定

- 用户选 Agent、点击连接；软件处理安装、配置、接收、会话续接与回传。已有登录能复用就复用；平台确实要求本人登录或授权时，在连接流程内完成一次。
- Coding Agent 走官方原生运行接口：Codex App Server；Antigravity 官方桌面原会话走 Sidecar + agentapi，原有独立后台助手保留官方 ACP 适配。保留原 Agent 的订阅、模型和工具，不改成模型 API，不操作现有 IDE 窗口充当默认接法。
- Personal Agent 使用已经验证的原生唤醒接口。Grok 的 Routine＋Hub 工具接法继续保留，不因为新增 Coding Agent 重做。
- 自由沟通、单聊、群聊和 Agent 相互 @ 是底层。文档、事项、会议是可选工具，接入不预设岗位、分工或工作流程。

## 官方 DeepSeek 桌面接入（当前默认）

“成员与连接 → 添加成员 → DeepSeek Harness → 连接运行端”；进入单聊或群聊后再选择原生工作会话或新建。沿用官方桌面版现有登录、模型、工具和项目，无需 B.ai Key、命令行或另一份 Web 运行端。本机 macOS 官方 `0.2.1-rc.5` 已完成真实桌面联测；其他版本明确显示未验证，不暗中降级。原有 B.ai / Web 成员保持原连接，不自动迁移。

具体证据、重开与解除连接验收见 [03 的官方桌面章节](03-实现状态与验收记录.md#官方桌面版接入补齐)。下文此前 Web + B.ai 的交付记录保留，不能用来替代官方桌面证据。

## Antigravity 官方桌面原会话（当前默认）

新成员选 Gemini / Antigravity 后先连接运行端，再在具体聊天里选择准确的原工作会话。已有 Gemini 后台成员在“查看接入”点击“连接桌面原会话”，选中后再切换。软件保留原登录、模型、项目和上下文，处理验证、工具和接收；用户不用查端口、会话 ID 或复制令牌。当前已验证 macOS 官方桌面 App 2.28.0，VSCode 扩展不混称已支持。

默认不打断原工作：忙碌时先排队，原轮结束后处理 Hub 消息。原桌面需保持运行，可最小化。原 ACP 后台会话和登录保留为可选独立助手，切换时只启用一个接收端；不会用旧接收端的成功回执冒充原会话已验证。

## 当前结果

原会话协作与独立助手分开。DeepSeek 官方桌面和 Antigravity 官方桌面已有正式会话选择入口；Codex 原运行端已打开会话的选择入口已实现，并完成同一 daemon 的真实往返；原 VSCode GUI 证据单列，不把所有旧版本和所有 GUI 都说成已验。Claude 远端连接器已实现；本机与 VPS 实例均未操作，最终订阅往返由用户配合验收。

- Grok / Dot：保留已验证的原生唤醒、普通聊天和跨成员协作。
- Codex：保留官方 App Server 后台会话，并在聊天会话选择器中列出原运行端中已打开的会话；通过官方 queue 唤醒原会话，不在新 App Server 偷偷 resume 原 GUI 会话。
- Antigravity：官方桌面 2.28.0 的准确原会话、实际文件/终端工具、上下文和忙碌排队已真实联测；旧 ACP 1.4.5 连接保留。
- DeepSeek Harness：官方桌面 0.2.1-rc.5 原会话和新建助手均已交付，原 npm / B.ai 成员不迁移。
- 新原会话必须亲自完成本次验证才显示可聊天。原项目的权限、模型和插件配置不因 Hub 接入被全局修改。
- 当前安装构建以 evidence/activation.json 为准。真实场景、原始失败、回归及未覆盖项见 [03](03-实现状态与验收记录.md)。

## 维护规则

1. 做新平台先查本目录和既有研究，直接复用已确认内容；仅补查版本变化、缺失参数或实测暴露的问题。
2. 方案仍在这里改，记录“原结论、实际新证据、影响范围”，不另建相互冲突的方案。
3. 没通过的测试明确写失败原因、原始证据和下一项修复，不把授权、HTTP 200 或 CLI 输出当成完整可用。
4. 不因失败偷偷切到另一个通道、更换模型、重建账号或清除登录。
5. 验收记录更新后，再更新旧的《支持的Agent.md》摘要；历史调研不覆盖当前路线。
