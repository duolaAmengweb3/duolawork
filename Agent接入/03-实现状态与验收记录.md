### 修复的实际原因

1. 界面使用当前绑定项目作为初始页面，导致原生项目存在却像是只能选 Hub 历史。
2. Codex 只读取 loaded 会话，遗漏历史；已改成官方 thread/list 与 project/list 分页，并补充实时未落库会话。只读元数据，不扫描其他会话正文。
3. Antigravity 版本检查仍停在 2.28，升级后的 2.29 不可用；连接器包还遗漏了 shared-file-client 依赖。修复兼容检查和两家插件打包，并加入独立目录导入测试。
4. Codex 的 queue 接受不等于开始执行。现在使用原 daemon 的官方 queue/add、queue/list、queue/start；等待原工作完成，不插队、不打断、不另开替代会话。
5. Codex 原生权限确认没有进入 Hub 的处理链路。现在仅处理 threadId、turnId 和本次 Hub 工作标识同时匹配的请求，沿用 Hub 已选权限；普通原生工作和其他线程的请求不处理，也不修改提供方全局权限。
6. DeepSeek 实际仍运行旧插件。已在空闲时正常重开并核对全部原会话 ID，原登录保留，新插件当前已生效。
