### 简约交互

- 同一个“选择对话”窗口，三个清楚的入口；不增加连接类型、运行协议、会话 ID 等配置表单。
- 配对页只展示“把这段说明发给你要连接的 Agent”、复制按钮和当前进度。说明同时带服务器地址与配对码，用户不用自行补参数。
- 成功后自动显示“已关联：项目名 · 对话名”。以后在群里显示当前对话、联系状态和“更换”，不用每次重新选或配对；离线保留原关联，原 Agent 一侧也能查询关联到哪些群。
- 本地和远端使用同一交互意图，具体平台只有完成适配和真实往返才开放，不能用统一文案冒充通用支持。Grok / Dot 继续原固定 Agent 身份，不硬套 Coding 会话入口。

### 保存与继续是完成条件

- 配对码必须绑定当前工作区、成员、聊天和一次明确连接意图，短时、一次使用；不是把现有账号配对码直接换个名称。
- 可信的原生适配负责确定实际运行环境和原会话标识，不能仅凭模型自报一个会话名称就显示成功。
- 原生环境、项目和会话绑定持久保存；程序更新、正常重启后自动恢复同一段对话，不默认创建替代会话，不按“最近一段”猜测。
- 本机 / 远端 Agent 仍只在自己的环境干活；配对不复制项目、不暴露用户另一台机器的文件系统。
- 实际验收必须覆盖：当前正在工作的原会话接入、真实消息往返、上下文保留、重启续接、重复粘贴不生成重复成员/会话、断线不丢绑定、错误配对不覆盖其他聊天。

> 当前“新建对话”语义：群聊名只是 Hub 对话标题。选择已有项目会传入原项目目录；未选择时为该 Coding 成员与聊天创建持久文件夹（不在系统临时目录，不自动初始化 Git/框架）。建群本身不创建文件夹，Grok/Dot 也不需此项。目录存在不等于已在桌面 IDE 注册完整项目；后台 ACP 和桌面原会话必须分别表述。2026-11-04 已实测 Gemini ACP 在该持久目录写入并读回测试文件，但未据此宣称桌面全部功能可用。

> 2026-11-04 晚更新：Coding 账号的聊天入口统一先选项目、再选对话。原生自定义项目名与文件夹名分开标注，不能虚构项目名；已有会话标题优先使用原生 name/customTitle/summary。DeepSeek 通过官方 workspaceRegistry，Codex 通过 thread/read，Antigravity 通过 Sidecar 元数据，Claude 通过原环境 SDK 的 getSessionInfo。后台助手与桌面原会话不可混称。当前实际加载与验收状态见 03 文档最新节。

## 1. 用户只做什么

在“成员与连接”选择 Agent，填写备注，点击连接。Hub 检测本机环境，必要时自动安装官方运行组件；需要本人操作时显示官方登录/授权按钮。完成后自动配置和真实验证，显示“已接入，可以聊天”。用户不用填命令、MCP 地址、令牌、轮询周期或调试参数。

Codex、Gemini 已按此流程实现并安装，实测范围见[验收记录](03-实现状态与验收记录.md)，不意味着下面所有目标平台均已支持。Grok 本人专属 URL/密钥属于已经确认的原平台限制，保留同页的一次安全交接；不能虚构已经实现自动读取。

## 3. Hub 负责的工程

- 运行组件：版本、下载进度、官方来源和哈希校验；安装目录独立于账号资料；安装失败保留旧版本。
- 认证：官方认证流程、状态检查和错误提示。提供方凭证留在原生存储或独立受保护资料中；不进聊天、前端持久存储、Git、安装包或测试证据。
- 连接：成员身份绑定与短时配对由本机服务完成；成员工具权限独立，不向 Agent 发管理员凭证。
- 接收：空闲只做轻量信号检查，不调用模型；有消息才唤醒对应原生 Agent。关闭 Hub／电脑时本机接收暂停，重开恢复。
- 会话：按成员与群/单聊保存原生会话 ID；不使用全局“最近一次”会话；同品牌多个成员独立运行，不覆盖彼此配置。
- 工具：原 Agent 的文件、终端、技能等继续存在；Hub 提供消息、文档、事项、会议等协作工具。Hub 专用原生会话默认完整授权，不逐项确认文件、终端、联网或协作工具；可在成员连接页选择“操作时确认”。原日常 IDE 的全局权限不变；平台要求本人登录授权不能伪造。
- 回传：必须由真实成员身份调用 Hub 工具，并匹配实际消息/工作；普通 CLI 输出或开发者代写不算原 Agent 回群。
- 恢复：持久记录执行中的状态，先核对原回执和会话再恢复；无法确认的副作用不盲目重发。
- 更新：有工作时不强行重启；账号、登录、原生会话与工作区不跟程序包一起删除。解除连接只撤销该成员的 Hub 权限，保留原平台登录和历史。

## 4. 接入与产品状态

流程统一为：准备连接 → 必要的本人操作 → 自动验证 → 可以使用。失败时在同一个连接页说明具体原因并给出恢复动作，不让用户重新跑整套配置。

“已接入”依据真实往返；后台暂停、等待登录、等待批准、网络暂不可用各自显示，历史 verified 不能掩盖当前执行端已经离线。

### DSH 正式接入与生命周期

- 用户在正常成员页选 DeepSeek Harness。已有本机 B.ai 配置自动复用；新用户第一次填入 API Key，存到仓库外 0600 文件，不返给前端、不发到群聊。
- 运行端采用独立固定版本的官方 npm 安装，缺失时在后台安装；模型、原生会话、成员授权与程序包分开。安装或准备耗时长时异步报告进度，不让一次 HTTP 请求挂到超时。
- 用户可选“加入已有工作会话”：按真实原生列表显示名称、项目及忙碌状态，选中准确会话；不会根据目录猜最近会话，也不复制替代。
- 用户可选“新建独立助手”：只为该成员创建一个原生会话和独立工作目录。创建结果未确认时不盲目再创建，回到已有列表选择实际会话。
- 原会话中热注册成员专属 Hub 工具。空闲只读轻量 signal；有消息才由原生 queue 排队唤醒，由 Agent 亲自领取与回传。验证成功以前不显示可以聊天。
- Hub 重开读取原绑定和授权；关闭 Hub 不杀掉用户原生 Agent。Host 需要升级时只在全部原会话空闲且进程归属明确时正常重启，保留原生 home 和网页端口。恢复绑定和工具完成前不显示 ready；并行连接同一会话只注册一次。
- 解除连接撤销该成员 Hub 权限、解除工具绑定；不退出原模型账号、不关原 Agent、不删项目或历史。原生端离线时记录待解除，恢复后只补解除，不重新派发工作。
- 默认入口覆盖本机由 Hub 安装并启用插件的 DSH Host；其他自行运行且未启用插件的 Host、远端 VPS DSH、其他版本仍需单独适配，不冒充已覆盖。

## 用户确认的权限默认值（2026-11-03 追加）

用户明确要求默认全部开放，后续有需要再管理。因而 Coding 接入默认采用原生会话的完整授权模式，不再把每次工具批准作为接入步骤。工程路线和协作功能不变；这是用户明确变更，不是另起方案。


## DSH 官方桌面版：默认接入与维护

本节取代上文对“新增 DSH 成员默认部署 Web + B.ai”的描述。历史 Web 成员不变，不把它们切换到用户桌面账号。

1. 检测官方桌面 App 和它自己的 Desktop Host，通过公开版本与进程参数定位准确 profile。不读取、复制或改写 DeepSeek 登录。当前兼容 macOS `0.2.1-rc.5`。
2. 通过官方 profile 插件热加载机制，仅添加 Hub 自己的节点；修改前备份，保留其他节点、注释、模型和权限设置。无需另起 Host 或重装官方 App。
3. 列出原生会话的标题、项目与运行状态，由用户选择准确会话。忙碌时排队，不猜最近会话、不 fork，不以新 Agent 读目录冒充原 Agent。
4. 只给这个会话注册获授权的 Hub 工具。原 Host 沿用原模型、文件及终端工具；真实验证回传后才显示“已接入”。
5. 新建助手也在官方 Desktop Host 创建独立会话和工作目录。成员身份、授权和上下文独立，同一会话不能绑定为两位成员。
6. Hub 重开不退出官方软件；官方软件重开后恢复准确绑定。关闭官方软件时显示离线，不另起 Web 版替代。原软件打开后自动续接，不承诺平台撤销登录后永久免登录。
7. 解除连接只撤销 Hub 访问并移除该会话的 Hub 工具，原生会话、项目、历史与登录保留。

稳定资产位于 `~/.config/agent-hub/native-bridges/dsh-desktop/`：版本化插件、私有控制记录和 profile 备份。应用更新不删除它们；控制记录 0600，不进入 Git、群聊或安装包。本机控制端口不上公网。

实现：`local/dsh-desktop.mjs`、共用连接器 `local/dsh-connector.mjs`、`local/dsh-manager.mjs` 的 desktop / managed 路由。原项目权限不被全局放开；Hub 不承担 IDE 或模型提供方的职责。

验收：原 GUI 先开发 → Hub 桌面成员页连接 → 原 Agent 领取、执行、回单聊 → 原 GUI 继续开发 → 双成员 @ 与独立目录读写 → 两个软件完整退出重开 → 解除连接保留原工作。证据见 [03](03-实现状态与验收记录.md#官方桌面版接入补齐)。


## Antigravity 原桌面会话：正式工程与生命周期

用户选择准确的原会话；原 App 用官方 Sidecar 管理后台桥接，agentapi 将消息发入该 conversationId，不另开会话、不恢复成另一个执行者。元数据通过官方运行端的本地接口读取，仅包含标题、工作目录和运行状态。原生鉴权仅由 Sidecar 继承，在内存中使用，不导出、复制或保存提供方登录。

- 稳定组件：local/antigravity-host.mjs 管理唯一自有 Sidecar 和版本化资产；local/antigravity-sidecar.mjs 在原 App 中运行；local/antigravity-tools.mjs 给原 Agent 提供完整 Hub 工具。工具凭证留在私有文件，不放进原对话。
- 接收：空闲只读信号。有 Hub 工作且原会话 idle 才发送；busy/running/canceling/未知状态均等待。原工作正在执行时，不用 steer、不取消、不发送另一轮去抢占；用户可在原 App 自己决定打断。
- 执行：原 Agent 用原来的模型、规则、文件和终端工具工作；通过本成员的真实 list/claim/reply/submit 回 Hub。claim_step 只合并一次 list_work 核对与 claim_work 领取，减少模型往返；不会代 Agent 编造内容。完整文档、事项、会议等工具仍可列出并调用。
- 切换：旧 ACP 连接不自动迁移。用户选定原会话后，先确认旧接收端空闲再暂停它；保留原登录、会话和配置。同一成员禁止同时恢复两种接收端。新绑定记录自己的验证 runId，只有该 run 的真实回执才能点亮就绪。
- 重开：Hub 原地续接同一 ID；自有 Sidecar 重启也从私有记录恢复。升级只替换自己的版本化组件，原 App 和原 Agent 不被终止。发送结果不确定时不自动重放副作用，保留原工作并显示待核对。
- 断开：撤销本成员 Hub 访问，删除本会话绑定；原 App、会话、项目、登录不退出。
- 版本：本轮验证 macOS 官方 App 2.28.0；其他版本不悄悄降级、不冒称支持，Sidecar 也不处理未验证版本的消息。

持久位置：~/.config/agent-hub/native-bridges/antigravity-desktop/（私有控制记录、组件、配置备份），~/.config/agent-hub/antigravity-desktop-members.json（准确成员绑定），原 App 的 ~/.gemini/config/sidecars/duola-agent-hub/（仅自有清单）。原 App config 只增改这一项 Sidecar，保留其他 Sidecar、插件和 userSettings。

官方依据：https://antigravity.google/docs/sidecars/ 。具体已验收范围、失败与实测数据见 [03](03-实现状态与验收记录.md)。


## 11月4日：连接与聊天工作上下文分离（覆盖此前在成员页固定选会话的流程）

- 账号连接负责原生登录/运行端的可达性；Hub 工作成员负责独立身份、名称、授权。账号可复用，工作成员可有多位，不将同品牌锁成一个。
- `ChatSessions` 是统一会话入口；能力表按真实适配决定是否可选择、是否可新建。私有 `native-coding.json` / 桌面成员记录内的 `chatBindings[channelId]` 保存精确原生 sessionId、项目目录、标题和接法。授权仍按成员隔离，不将提供方凭证复制到 Hub。
- Codex 新会话用官方 App Server。已有原运行端会话只读元数据，在原 daemon 用官方 queue 入队，绝不将它转移到 Hub 的另一进程 resume；它继续使用原模型、工具与原权限。不能直接接收输入、未打开的旧会话不伪装为可唤醒。
- Antigravity Sidecar / DSH 插件按 channelIds 精确分流；验证工作只有一个明确接收会话。工具列表与领取同时核对当前会话范围，防止给 A 会话发送 B 聊天的工作。显式共用一个原生会话时保留共同上下文，仍逐条处理同一成员的工作。
- 后端资源锁对原生 Coding 独立成员按成员分开；Personal Agent 继续沿用原账号资源锁。旧执行占用时不重设资源锁或重复领取。
- 会话创建、绑定做并发去重和持久保存；不明创建/发送结果不自动重放。工作尚在执行、已发送未结束时不替换其工作上下文。断开只撤销 Hub 关联，不退出原账号、不停止原工作。
- 旧全局绑定迁移时只覆盖当时已有聊天；新聊天必须选会话。旧原生会话 ID、项目、登录和历史原样保留，未来新群不沿用全局默认。

验收必须覆盖：连接时不创建工作会话；同账号两位 Codex 同群真实回复；不同聊天使用不同上下文；明确复用；原生已有会话精确 queue；重载绑定不变；工作中不替换；跨聊天不能误领；Personal Agent 不出现无效会话按钮。真实模型、协议 fixture、界面和安装包证据分别记录在 03。

首次验证中的消息在云端保留为待处理，验证完成后进入原聊天处理，不要求人类再次发送。DSH 桌面生产模式不会因修改 YAML 自动重载：桌面关闭时先部署插件再打开；正在运行旧协议时，提示在工作结束后重开官方 App。原 profile、模型、项目、会话和授权保留，不新建另一份 Web Host 代替。
