# 接入工程方案（执行基线）

状态：2026-11-03 用户确定的执行方向。后续按此实现和验收，不再来回更换定位或入口。

同日新增“让原项目中正在工作的具体会话加入协作”的产品层，见 [04-已有工作会话加入协作-可行性验证.md](04-已有工作会话加入协作-可行性验证.md)。本文件已安装路线描述的是原有通用 Agent 接入，继续保留；不能将其 Hub 专用会话称作接管已有 IDE 会话。新增能力目前只有可行性证据，未安装到用户入口。

## 1. 用户只做什么

在“成员与连接”选择 Agent，填写备注，点击连接。Hub 检测本机环境，必要时自动安装官方运行组件；需要本人操作时显示官方登录/授权按钮。完成后自动配置和真实验证，显示“已接入，可以聊天”。用户不用填命令、MCP 地址、令牌、轮询周期或调试参数。

Codex、Gemini 已按此流程实现并安装，实测范围见[验收记录](03-实现状态与验收记录.md)，不意味着下面所有目标平台均已支持。Grok 本人专属 URL/密钥属于已经确认的原平台限制，保留同页的一次安全交接；不能虚构已经实现自动读取。

## 2. 固定接法

| 对象 | 默认工程路线 | 用户身份与会话 |
|---|---|---|
| Codex | 官方 App Server；复用已安装客户端，缺失时由 Hub 安装官方运行组件 | 已有 ChatGPT 登录优先复用；精确保存每位成员、每个 Hub 会话对应的原生 thread ID |
| Gemini / Antigravity | 官方 Antigravity ACP 运行组件；参考 T3 Code 和 ACP Registry 的安装、认证、权限与会话管理 | 使用官方账号认证；运行组件可能要求独立首次登录，不能冒称继承旧 IDE 会话 |
| Grok Bot | 指定 Bot 的原生 Webhook Routine 唤醒，由 Bot 使用自己的 Hub 工具领取消息、回复 | 已完成的 Skill 配对、例程和成员授权继续复用，见 Grok 专页 |
| Dot | 既有 MCP Events 通道保留 | 既有成员、授权、订阅与会话保留，不因本轮升级重建 |
| 其他已列目标 | 按旧台账中的官方原生协议接入，逐家实测后开放 | 研究目标不是已支持清单；不在本轮临时增加承诺 |

不以反代模型 API 代替完整 Agent。不把浏览器控制当成 Coding Agent 的默认路径。不通过绕过平台权限、伪装客户端身份或把写工具标成只读来通过验证。

## 3. Hub 负责的工程

- 运行组件：版本、下载进度、官方来源和哈希校验；安装目录独立于账号资料；安装失败保留旧版本。
- 认证：官方认证流程、状态检查和错误提示。提供方凭证留在原生存储或独立受保护资料中；不进聊天、前端持久存储、Git、安装包或测试证据。
- 连接：成员身份绑定与短时配对由本机服务完成；成员工具权限独立，不向 Agent 发管理员凭证。
- 接收：空闲只做轻量信号检查，不调用模型；有消息才唤醒对应原生 Agent。关闭 Hub／电脑时本机接收暂停，重开恢复。
- 会话：按成员与群/单聊保存原生会话 ID；不使用全局“最近一次”会话；同品牌多个成员独立运行，不覆盖彼此配置。
- 工具：原 Agent 的文件、终端、技能等继续存在；Hub 提供消息、文档、事项、会议等协作工具。Hub 专用原生会话默认完整授权，不逐项确认文件、终端、联网或协作工具；可在成员连接页选择“操作时确认”。原日常 IDE 的全局权限不变；平台要求本人登录授权不能伪造。
- 回传：必须由真实成员身份调用 Hub 工具，并匹配实际消息/工作；普通 CLI 输出或开发者代写不算原 Agent 回群。
- 恢复：持久记录执行中的状态，先核对原回执和会话再恢复；无法确认的副作用不盲目重发。
- 更新：有工作时不强行重启；账号、登录、原生会话与工作区不跟程序包一起删除。解除连接只撤销该成员的 Hub 权限，保留原平台登录和历史。

## 4. 接入与产品状态

流程统一为：准备连接 → 必要的本人操作 → 自动验证 → 可以使用。失败时在同一个连接页说明具体原因并给出恢复动作，不让用户重新跑整套配置。

“已接入”依据真实往返；后台暂停、等待登录、等待批准、网络暂不可用各自显示，历史 verified 不能掩盖当前执行端已经离线。

## 5. 一次完整验收

| 验收项 | 必须看到的结果 |
|---|---|
| 新用户接入 | 从普通成员页开始，不使用开发者管理接口代替用户完成认证；只有必要首次登录/授权 |
| 普通沟通 | Hub 发消息 → 正确原生 Agent 自己领取 → 回复回到同一单聊/群 |
| 连续沟通 | 追问保留本会话上下文，不串到别的群、账号或最近 IDE 会话 |
| 协作 | 正确的 Agent @ 另一个真实成员并收到回复，无人工转述 |
| 原生能力 | 实际读写指定测试文件并执行适用验证，交回可核对的结果；不只生成一句“已完成” |
| 重开恢复 | 完整退出测试客户端/执行端并重开，保留登录和精确会话；不用重新配对 |
| 异常 | 瞬断、超时、重复事件、执行中退出、解除连接，分别验证恢复和不重复副作用 |
| 发布生效 | 工程检查通过后打包启用，核对真实窗口与本地服务构建号一致，旧登录资料保留 |

测试用独立群和工作目录。原 VPS Claude Code 订阅不参与测试；不改系统 VPN、日常 Chrome 或已有提供方模型配置。

## 用户确认的权限默认值（2026-11-03 追加）

用户明确要求默认全部开放，后续有需要再管理。因而 Coding 接入默认采用原生会话的完整授权模式，不再把每次工具批准作为接入步骤。工程路线和协作功能不变；这是用户明确变更，不是另起方案。
