# Claude Code 远端连接器

更新：2026-11-04。连接器、服务端会话登记和 Hub 入口已实现并发布；用户的 Claude/VPS 未被访问或运行，真实订阅往返由用户操作后验收。

## 怎么使用

1. 打开本地 **Agent Hub → 成员与连接 → 添加成员**，平台选择 **Claude Code**，备注例如“Claude VPS”。点连接，点 **生成接入步骤**。
2. 在你自己的 VPS 终端操作。先确认 `node --version` 为 22 或以上，原来的 Claude Code 已能正常使用。复制 Hub 中的安装命令执行，再执行配对命令；提示时粘贴页面上 15 分钟有效的一次性配对码。无需 Claude API Key、服务器密码或重新登录。
3. 在 VPS 上 `cd` 到原项目目录。等正在工作的 Claude 完成，正常退出那个终端会话，再执行页面里的启动命令，保留 `--resume`；官方 Claude 选择器会让你选择原来的会话。首次确认官方自定义 Channels 提示与 MCP 使用授权。
4. 回到 Hub，进入单聊或群聊，点 **Claude VPS · 选择工作会话**，选择刚接入的原会话。发一句“说一下当前项目目录，只回复目录，不修改文件”，应在 Hub 收到原 Claude 的回复。

后续使用同一条启动命令，配对无需重复。要新建原生会话，去掉 `--resume`；要接另一位 Claude 成员，在 Hub 添加另一备注，使用它自己的配对步骤。多个原生会话可以在线，各群分别选择；同一原生会话不能同时属于两位成员。

**关闭 Claude 会话后不会继续接单。** 群消息和会话绑定保留；用同一启动器恢复原会话后继续接收。连接器不替你在 VPS 打开终端、启动已关闭的 Claude 或接管正在运行但尚未加载连接器的旧终端。

解除连接：Hub 成员卡片的“解除连接”。撤销 Hub 权限，保留 Claude 登录、原项目与会话。恢复需重新添加成员配对；连接器不会自动绕过撤销。

## 实现逻辑与现成能力

- 官方提供 **MCP stdio + `claude/channel` 通知**。连接器由原 Claude 启动为子进程；有 Hub 工作时才发通知唤醒模型，无工作不调用模型。
- 官方 **SessionStart Hook** 给出原生会话 ID、项目目录和可选标题；只登记这些元数据，不读取聊天全文、登录令牌、模型配置。
- 官方 **`--resume`** 恢复原会话；本次命令附加 Hub 插件和 MCP，保留原提供商登录与原生工具。不写日常 Claude 全局配置。
- Hub 实现的是 **会话登记、在线心跳、群与会话的绑定、成员授权、工作去重及真实回执**。这些是产品适配，不声称会话选择技术独有。
- Claude 的文件、命令和代码修改发生在 **VPS**。通道只提供 Hub 群消息、文档、会议、事项等协作工具；没有本地 Mac 文件或终端执行接口。所有连接由 VPS 主动请求 HTTPS，无需暴露 VPS 入站端口。
- 官方跨会话 Inbox 能力已核对，但公开页面没有给完整外部消息数据格式；这版统一采用有完整文档契约的 Channels，不猜 socket 协议，不并行维护两套半成品路径。

## 当前支持边界

- 这版针对 **VPS/Linux 上的交互式 Claude Code**，沿用订阅与原项目。官方 Channels 为 research preview，自定义通道需要启动时确认；组织策略禁用时需管理员开启。
- Hub 列出的是通过启动器加载连接器的会话。没有宣称能扫描、热接管任意已有 Claude GUI/终端或让已关闭会话凭空运行。
- Hub 暂不远程创建 VPS 的项目/终端。新建在 VPS 用启动器完成，然后在 Hub 选择。UI 不展示一个实际没有实现的“远端新建”按钮。
- 官方通道写入不等于模型收到并交付。只有原生会话领取 Hub 的验证工作并回传正确结果，连接才成为 verified。配对、在线、实际往返分别记录。
- 同一成员的不同会话按工作领取串行；不同成员可并行。切换绑定不打断已经领取的工作。网络失败保留身份、绑定与待办，不复制订阅凭证。

## 已执行的验收与待用户操作部分

隔离测试使用真实 Worker/D1、真实 SDK stdio 客户端与分发的同一份连接器文件；模型端由协议测试客户端代替，不消费订阅。

- 下载文件的 SHA256 与服务端公布版本一致，可单独运行，不需要克隆私有仓库或 npm 安装依赖。
- 一次性配对；授权仅存在测试远端私有文件，0600；配对输出不含长期令牌。
- 两个原生会话分别绑定两个群，错误会话不能领取另一群工作；同一会话重复接收器被拒绝。
- 真实 SDK Channel 通知发出、工具列表可读、按目标会话领取并回帖到正确群。
- 运行中更换绑定被拒；关闭/重连后绑定保留；解除连接后原凭证不能再读写。
- 启动器只附加当次插件、MCP 和 Hub 工具授权；不改 provider/model，不写原登录，不读取 transcript_path。
- 完整自动测试 242 项通过；类型检查、构建、登录资料保护及隔离 Electron 重开门槛通过。
- 本轮 CUA 桌面视觉检查受本机接口故障阻塞：`Sky Computer Use native pipe startup failed`，浏览器接入主机也不可用。已记录，不冒充点击验收通过。

待用户操作后的最终证明：在 VPS 加载官方 Channels → Hub 显示原生验证通过 → 单聊真实回复 → 分别选择两个原生会话并核对项目 → 退出并恢复原会话后继续回复。此文档不把隔离协议测试说成真实 Claude 订阅测试。

- `connectors/claude/cli.mjs`：配对、当次启动器、SessionStart 元数据登记。
- `connectors/claude/channel.mjs`：官方 MCP Channel、工作筛选、领取与回帖。

## 同次成员页调整

成员与连接从大卡片网格改为紧凑列表，保留聊天、连接设置和解除连接。支持按名称/平台搜索、平台筛选、可沟通数量、长名称省略和空结果提示。添加成员改用独立对话框；修改备注与解除连接放入每行更多菜单。原生运行端在线与真实往返验证保持区别，未验证显示“等待首次回复”。这轮没有改动群聊协作、原会话绑定或原平台登录逻辑。

视觉点击检查仍受本机 CUA 接口故障影响，未声称通过人工式视觉验收。
