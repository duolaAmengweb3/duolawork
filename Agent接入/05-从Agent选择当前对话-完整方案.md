# 从 Agent 选择当前对话：完整产品与工程方案

更新：2026-11-05。产品：DuolaWork。状态：**第三入口已实现，当前安装与逐家实测状态见 `03-实现状态与验收记录.md` 顶部。** 下文保留完整设计；设计中的多设备归属、同群同账号多参与项等不能自动等同本次已实现。

### 11月5日下午实现对应

- 用户入口为「从 Agent 配对当前对话 → 复制配对说明」。不用先选项目，复制到原 Agent 即识别本段对话；接收原生确认后自动保存并回到聊天，既有账号连接复用。
- 当前限定**这个成员已经连接的原环境**。本机已连接账号的说明发到另一台尚未连接的 VPS 会明确拒绝，不通过会话码新增设备或发放成员授权；跨新环境的透明补安装仍属后续设计。账号尚未连接时先走已有账号接入，不能把它伪装为本次对话选择。
- 实际接口采用 `/v2/session-links` 与 `/v2/self/session-links`，码为 80 bit 随机值的 20 位十六进制表示，15 分钟有效；服务器只保存哈希。已有成员令牌用于验证原环境，不在复制说明中传递长期令牌。
- 自动回执经原生队列发到同一 ID，由该对话自身工具确认。事务状态保存于服务端；关闭界面不取消操作，接收组件重启保留发送日志，不重复发送未知结果。30 分钟未收到确认时保留旧关联并提示重新复制。
- 现有通用原生分发包用于更新同一原环境接收代码，保留原 grant、runtime ID 和项目。Claude 使用已加载 Channel 的两个配对工具；旧 Channel 缺工具时明确要求更新，不猜 ID、不操作用户的 Claude/VPS。
- 当前切换沿用各适配器已有的工作排队/忙碌保护与比较更新；不承诺已完成本设计全部细粒度并发和跨环境权限扩展。
- Codex、Antigravity CLI、原 DSH Host 的第三入口已做原生模型往返；Claude 是隔离协议与实际分发 MCP 子进程验收，不代表原 VPS 订阅实测。桌面形态的本轮结果以 `03` 为准。旧 Gemini CLI 缺少可靠当前调用者识别，不显示这个入口。

本文件细化《01-接入工程方案》的第三种选择方式，不另建一套账号接入。覆盖用户最新要求：不重复接入、知道接到哪里、重开后继续、国内外多家适配、尽量复用现成实现、保持简单。实际已安装能力以《03-实现状态与验收记录》为准。

## 1. 定案：接入一次，每个聊天选一次工作对话

**添加成员解决“是哪一个账号”；选择对话解决“这个群和它的哪段工作交流”。配对码只是第三种选择方法，不是第二次添加成员。**

例如，用户已接入“我的 Codex”。在“网站开发”群里，既可以从列表选“官网项目 / 修复登录”，也可以把一段说明发进正在修复登录的 Codex 对话。两条路最终保存完全相同的关联。以后打开这个群，自动继续用它，不再显示接入步骤。

同一账号可以在不同群关联不同项目、不同对话。换备注、项目改名、换安装包不改变关联。Agent 仍在自己的电脑或 VPS 干活；DuolaWork 负责沟通与共享资料，不搬运原项目、不接管 IDE。

### 三个入口

| 入口文案 | 用户做什么 | 系统做什么 |
|---|---|---|
| 选择已有对话 | 选择项目、对话 | 关联准确的原生对话 |
| 新建对话 | 选择项目，创建 | 在原环境创建持久对话，随后走同一关联流程 |
| **从 Agent 中选择** | **复制说明，发到正在使用的那段 Agent 对话** | **自动识别当前对话，复用连接，验证并保存关联** |

第三项不要求先从列表选项目，适合“我已经在那段对话里了”、远端环境、同名对话难辨认等场景。内部仍称短时配对码，用户界面不再新增“配对管理”概念。固定身份的 Grok Bot / Dot 不显示这三个 Coding 选项。

## 2. 用户走的完整流程

### 2.1 已有账号、已有连接：正常路径

1. 群里的成员入口显示“Codex · 选择工作对话”；点击后选择“从 Agent 中选择”。
2. 同一个小窗口仅展示目标成员、目标群、说明和一个主按钮：**复制说明**。辅助文字：“发到你希望在这个群继续使用的那段 Codex 对话。会保留原项目和上下文。”
3. 用户粘贴一次。原 Agent 调用已经安装的适配工具；没有重复登录、重复建成员、重复安装连接器。
4. Hub 自动显示：“已找到：官网 / 修复登录，正在确认回复”。原工作忙碌时改为“等待当前工作结束后确认”，不打断它。
5. 原会话完成一次最小自动往返后，原位显示：**“已关联：官网 · 修复登录。以后这个群会继续使用这段对话。”** 主按钮为“回到聊天”。群里的当前对话信息同步更新，无需刷新。

复制说明中自动包含真实服务地址、目标群、成员、协议版本与短时码；没有让用户补参数的空格。下面只是文案模板，不是可执行接入凭证：

> 请把当前这段对话用于 DuolaWork 的「网站开发」群，成员是「我的 Codex」。沿用当前项目和对话，复用已有连接，完成自动确认后告诉我结果。连接说明：〈官方地址〉；本次连接码：〈自动填写〉。

技术约束放在版本化的适配说明和工具实现里，不把长篇排障说明塞给用户。

### 2.2 原环境尚未安装接收组件

仍在上述同一个流程中补齐原环境组件，不让用户回“添加成员”重走一次。适配器先查已有安装和授权，只补缺项；首次必要的原平台确认直接显示在当前步骤，完成后自动续接。

**不能把账号曾经在本机接入，等同于另一台 VPS 已经装好接收组件。** 新设备首次准备是必要的技术动作，但不是新增账号。新设备只获得本次目标聊天需要的授权，不能借一个对话码取得其他聊天或管理员权限。

如果原平台确实要求重开原对话才能加载插件，显示具体原因和一个准确动作；恢复指定原会话，不使用“最近一次”，不把原任务杀掉。只有已经加载接收组件的环境，才承诺以后关联其他对话无需重复安装。

### 2.3 用户没有先添加成员

本次第三入口从群内已有成员发起，因此不会无中生有添加账号。首次“添加账号”的既有一段话接入可以在内部串联安装与关联；不得强迫用户连续复制两段几乎一样的说明。两个入口共享安装器、状态和错误处理，但后台授权目的明确区分。

## 3. 连接之后，用户怎样知道接没接、接了谁

### 3.1 群里保留一行信息，不加状态面板

在成员的现有工作对话入口显示：

```text
[Codex 图标] 我的 Codex
官网 / 修复登录             可联系    更换
```

项目和对话标题来自原平台。位置仅在远端或存在重名时补充“办公室电脑 / VPS-01”。长标题省略但可展开；无标题优先使用原平台已有摘要、时间和项目；确实拿不到则显示“未命名对话 · 今天 10:20”，允许改 Hub 备注，不为美化标题额外扫描历史，不用 UUID 当名称，不虚构项目名。

点击信息行的轻量详情只放：当前项目与对话、所在设备、最近联系时间、“更换对话”“取消此群关联”。能准确打开原生对话时才显示“在 Codex 中打开”；远端不能在本机打开时显示操作说明，不给无效按钮。

### 3.2 成员页只回答账号层的问题

“我的 Codex · 2 台已连接设备 · 用于 3 个聊天”，展开后查看对应群和对话。这里保留“解除账号连接”；群里的“取消此群关联”仅影响当前群。两种作用域不可共用含糊的“删除”按钮。

用户不需要维护设备表。设备名称默认取原环境可用名称，重名时加可辨识后缀；只有主动修改才填备注。若平台不提供可信账号标识，显示用户命名的连接，不冒充已经验证账号邮箱，也不能靠设备名自动合并账号。

### 3.3 少量状态，对应明确动作

| 用户看见 | 实际依据 | 用户需要做什么 |
|---|---|---|
| 选择工作对话 | 这个聊天还没有关联 | 三选一；不重新登录账号 |
| 可联系 | 关联已保存、曾完成真实确认、当前原会话接收端可达 | 正常聊天；不承诺模型一定立即回复 |
| 正在处理 / 等待当前工作结束 | 对应原会话真实忙碌、消息已排队 | 可继续沟通，无需重新配对 |
| 暂时离线 | 关联还在，但接收端不可达或心跳过期 | 网络恢复后自动重连；原软件关闭时提示打开原软件 |
| 需要处理 | 明确的权限拒绝、原会话删除、版本不支持等 | 展示原因与一个对应动作 |

“已关联”是持久事实，“可联系”是当前状态；不能共用一个永久绿色 verified 标记。网络超时不等于退出登录，原生进程退出不等于账号失效。离线不会让群输入框失效；发给该成员的消息显示等待送达，可取消。

### 3.4 原 Agent 一侧也能认出来

关联完成后只回一条简短确认：“这段对话已用于 DuolaWork 的『网站开发』群；项目：官网。以后可在该群继续联系我。”提供打开该群的链接。确认来自实际工具结果，不靠模型自行宣布成功。

原会话的适配组件保存关联；会话恢复时向 Agent 注入简短、最新的关联信息，并提供状态查询工具。原平台有状态栏扩展点时显示轻量标识；没有就使用确认消息和可询问的状态，不修改原聊天标题、不强行给每家造一个面板。不在每次重连或每轮对话刷确认消息。

## 4. 用户没想到但必须处理的情况

| 场景 | 固定行为，避免增加正常流程步骤 |
|---|---|
| 同一说明粘贴两遍 | 返回同一关联结果，不增加成员、会话、接收器或重复确认消息 |
| 码过期 | 只重发这次说明；已关联的对话不受影响，不重做账号接入 |
| 窗口关了，稍后回来 | 从服务端读取同一进度与结果；不靠弹窗内存保存 |
| 代码粘贴到了错误平台 / 另一账号 | 拒绝覆盖，说明目标成员不匹配；原关联保持可用 |
| 同一成员、同一群已经关联这段对话 | 直接显示当前结果；可达性检查不反复调用模型 |
| 同一群准备换到另一段对话 | 在“更换”中明确选择；新关联验证失败不破坏旧关联；发出说明前就说明会替换哪段 |
| 原对话正忙 | 记录关联意图，等安全边界确认；不把整个账号的其他对话一起锁住 |
| 更换时旧对话还有已派发消息 | 已派发任务在旧版本完成，回执按旧路由归档；新消息按切换后的版本走，不能抢单或重放旧任务 |
| 用户在两台电脑同时更换 | 版本条件更新；较旧的确认不能覆盖较新的选择，过时请求就地结束 |
| 原会话改名、项目改名 | 同一原生 ID 保持绑定，更新显示标题；不要因为名字变化重新配对 |
| 原项目移动 | 由原环境核实并更新路径；不能按同名文件夹猜测，更不能在旧位置偷偷建空目录 |
| `/new`、清空或 fork 生成了新原生 ID | 不自动把旧绑定转移过去；原 Agent 可报告“新对话尚未用于此群”，用户主动更换才迁移 |
| 原软件正常退出、网络断开 | 保留绑定；恢复同一环境后核对并重连，不创建替代对话 |
| 原平台明确删除对话 | 显示“原对话已删除，选择其他对话”；Hub 群消息仍在，不伪装恢复原上下文 |
| 同一原会话用于多个群 | 允许，详情列出所关联的群；首次增加第二个群时就地说明“这些群会共用这段对话的上下文”，不默默复制或拆成新会话 |
| 同账号在不同项目工作 | 保留一个账号，多条明确关联；禁止用账号级“最后选中的会话”路由 |
| 同群需要同账号的两段对话参与 | 用可辨识的参与项“Codex · 官网”“Codex · 后台”；共用账号连接，各有独立关联。普通添加默认不制造此高级结构，旧成员资料不强制合并 |
| 从群移除成员 / 取消关联 | 撤销该群新增消息与资源权限，取消未派发消息；原会话和项目保留。已进入 Agent 上下文的内容不能声称已被抹去 |
| 解除整个账号 | 展示影响的聊天数量，撤销它的所有 Hub 关联与令牌；保留原平台登录、文件和历史 |
| 版本升级不兼容 | 保留旧安装和数据；明确提示需更新，不删除关联、不自动换成其他 Agent |

同一原会话跨群意味着它可能记住其他群内容，不能只靠路由声称上下文隔离。私密群另选对话即可，正常路径不要求用户学习隔离设置。

## 5. 各家怎么实现，哪些范围不混称

第三入口的统一能力是：**确定调用者原会话 → 向该原会话投递 → 收到真实确认 → 重启后还找得到同一会话。** MCP 工具或 ACP 连接成功本身不够。

| 平台 | 确认“当前这段” | 后续接收与继续 | 方案与当前证据 |
|---|---|---|---|
| Codex | 原生命令上下文的 `CODEX_THREAD_ID`，与原 App Server 的准确 thread、工具调用/本次意图核对 | 复用原 daemon 的 thread queue；记录原 thread，重开后恢复准确身份 | 本机 0.166.0 已有原会话往返与重启证据；第三入口还需实现调用者识别及关联事务。不同 GUI/远端版本逐项验收 |
| Antigravity 官方桌面 | 官方 Hook 输入的 `conversationId`、`workspacePaths`；由已装组件向 Sidecar 登记本次关联意图 | 既有 Sidecar + `agentapi send-message` 发往同一 conversation；原工作忙碌时等待 | 本机 App 2.29.0 已有原会话证据；新增 Hook 关联尚未联测。IDE 扩展、CLI 不能因名字相同算已支持 |
| DeepSeek Harness | 官方 Host 插件的真实工具执行上下文 `exec.agent.id`，核对 Session Controller / Workspace Registry | 在原 Host 用指定 session 的 prompt queue；插件持久保存关联，重启恢复 | 官方桌面 0.2.1-rc.5 已有原会话证据；新增关联工具和云端事务待做。Web Host 可复用插件架构，但远端自助安装仍需验收 |
| Claude Code | 既有 SessionStart Hook 的 `session_id` 与当前实例专属状态；调用配对工具时使用该实例上下文 | 官方 MCP Channels 向原 Claude 推送，原会话恢复后重新登记 | 原生接口及现有连接器已核对；真实 VPS 订阅不参与本轮测试。首次加载自定义 Channel 的官方限制必须如实显示 |
| OpenCode | 官方插件命令/调用上下文的 sessionID | 同一 server 的 session API / 插件接收，持久 ID 路由 | 已核对官方接口，适合下一适配；当前未接入，不显示可用 |
| Qwen Code | 官方 Hooks 提供 session_id；本次操作关联到该实例 | 官方 Channel / daemon 能力可复用，但需验证指定既有会话的路由，不用新建渠道会话冒充 | 已核对官方 Hooks 与 Channel 文档；既有会话主动接收闭环未验证，不能列为第三入口已支持 |
| Kimi Code | 同一原 server 的 session 身份；具体调用者上下文需独立核验 | 官方 Server API / WebSocket 可操作 sessions | 接口存在不等于任意独立终端可热接管；列为候选，不承诺现成支持 |
| Grok Bot / Dot | 原 Bot / Agent 的固定身份 | 原 Routine / MCP Events | 沿用已有账号接入，不新增虚假的项目会话配对 |

### 本轮确定的实现选择

- **直接在现有 Codex、Antigravity、DSH、Claude 适配上增加统一关联能力。** 不换模型，不新开 Harness 来冒充原会话。
- 账号连接、三种选对话入口，最终调用同一个关联服务；不能复制三份绑定代码。
- 原生对话身份由运行环境证明，模型传来的 `sessionId` 只能是线索。比如 Codex 环境变量还需和原宿主核对；不能把继承了父线程变量的子代理接成父线程。
- Hook 只提取会话标识和匹配本次工具操作的随机意图标识，不把所有用户提示或原生历史上传。无当前调用身份的适配不自动猜最近对话，也不把“输入 ID”交给用户补洞。
- 同机与远端采用同一关联协议；远端组件运行在 Agent 自己的机器上。现有三家本机通过，不代表三家的 VPS 自助接入已经完成。
- “原会话继续”指继续原生持久对话 ID 与平台保存的上下文；不承诺复活原进程内存、后台终端或已被平台删除的历史。

### Claude 首次安装时怎样拿到原会话，避免循环依赖

已有 Channel 的会话直接用其专属 Hook 状态。尚未加载组件时，在支持相应能力的版本里调用官方 Skill 的一次性 `PreToolUse` Hook，取得本次原生 `session_id`；这与 Channels 的首次加载是两件事。随后生成带**明确 ID**的原会话恢复动作。官方 Hooks 支持 Skill 调用时注册这一机制，但该自助路径仍需隔离原生验收，不能把文档支持当成安装成功。禁止用最新文件时间、裸 `--resume` 或模型猜测补齐 ID；无法取得官方调用身份的版本就明确不开放第三入口，已有选择方式保留。不会操作用户排除的 VPS Claude 来填补验证证据。

**在本轮核对的项目中，没有发现一个能直接满足上述所有平台、账号语义、准确原会话与群关联的即插即用组件。** 不是从零做 Agent；需要自己补的是 DuolaWork 的关联记录、一次性意图、状态呈现和原子切换。许可证按各文件实际声明保留归属；来源版本固定，不能自动跟 main 更新。

## 7. 内部模型：复用连接，新增关联意图

下面是研发结构，不向用户增加表单。

```text
账号成员 Connection（长期；一个账号）
  └─ 原环境 Runtime（电脑 / VPS，可多个；自己的接收组件）
       └─ 原生对话 NativeConversation（原生 ID + 项目）

群/单聊里的参与项 ── ConversationLink ──► 一个准确 NativeConversation
                              ▲
                 三种选择方式都写入这里
```

### 数据职责

| 记录 | 必要字段与规则 |
|---|---|
| Connection | workspaceId、memberId、platform、已授权原环境身份；复用已有账号资料，不用备注判断身份 |
| Runtime | 稳定 environmentId、实例公钥/受保护身份、nativeProfileKey、适配版本、能力、最近联系时间；进程 instanceId 变化不改变环境 ID |
| NativeConversation | environmentId + nativeProfileKey + nativeSessionId 为身份；projectId/路径与可读标题为可更新元数据 |
| LinkIntent | intentId、目标 member/channel/参与项、允许的平台/连接、期望旧 linkRevision、码哈希、过期时间、幂等键、提出者、领取者、待验证候选 |
| ConversationLink | 参与项与 chat 的唯一当前关联、原生身份、revision、verifiedAt、最近联系与异常原因；与账号级 verified 分开 |
| Delivery | chat、message、linkRevision、nativeSessionId、原生 requestId、领取/提交回执；保存去重和恢复依据 |

当前主要是 `(memberId, channelId)` 关联；采用内部 `participantId` 可承接同群同账号不同工作对话，但普通流程不要求用户创建“工作身份”。旧成员、旧 ID 原样保留，不能按名称批量合并。

### 同一能力的最小适配契约

```text
capabilities()                     // 明确版本、环境、可识别/投递/续接范围
identifyCurrent(invocation)        // 原宿主证明的当前对话，不收模型自报当证据
describe(conversationRef)          // 原项目、标题、可达性
attach(conversationRef, linkGrant) // 使用原连接注册关联
enqueue(conversationRef, message) // 精确路由，原生忙碌排队
reconcile(savedLink, deliveries)  // 恢复同一 ID 和未定回执
detach(linkId)                     // 只撤销此次关联
```

这是 Hub 内部适配边界，不是要求所有厂家实现新协议，也不是让用户自行部署七个服务。

## 8. 配对与保存：一次操作，不能串群串账号

### 接口意图（待实现，不是当前已有 API）

- 所有者创建 `POST /v2/session-link-intents`：校验目标群、成员及当前关联版本，返回完整复制说明。存在同一未完成意图时复用，不每次弹窗生成新码。
- 原环境兑换 `POST /v2/session-link-intents/redeem`：提交短时码、尝试 ID、受信原环境身份与原生调用证据。优先复用已有连接；新环境走同一流程的受限登记。
- 原环境 `confirm`：提交指定原会话的实际接收/回传证据；成功后原子写入 ConversationLink。
- UI 订阅该意图状态；断流后查询结果。取消意图或移除关联独立于解除账号。

码设计：随机 16 位 Crockford Base32（80 bit），可分组显示，默认 15 分钟有效；服务端仅存哈希，按意图/来源限流。完整码只出现在用户主动复制的私有说明和原端输入，不进 URL 查询、普通日志或 Git。码绑定 workspace + member + chat + 操作类型与期望版本，不可拿去兑成员级通用权限。

### 事务顺序

1. 验证短时码与目标，原子预留本次领取者。没有可靠调用身份时保持未完成，不烧掉码后假成功。
2. 适配器核对当前原生会话和环境。原宿主与代码执行来源对应；读路径不当作身份证明。子代理调用、复制来的环境变量、同名项目均需排除误绑定。
3. 为候选会话建立**待验证、仅此聊天**的关联权限。旧关联仍保留；候选还不能领取普通群任务。
4. 将一次最小验证消息通过实际接收通道发给同一原会话，由它回传本次挑战与身份。只注册成功或 HTTP 200 不算通过。忙碌时挂起验证，不强行抢占，也不因过了几秒就重新登录。
5. 校验成员还在群中、意图没取消、旧 revision 未改变；原子提交新关联，完成旧关联交接。真实回执和 UI 状态使用同一事实来源。
6. 意图消费后保留结果映射。相同领取者与尝试 ID 重试只取回同一结果；其他领取者重放拒绝。已验证关联不依赖短时码继续存活。已经取消/撤销的结果保留终止标记，重贴旧码不能复活权限。

测试中断、UI 关闭、网络响应丢失都可恢复同一意图。失败只移除候选关联，不注销已有账号、不撤销其他群授权、不轮换整个成员的长期令牌。

已连接原端使用现有身份签名/认证；新端使用码限定的初始化能力登记自己的设备身份，绝不获得所有者凭证。需要扩展现有 member token 的服务端 scope 校验，不能只靠客户端过滤 channelIds。

本机制保证正确路由和授权归属，不声称能抵御用户原机器上已经取得同等文件权限的恶意进程。原平台登录凭证始终留在原环境。

## 9. 运行、重启与更换时的确定行为

- 绑定与消息队列落在持久存储；本机缓存只是加速。每条消息入队时就固定 linkRevision 与原生 ID，不在执行时重新读“当前选中”而投错人。
- 原生队列支持请求去重时复用稳定 requestId；Hub 的领取和提交也幂等。不能承诺网络层恰好一次：发送结果未知时先核对原生队列/回执，不能为了 UI 变绿自动重新做有副作用的操作。
- 同一个原会话只由一个适配实例持有投递租约；instanceId + generation 防旧进程恢复后双发。不同原会话可并行，不用成员总状态把整个账号锁死。
- 升级时保留数据目录、原环境 ID、关联和回执；迁移可回滚。原软件开着且工作中时不重启它；接收器升级等到该实例安全边界。
- 短时码、长期关联、可续期访问凭证分别管理。连接器沿用受保护的续期机制，不让凭证正常轮换要求用户重新粘贴；实际撤销授权或原平台要求本人认证时才显示对应动作。
- 原程序重开后重建监听，核对同一 session。仅在已实现原生安全恢复、无其他活跃写者时恢复指定会话；不能安全恢复就等待用户打开原软件，仍保留绑定。
- 普通离线自动退避重连，不消耗模型 tokens 做心跳、不反复写群消息。长期离线的待发消息恢复时先按时间列入同一队列，可取消；不得把用户已取消的旧要求再次执行。
- 取消关联阻止未来派发；已进入原会话的工作不被粗暴杀进程。它的迟到回执按原 message/旧 revision 归档，不更新当前关联，也不给已撤销会话新的群资料。
- 新环境、账号切换、原 profile 变化必须重新核对归属；不能以相同目录或相同标题静默接到另一账号。

## 10. 本地与 VPS 共用方案，不增加用户负担

```text
DuolaWork 群聊 ⇄ 已有云端协作服务 ⇄ 原环境的小连接器 ⇄ 原生 Agent 会话
                                              本机 / VPS / 另一台电脑
```

原环境连接器主动向协作服务出站连接；优先复用已有事件/长连接，断线以游标补读。无需用户给 VPS 开入站端口、配公网回调或把 SSH 密码交给 Hub。现有云端部署独立于本次设计，不因此重装服务器或重建数据。

传输的是获授权的群消息、资源引用和结果。项目路径留在对应环境，展示路径不等于远程文件访问；真正跨机共享代码走仓库分支/提交，资料走共享空间。原端可保存自己的持久工作目录，不能让 VPS 把本机 `/Users/...` 当有效工作区。

同一个账号在不同环境是否确实相同，需要平台可信身份或用户明确的连接归属；不采集认证文件来猜。不可靠时维持单独的连接记录并说明归属，不能悄悄合并。人类只需在确有身份冲突时做一次选择，正常关联不增加账号表单。

## 12. 一份交付的验收门槛

所有列为“可用”的平台/版本都要完成同一套验收，不能让一家通过替其他家背书。原 VPS Claude 不触碰；未经其真实验收，只标连接器/协议已验，不标订阅实例已验。

| 场景 | 必须拿到的证据 |
|---|---|
| 原会话一次粘贴 | 用户先在原软件创建真实项目与对话；粘贴前后原生 ID 相同；无重复成员、无新助手 |
| 当前对话识别 | 同项目两段对话、两个项目同名对话、子代理、两个账号并存；只能关联实际调用那一段 |
| 原能力保留 | 在隔离测试项目用原会话读写并读回文件，工具和模型未替换；新文件不落到 Hub 临时目录 |
| 原上下文继续 | 配对前原对话已有识别信息，配对后经原接收通道准确取回；不能由安装器代答 |
| 忙碌时关联 | 原任务不中断、不消失；其结束后完成确认；其他会话继续运行 |
| 真正收消息 | Hub 发消息后原 Agent 经实际接收入口回复正确群；代码兑换成功不作替代证据 |
| 保存与恢复 | 关闭弹窗、重开 Hub、重开原 Agent、连接器升级后仍是同一原生 ID 和项目，正常继续消息 |
| 两端可辨识 | Hub 显示项目/对话/位置；原 Agent 能查到它关联的群；重命名后仍识别，无 UUID 主标题 |
| 重复与过期 | 双击、重复粘贴、请求响应丢失、已消费/过期码；不会新增资源或影响旧关联 |
| 切换竞争 | 两设备更换、取消中确认、成员移出群；旧意图不得反向覆盖，新旧回执不串 |
| 跨群与跨账号 | 同账号不同会话并发、同会话多群明确提示；错误成员/其他聊天凭证不能领取、发言或读资源 |
| 网络异常 | 断网、服务端超时、原应用关闭、消息发送结果未知；状态有原因且可恢复，不制造重复执行 |
| 取消作用域 | 只取消本群时其他群继续；解除账号影响范围显示准确；原平台登录、项目、历史都保留 |
| 原会话失效 | 删除、fork、新建、更换项目、账号切换；不偷偷换目标、不自动建空项目冒充续接 |
| 原平台限制 | Claude 首次官方确认、组织策略、AG 插件未加载、版本不支持；每种只给真实有效的下一动作 |
| 桌面实际使用 | 当前安装包内操作，短窗口/长标题不遮按钮；返回群里不需刷新；不抢原软件焦点、不强制重登 |

UX 验收目标（不是已测成绩）：已经完成账号连接的正常路径只需“选第三项 → 复制 → 粘贴”；无邮箱、Token、URL、ID 手填。连接码生成、状态变化不依赖模型；点击立即有反馈，局域正常网络下控制操作目标 2 秒内返回。原 Agent 推理/忙碌耗时单独显示，不以 60 秒轮询人为增加等待，也不承诺厂家响应时间。

交付报告必须分清：代码测试、指定原平台真实往返、重开续接、当前安装包生效。包含版本、环境、原生 ID 前后相等证明、操作次数和用时；证据脱敏、不含配对码与长期凭证。没有完成这套闭环，不把第三入口标成已经上线。
