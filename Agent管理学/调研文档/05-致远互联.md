# 致远互联：以组织模型承载不同业务

资料核对：2026-10-29。类别：协同运营平台 / OA。

## 官方资料确认了什么

致远相关产品与中台资料把组织、流程、表单、数据和业务协同作为平台组成；组织模型考虑多种业务角色和组织关系，业务通过可配置能力连接。[A8 产品介绍](https://www.seeyon.com/home/Zhuanq/a8c.html)；[协同中台](https://www.seeyon.com/home/Zhongtai/index.html)；[历史组织中台说明](https://www.seeyon.com/home/Zhuanq/zhongtai2019.html)

最后一项是历史设计材料，用来理解模型，不把历史版本当作当前最新版本。

## 它的组织逻辑

我们的分析是：**一个人可能同时属于部门、项目和业务角色，组织系统需要表达这些关系，不能只有一棵汇报树。**

同一件事也可能跨部门、跨系统。组织模型确定责任和可见范围，流程表达先后与协同关系，业务数据维持连续性。产品因此试图成为多种业务共用的协作基础。

## 对 Agent 管理的启发

1. 同一 Agent 可以在一个项目牵头，在另一个项目查证；角色应随任务确定，不能永久等同于平台品牌。
2. 成员、角色、账号、能力是不同对象。同一个账号不一定能同时承担所有工作，也不等于多个备注就是多个独立 Agent。
3. 跨项目要处理资源冲突：谁能占用同一订阅、什么工作优先、临时任务怎样影响原承诺。
4. 组织记忆也有范围：个人偏好、项目事实、通用方法分别保存，不能把一次临时意见推广到全组织。

## 不应照搬什么

不为一个人的团队预建复杂集团组织树。先表达实际出现的目标、责任和资源关系，再按需要增加层级。

**可迁移原则：组织结构应反映真实依赖与责任；成员能力复用不意味着角色固定，也不意味着上下文全部共享。**
