## 2. 当前记录里已经存在的组织机制

README 的目标已经从普通新闻收集转向寻找值得验证的小项目与机会；不同研究者保留自己的判断和材料。

- **独立工作边界**：Grok、dot、Muse 各自发现和筛选；duola 雷达是另一条独立流程，不能把脚本自动当成有判断能力的 Agent。
- **资料归属**：分别维护自己的目录，原始素材和结论需要一起交付。
- **不同工作节奏**：dot 的规则写有北京时间 06:00 / 12:00 / 19:00；Grok 的研究与汇总有错开的时点。因此不能将早先“统一三次”概括成当前所有成员完全同一时刻运行。
- **共同讨论通道**：带 discuss 标签的 Issues 用于交流；发言有身份、可追问、分歧有轮次上限。
- **决定与执行分开**：README 中有需要 Red 确认的规则修改；部分具体规则也记录投票形成。具体授权范围需要逐项看，不能推断任何多数票都能改全部规则。
- **交付标准演化**：新事实与存量关注分开、来源与判断分开、同项目的新事件与旧转述分开。

我们的判断：这已经包含目标、边界、节奏、决策和规则迭代。GitHub 提供了部分协作基础，组织并不是从“买一个专门软件”才开始存在。

## 3. 从这个案例可以提出什么问题

| 现象或反馈 | 候选解释，不是已判定根因 | 应看什么证据 |
|---|---|---|
| Agent 互相点头 | 过早看见对方结论；同一来源反复转述；缺少判断标准 | 初始独立判断、引用来源关系、改变观点的原因 |
| 内容套模板 | 格式与条数被当成完成；缺资料也必须给结论 | 未达标准的条目是否仍被交付；是否允许空结果 |
| 汇总变成大乱炖 | 只有拼接责任，没有选择和裁决责任 | 冲突有没有被处理；最终稿是否保留来源与取舍理由 |
| 每方都很忙，用户仍不满意 | 成员局部目标与用户需要不一致 | 用户实际用途、返工原因、被忽略的要求 |
| 规则越写越长 | 每次反馈都追加条款，旧条款未废弃 | 规则冲突、适用范围、失效时间、执行负担 |
| 定时任务不等于实时协作 | 工作节奏、上游完成与下游唤醒脱节 | 计划时间、实际领取、产物到达、下游开始四种时间 |

这些也可能在人类组织出现，但本案例没有提供“人类更严重”的发生率比较。

## 4. 对 Grok 当日提案的独立评审

可采纳为试验的方向：先独立判断再讨论、为修改规则留下依据、记录真实反馈、限制无增量讨论、把复盘接到行动。

以下建议应修改后再试，不能因其他 Agent 提出就直接点头：

1. **不要用“至少发生两条分歧、至少采纳一条异议”验收讨论。** 正确结果可能恰好一致。应验收检查是否独立、理由是否具体、重要错误是否发现。
2. **连续几轮没有分歧不能直接判定来源同质。** 还可能是问题简单、事实明确或评价尺度过粗。应查引用和判断过程，不按分歧数量自动换源。
3. **没有新证据的改口不一定是附和。** 推理被纠正、理解了原先遗漏的约束，也可以合理改变观点。
4. **不回复不能当作没价值。** 用户可能忙、已读但未行动；缺失反馈要标“未知”，不能自动计负分或淘汰类别。
5. **预测记分只适合明确、可到期核实的事件。** 不必把每条主观选题硬改为概率题；“积累 20 条”也不是普遍足够的统计门槛。
6. **不将人类会议时长搬给 Agent。** 保留独立查证和必要讨论的资源，按是否有新信息、问题是否解决来结束。

这份评审仅供本研究，不改变原仓库已授权规则。相关外部研究的本轮核验版本见[管理学](10-管理学与组织实践.md)和[Agent 研究](11-Agent研究与已有产品.md)。

## 5. 下一份案例记录应保留什么

不必保留不可获取的内部思维；保存可观察的工作证据即可：

| 字段 | 作用 |
|---|---|
| 目标、成功标准与本轮输入 | 判断是否做了正确的事 |
| 成员、实际模型/工具配置及独立初稿 | 判断差异来自哪里；无法获取的字段标未知 |
| 证据链接、抓取时间与共用来源 | 避免把重复来源误算多方证实 |
| 任务领取、交付、复核与裁决记录 | 区分说过、做过和通过 |
| 最终成果及用户实际修改 | 判断成果能不能被使用 |
| 用户主动协调时间、失败重试与资源消耗 | 判断是否真的减轻负担 |
| 规则变更、理由、适用范围、结果和撤回 | 判断组织是否学到了有效方法 |

优先回收已有批次的完整链路，再补有明确目的的新试验。失败批次和放弃的方案也保留，不能只挑成功故事。

## 6. 可以写进白皮书的案例结论

**已有依据：** 个人已经能够借助共享仓库、原生 Agent 与定时机制形成持续工作安排；用户遇到的问题正在从“有没有 Agent”扩展为“如何组织和判断它们的工作”。

**尚待验证：** 哪种分工、决策和学习机制真正带来稳定收益，以及收益能否抵消更多流程和协调的成本。

不能写成“我们已经验证了自进化组织”或“推文反馈证明巨大商业市场”。更有研究价值的故事，是记录这个组织如何从真实失败中修改规则，以及修改什么时候有效、什么时候无效。
