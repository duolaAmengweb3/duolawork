# Agent 组织：已有研究支持什么，市场已经做到什么

资料核对：2026-10-29。研究数据保留论文版本与测试范围，产品文档与实际效果分开。

## 1. 多 Agent 有收益，也有明显失败

| 原始来源 | 已报告结果 | 对我们有用的判断 |
|---|---|---|
| [Anthropic Research 系统，2025-06-13](https://www.anthropic.com/research/multi-agent-research-system) | 内部研究评测中，Opus 4 牵头加 Sonnet 4 子 Agent，相对单 Opus 4 提升 90.2%；其多 Agent 系统 token 用量约为普通聊天的 15 倍 | 独立方向的广度探索适合并行；收益伴随资源投入。15 倍的参照是聊天，不是单 Agent |
| [Towards a Science of Scaling Agent Systems，v3，2026-04-08](https://arxiv.org/abs/2512.08296v3) | 260 种配置、6 个基准；相对单 Agent 的表现变化从可拆分金融推理的 +80.8% 到顺序规划的 −70.0% | 任务与组织结构匹配，比笼统增加参与者更重要 |
| [Multi-Agent Teams Hold Experts Back，ICML 2026](https://proceedings.mlr.press/v306/pappu26a.html) | 自组织团队在测试中未达到其中专家的表现，ML 基准最高损失 41.1%；折中专家与非专家意见是重要问题 | 汇总需要判断依据与能力，不能将“达成一致”作为正确性的证明 |
| [Why Do Multi-Agent LLM Systems Fail?，v3，2025-10-26](https://arxiv.org/abs/2503.13657v3) | MAST-Data 汇集 7 个框架的 1600 多条轨迹；归纳 14 种失败，分为系统设计、Agent 间不对齐和任务验证三类 | 失败可能来自组织和执行设计，不必全部归因于模型本身 |

以上不能横向拼成一张性能排行榜：模型、任务、资源、比较基线不同。也不能据此推导“我们应该永远单 Agent”或“永远多个 Agent”。

**研究推导：** 管理层应该能决定何时联合、何时独立、何时复核、何时停止；不能为产品叙事强制每项工作都走多 Agent。

## 2. Paperclip：组织运行机制已经是竞争领域

官方核心概念包括组织目标、Agent、任务、委派、心跳与治理；任务可追溯目标，单任务有一个责任人，并用原子领取避免重复占有。执行可以由时间、分配、评论等触发。[核心概念](https://github.com/paperclipai/paperclip/blob/master/docs/start/core-concepts.md)

产品定义包含多种执行适配、Agent 配置版本和恢复等设计，也在描述可复用工作流实验。不能将其仅归类为“多个编码工具的启动器”。[产品定义](https://github.com/paperclipai/paperclip/blob/master/doc/PRODUCT.md)

**我们的分析：**

- 已有产品覆盖目标、组织、自动执行与治理，“Agent 组织管理”不是空白市场。
- 可以参考任务归属、目标关系、唤醒和版本机制。
- 我们可以研究更适合个人原生 Agent 团队的使用体验、动态职责和有证据的组织改进，但这些仍是差异化假说。
- 文档说明有机制，不证明它或我们能稳定提升商业结果。本轮没有部署 Paperclip 进行业务对照。

## 3. Hermes：记忆与方法积累也已有实现方向

官方 README 描述持久记忆、会话检索、从经验创建与更新 skills、定时执行和子 Agent 等能力。[Hermes 官方仓库](https://github.com/NousResearch/hermes-agent)

**我们的分析：** 可以把个体 Agent 的记忆与方法积累作为组织学习的一个输入。但单个成员学到经验，与组织改变分工、评价方式和资源分配，是不同层次。不能因为多了一层组织界面，就宣称比个体记忆更有效。

不采用 README 中“唯一”之类排他性宣传，也不把“self-improving”当作经过独立验证的效果。

## 4. 本研究真正要提出的增量

| 已有能力 | 还值得研究的问题 |
|---|---|
| 接入和唤醒多个 Agent | 怎样判断这次是否需要多个，以及选谁参与 |
| 派任务、追踪状态 | 怎样让职责、决定、证据与成果保持一致 |
| 自动汇总文本 | 怎样保留独立判断、处理冲突而不折中糊弄 |
| 保存知识和 skills | 怎样决定哪些经验值得固化、何时应废弃 |
| 展示成本和完成率 | 怎样识别用户价值、失败归因与协调负担 |
| 组织树与主管 Agent | 怎样避免主管成为单点瓶颈或错误放大器 |

这些问题有研究和产品空间，不等于我们已经形成优势。竞争判断最终应落到真实任务中的可用成果、用户负担和资源开销，而不是理念是否听起来更大。
